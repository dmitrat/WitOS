# Working on WitOS

## Project direction

The core objective is standard upstream .NET above a minimal native kernel and a hardware-independent system layer. Shells and applications eventually run on that .NET platform. [ADR 0024](@Docs/Implementation/ADR-0024-Three-Layers-and-Unix-Form-Runtime.md) (2026-10-06) fixes the architecture: a nano-kernel of mechanisms whose hardware part (`Kernel.Arch.*`, `Kernel.Platform.*`) is the UHI; a user-space system layer that owns loading, process state and the runtime substrate; unchanged upstream .NET in its Unix form (`TargetOS=witos`), whose POSIX-shaped substrate is private to the system layer. Neither Win32 nor POSIX is an external contract of WitOS. The specifications are [RFC 0011 v3](@Docs/RFC-0011-Kernel-Architecture-and-ABI.md) (kernel architecture, ABI-1 between the kernel and the system layer, ABI-2 between the system layer and .NET) and [RFC 0015 v2](@Docs/RFC-0015-DotNet-Runtime-Port-and-Compatibility-Contract.md) (the runtime port and the compatibility contract); the Implementation Strategy §157 maps the milestones to the plan. Current guest code includes the kernel's ABI-1 mechanisms on both ISAs, the system layer of phase S and upstream .NET's NativeAOT in its Unix form, which passes the M3 acceptance on both (R2); the Windows-form runtime line was removed at plan step K8.2, and the kernel policy it needed (native PE loading, the DLL lifecycle, files, process state) leaves at K8.4. Host-side C# tooling must not be described as guest .NET support.

The application compatibility target is unchanged portable managed binaries under upstream CoreCLR/JIT, standard TFMs/SDK/NuGet and optional additive WitOS APIs. NativeAOT is an early system implementation/deployment tool, not the application compatibility contract; do not replace upstream CoreLib or managed semantics.

Original vision documents live in `@Docs/`. Concrete implementation status and deliberate limitations live in `@Docs/Implementation/`. Preserve original drafts unless the task calls for revising them.

Track the program in the root PLAN.md: phases A, K, T, S, R, D, N, V, P with steps such as `K2.1`. Name a slice, its commit and its PR by its step; after each completed step update the plan's checkboxes, evidence links and next step; mark a step complete only when its guest acceptance passes on every supported ISA. The plan before ADR 0024 is `@Docs/Implementation/Plan-Archive-2026-10-06.md`; the removed Windows-form host line's is `@Docs/Implementation/P6.4-Plan.md`.

## Rules of the new direction

These follow RFC 0011 v3 and RFC 0015 v2 and bind every new slice in phases K, T, S, R, D and N.

- The kernel keeps mechanisms only. Nothing in `src/Kernel` learns an image format, a file, a path, a directory, a name of a thread or process, an environment variable, a library or symbol, a language's exception format, a service or a device class. A call enters ABI-1 only when no composition of existing calls provides the mechanism and a layer-2 consumer with a test needs it (RFC 0011 §5); the kernel policy RFC 0011 §8 marks "leaves" is maintained until step K8 and never extended.
- Every system call validates its whole input, including every byte of a destination buffer, before it changes any state or writes any byte; a failed call changes nothing; an object is published only after all of its resources exist. Request structures start with `Version` and `Size`; an unknown version is `UNSUPPORTED`, a wrong size `INVALID_ARGUMENT`, and the kernel never pretends success. After step K1 a call number, a status value and a rights bit are never reused; `QUERY` reports the ABI-1 version and the feature mask of the families present (RFC 0011 §10.1). `@Docs/Implementation/ABI-Reference.md` stays equal to the headers, which a host test checks; a change to RFC 0011 §7 that is not in the headers is a plan step, not a fact.
- Handles are capabilities: no ambient authority, generation-bearing tokens, attenuation only downward on `HANDLE_DUPLICATE`, transfer over channels by move with the `TRANSFER` right, and closing never terminates an object's activity except a channel endpoint's. One wait (`OBJECT_WAIT`) serves every waitable object with absolute monotonic deadlines; an activation interrupts a wait or sleep with `INTERRUPTED` and is delivered through the fault callback with the interrupted context (RFC 0011 §7.4–§7.5).
- Only the register block of a thread context and the calling convention differ between ISAs; everything else in ABI-1 is identical, and layer 2 is recompiled, not rewritten. A new platform adds `Kernel.Arch.<isa>` and `Kernel.Platform.<board>` and nothing in `src/Kernel`. Devices stay unknown to the kernel: the platform enumerates regions and lines, the kernel publishes descriptors and mints capabilities on request (RFC 0011 §7.7).
- The system layer's substrate is taken from pinned open code, never written: musl, LLVM libunwind, libc++abi and libc++, `ld.so`, patched only through `UpstreamPatches`. WitOS adds no symbols to the libc namespace; everything WitOS-specific is `libwitos` and `OutWit.OS.*`. The substrate is never an application API: applications see .NET and WitOS capability APIs (RFC 0011 §9).
- Layer 2 is built by the pinned clang and lld (`Toolchain.LLVM_VERSION`, extracted by `setup` from the hash-verified LLVM installer, never a system compiler) for the triples `x86_64-unknown-linux-musl` and `aarch64-unknown-linux-musl` (T1): ELF, the SysV convention, the Itanium C++ ABI. A layer-2 source is one for both ISAs and, until the libc of S1 exists, compiles freestanding (`-ffreestanding -nostdlib -nostdlibinc -fPIE -Wall -Wextra -Werror`; ARM64 adds `-ffixed-x18`, the kernel's compiler TLS register). The sysroot `src/Sysroot/include` holds what layer 2 adds to the kernel's ABI-1 headers, starting with the transport `witos/syscall.h`; the ABI-1 headers stay the kernel's and compile under MSVC and clang alike, so an MSVC-only construct needs a `_MSC_VER` branch. The root task is `tests/User/root.c` with `root_mechanisms.c` (their shared declarations hidden, so that calls between them need no GOT), linked by `tests/User/root.ld` at the image window as a static `ET_EXEC` with page-aligned RX, RO and RW segments and converted by `FlatImage.FromElfAsync`, which refuses an interpreter, a dynamic section, TLS, a writable executable segment and an unaligned or a fifth segment; the kernel still knows no ELF. Its first log line names the compiler and the ISA; then it checks the mechanisms no other part of layer 2 uses yet (K8.2: waits on several objects, a suspended thread's context read and replaced, an activation of a thread that has not run, the memory-pressure event, `MEMORY_RESET`) on threads of the one form, and `boot-128` of both suites requires both lines. The kernel and its loader are clang's since T3 (see the kernel rules); the kernel policy's PE fixtures keep MSVC, MASM and armasm64 until K8.4.
- The libc is musl at the pinned release (`MuslLibc.VERSION`, the tarball by SHA-256, extracted by `setup`), built by WitOS.Dev after musl's own Makefile rules and options for both triples (plus `-ffp-contract=off`, the meaning GCC gives `-std=c99` and clang does not, S7.2), never by musl's build system and never from a system copy; upstream files change only through `patches/musl` (WitOS's hooks, musl's own later fixes backported unchanged with their commits, S7.2, and the C linkage guards `sys/membarrier.h` lacks, R1.3, which the libc build writes beside its generated headers and the sysroot installs), and the assembly that issues Linux system calls is left out in favour of musl's generic C; the soft-float builtins clang needs for `long double` on aarch64 come from compiler-rt's sources pinned at the toolchain's tag in `src/Substrate/compiler-rt.lock.json`, compiled unchanged. WitOS's part of the library is `src/Substrate/libc`: `__wit_syscall` maps each Linux system call number onto ABI-1 or returns `-ENOSYS`, never a pretended success; descriptors 0–2 are the kernel log (one `DEBUG_WRITE` per `writev`, so a line arrives whole, and `TIOCGWINSZ` succeeds so stdio line-buffers); the clocks are UTC and the monotonic domain, and the processor-time clocks are `EINVAL`, since the kernel reports no processor time (R1.2b); `system.c` answers from `MEMORY_QUERY` (R2.1): `sysinfo` the physical memory, `getrlimit(RLIMIT_AS)` the data arena `mmap` reserves in (the GC halves its region range against it), `sched_getaffinity` the processors threads run on, and every other limit and every setting is `ENOSYS`; `mremap` is `ENOMEM` for growth inside one of the library's mappings or the calling thread's stack, which musl's `pthread_getattr_np` probes, and `ENOSYS` otherwise; a thread's name (`prctl` `PR_SET_NAME`/`PR_GET_NAME`) is the library's, kept in its thread record and inherited by a new thread; `mmap` keeps a table of its mappings (S5.1): anonymous memory is a reservation committed under the requested protection or reserved alone for `PROT_NONE`, a file's private mapping is a committed copy, and an executable mapping of a page-aligned package file is package object mappings of at most 64 pages, published, never writable (plain memory never executes); `MAP_FIXED` replaces the library's own mappings in its range, `munmap` and `mprotect` act on every mapping a range touches through partial releases and commits; `crt1` builds musl's stack image (argc, argv, no environment, the auxiliary vector with `AT_PHDR` from the mapped ELF headers and `AT_RANDOM` from the kernel) from the startup descriptor; `static.ld` links a program as a static `ET_EXEC` at the image window with the headers in the read-only segment. Files are the read-only boot package (S1.2, `files.c`): the library validates the package's table as the kernel's loader does, maps a window per read, treats a name as a file and a prefix as a directory, serves `/dev/null`, `/dev/zero` and `/dev/urandom`/`/dev/random` over `RANDOM`, refuses every write with `EROFS`, answers `statx` with `ENOSYS` so musl falls back to `fstatat`, answers `readlink` and `readlinkat` with `EINVAL` for a path that exists and `ENOENT` for one that does not (R1.2b; musl's `realpath` tells them apart), and keeps the current directory itself (S6.2: a relative path joins the current directory or a directory
descriptor and is normalized with it, `chdir` and `fchdir` accept a directory of the package, and a process starts in
the directory its start message names); file `mmap` stays `ENODEV` until the namespace service. Descriptors (R2.3a): `dup`, `dup2`, `dup3` and `F_DUPFD` share the open file description (one position and `O_NONBLOCK`, `FD_CLOEXEC` per descriptor); a duplicate of a standard stream writes to the log; descriptors 0–2 are slots of the same table, a standard stream until closed, then free for the lowest descriptor an `open` or a `dup` takes, and `dup2` may put a file, a pipe or another stream there within the process. Pipes (`pipe.c`) are within the process: a ring buffer of anonymous memory per pipe with its own lock, a reader or writer parking on a futex word outside the table lock (`__wit_syscall` takes it only to find the pipe and hold a reference), the end of the file once no writer is left, `EPIPE` after `SIGPIPE` once no reader is, atomic writes of `PIPE_BUF`, `O_NONBLOCK`'s `EAGAIN` and `FIONREAD`; `poll` and `select` see no descriptor yet (`ENOSYS`). Threads (S2) are the kernel's: musl's `__clone` is a suspended `THREAD_CREATE` of the one form entered through `__wit_thread_entry` (the thread pointer is the request's TLS base on x64 and written to TPIDR_EL0 by the trampoline on ARM64), a thread's `SYS_exit` and `__unmapself` are `THREAD_EXIT` with the exit request naming the clear word and its futex event, and `__unmapself` first takes the stack out of the mapping table, since the kernel releases that reservation itself (R2.2), and futex waits park in sixteen slots (K5.3), as many as the kernel's threads of a process, with their own auto-reset kernel events under one lock, so that a wake reaches that word's waiters alone and none is lost (the exit word's waiters share the one event the exit request sets); thread ids are the library's, the kernel handle is closed after the resume, and musl's `clone.c`, `__unmapself.c` and the x64 `__set_thread_area.c` leave the build. Signals (S3) are the kernel's faults and activations made POSIX by `signal.c`: the one fault callback (`__wit_signal_entry`, entered in the kernel's convention) classifies a fault by its vector or exception class into the synchronous signal and `si_code` Linux gives it and an activation by the marker callback into the signal it carries; dispositions, each thread's mask, pending set and `sigaltstack` are the library's, kept with the thread records; a handler runs after `EXCEPTION_CONTINUE` into the trampoline with a frame (the saved context, a `ucontext_t` in musl's layout, a `siginfo_t`) on the thread's stack or the alternate stack, and returns through `__wit_sigreturn`, which resumes the saved context through a delivery of its own (K8.1: `THREAD_CONTEXT_RESTORE` leaves ABI-1): with the thread's signals held it leaves the frame in the thread's record and raises an activation of its own thread with the marker `__wit_sigreturn_activation`, from the interrupted stack below its red zone when the handler ran on the alternate stack, since the callback needs `WIT_EXCEPTION_STACK_MINIMUM` of room; the callback recognizes the marker before any mask or hold, ends the hold, re-arms what arrived meanwhile and continues the frame's transfer with `EXCEPTION_CONTINUE`; layer 2 uses no call that K8 removes; pending signals are re-armed as activations of the own thread; `pthread_kill`, `raise`, `tkill` and `kill` of the own process are `THREAD_ACTIVATE` of the thread's kept handle; `SIG_DFL` faults are `EXCEPTION_REJECT`, `SIG_DFL` activations end the process with `WIT_EXIT_SIGNAL(sig)` (S6.1; 128 + the signal before); a blocking path checks `__wit_cancel_requested` before it parks so that musl's cancellation needs no atomic system call window; library locks (`__wit_lock`) hold the thread's signals, the mapping, descriptor and package tables run under one lock in `__wit_syscall`, and the library's own per-thread state (the hold count, the signal held back, the cancellation point in flight) is a `WitThreadLocal` in the thread's record that `__wit_thread_local` finds by the thread pointer without a system call, zero before musl installed the main thread's pointer (S5.3): the libc has no thread-local variable, since musl's dynamic linker gives `libc.so` no TLS module. Never deliver a signal from the callback itself, never run a handler while a delivery is active, and never claim job control, `sigqueue` or signals to other processes. The C++ runtime (S4) is LLVM's libunwind, libc++abi and libc++ at the toolchain's release (`src/Substrate/llvm-runtimes.lock.json`: the release tarballs by SHA-256 and the LLVM libc headers libc++'s `from_chars` includes, file by file), built by `LlvmRuntimes` after the runtimes' CMake rules for a static Linux-musl build and compiled unchanged; `__config_site` is configured from the upstream template, never written by hand; sabotage-linux's sanitized kernel headers (`linux-headers.lock.json`) are seen by the runtimes' build alone, for `<linux/futex.h>`, never by a program; `static.ld` keeps the unwind tables in the read-only segment and every program links with `--eh-frame-hdr`; the `cxx` scenario of both suites requires the Itanium trace of `cxx_exceptions.cpp` that `tests/User/cxx_itanium_trace.h` records and that CI's `itanium-reference` job requires of a native Linux build — change that file only with a Linux run that prints it. Dynamic linking (S5.3) is musl's: `MuslLibc.BuildSharedAsync` compiles every source of `libc.a` again with `-fPIC` beside `ldso/dlstart.c` and `ldso/dynlink.c` and links `libc.so` with `-shared -e _dlstart` and musl's linker options; it is the dynamic linker at `/lib/ld-musl-<arch>.so.1` of the boot package and resolves `DT_NEEDED` "libc.so" to itself; its one change, `patches/musl/dynlink.c.patch`, takes the start message in `__dls3` before anything is opened; a dynamic program links `Scrt1.o` with `-pie --dynamic-linker`, and every image another component maps (a shared library, a dynamic program) links with `-z separate-loadable-segments`, so that its code maps from the package without a copy; `membarrier`'s private expedited barrier is `PROCESS_WRITE_BARRIER`; compiler-rt's complex multiplication builtins join the pin because `libc.so` links whole. The shared C++ runtime (S5.4) is the same sources and options as the static one, position-independent, linked by `LlvmRuntimes.BuildSharedAsync` as `libunwind.so.1`, `libc++abi.so.1` (on libunwind) and `libc++.so.1` (on libc++abi and libunwind) in the package's `/lib`; every dynamic image starts with compiler-rt's `crtbeginS.o` (its hidden `__dso_handle`, built from the pinned `crtbegin.c` with init and fini arrays and no frame registry), and the 128-bit division builtins join the pin for libc++'s filesystem clock. The phase S acceptance is `tests/User/acceptance_main.cpp` with its library: exceptions across modules, threads with the library's `thread_local` objects, `exception_ptr` between threads and a SIGSEGV left with `siglongjmp`; the S4 C++ scenarios also run as the dynamic program `/bin/cxx`. The layer-2 scenarios (`libc`, `libc-test`, `cxx`, `spawn`, `process`) boot the release kernel on both hosts (T2.1b, `KernelImageBuilder.RELEASE_KERNEL_SCENARIOS`): no self-test, no fixture, no MSVC; the release suite judges them and requires their `RequiredLines`. The `libc` scenario of both suites runs `tests/User/libc_hello.c` as the root task and requires its last line; the `libc-test` scenario runs musl's libc-test at the pinned commit (`src/Substrate/libc-test.lock.json`, checked out by `setup`) under the system layer's root task (S7.1): every test `tests/User/libc-test.json` selects is compiled unchanged and linked twice, statically and dynamically against `libc.so` (its `dynamicOnly` tests dynamically alone, its `libraries` beside them, its `linkLibraries` needed at the start and linked as objects into the static form), placed in libc-test's layout under `/libc-test`, and `tests/User/libc_test_runner.c`, the scenario's `/bin/init`, starts each run in a process of its own from `/libc-test` with `posix_spawn` and requires it to exit with zero; the math suite (`math`) is built dynamically alone, as libc-test builds it, less what `mathExcluded` leaves out on an ISA (S7.2); the scenario requires `all N tests passed`; a test leaves the selection only with a reason recorded in the S1.3, S7.1 or S7.2 document, and nothing of libc-test is patched.
- Started programs (S5.2, S5.3): a program another process starts is a position-independent executable of the boot package; a static one (`ET_DYN` with `PT_DYNAMIC`, no `PT_INTERP`) is linked by `MuslLibc.LinkStartedProgramAsync` with `rcrt1.o`, which is musl's `ldso/dlstart.c` included unchanged and compiled with musl's options, `-DCRT` and `-fPIC`, whose second stage takes the start message (`src/Substrate/libc/start.c`) before `__libc_start_main`; `StartedProgram.Validate` refuses at build any relocation that is not relative, a needed library and text relocations. The libc's process context (`witos/libc_context.h`: the log, the package and its size) is what crt1 and the start message fill, and the only way libwitos reaches the libc. libwitos (`src/Substrate/libwitos`, `witos/spawn.h`) is WitOS's library beside the libc, never in its namespace: its loader checks the whole ELF of the program and of its interpreter (a package path with no interpreter of its own) before `PROCESS_CREATE`, a dynamic program with `PT_PHDR`, maps executable segments from the package without a copy (published through its own view first) and every other segment (read-only data too, R2.1, so that a program may make its pages writable) and the first stack as anonymous objects of at most 64 pages, places the program at the start of the child's code arena, its interpreter 64 MiB above and the stack at the top, starts the thread at the interpreter's entry when there is one, builds the Linux stack image (argc, argv, envp, the auxiliary vector with `AT_PHDR`, `AT_ENTRY`, `AT_RANDOM`, `WIT_AT_START` and `AT_BASE` for an interpreter alone), and sends the start message (`witos/start.h`: the log with `WRITE|TRANSFER`, the package with `MAP|EXECUTE|QUERY|TRANSFER`, the package's size) before `THREAD_CREATE` version 3; a failed start closes everything it made, and a started program closes its endpoint once the message arrived. The process manager (S6.1) is libwitos's `witos_manager_run`, run by the system layer's root task (`src/RootTask`), which starts `/bin/init` and ends with its status: one channel whose receiving end the manager waits on beside its first process, and a duplicate of the other end with `SEND` alone for every process it starts, the third capability of the start message (version 2, `witos/start.h`); a request (`witos/manager.h`) is a memory object checked whole before anything starts and the end of a channel for the reply, which moves the process handle back without `MANAGE`, and the manager keeps none. The libc's `posix_spawn` (musl's `posix_spawn.c` leaves the build) and `wait4` speak it: file actions, process groups, sessions and scheduling are `ENOSYS`, child ids are the library's from 2, a wait for more than four children polls at 10 ms, the libc's default signal actions exit with `WIT_EXIT_SIGNAL(sig)`, which `waitpid` reports as `WIFSIGNALED`, and a fault is reported as `SIGSEGV`. A child starts in the caller's current directory with the caller's standard streams (S6.2, start message version 3
and spawn request version 2): the file actions change them in order (`addchdir_np`, `addfchdir_np`, `addclose`,
`adddup2` between standard output and error, a close of any other descriptor does nothing), a relative program path
names the program from the child's directory, and a file or a pipe as a stream is `ENOSYS`; the standard descriptors
are the log capability one by one: a child gets the log for each standard stream the caller has open as the log (a file or a pipe `dup2` put there stays the caller's), and closing one takes it away until a `dup` or `dup2` puts another there (R2.3a). The `process` scenario of both suites boots
that root task with `tests/User/process_init.c` as `/bin/init` and requires its last line and the root task's report of status 0. The `spawn` scenario of both suites runs `tests/User/spawn_main.c` as the root task with the static child and the dynamic program (`tests/User/dynamic_main.c`, its library and the `dlopen` plugin), the phase S acceptance program and `/bin/cxx`, and requires the child's first line, the last lines of the dynamic, acceptance and C++ programs and the root's last.
- The system layer's sysroot (R1.2a, `Substrate.Sysroot`) lays the substrate out as a Linux musl rootfs under `artifacts/sysroot/<arch>`, marked by `etc/witos-release`, built anew from the substrate's own builds and never a system copy: musl's installed headers, `witos/` (the system layer's and the kernel's ABI-1 headers), libunwind's and libc++'s (`c++/v1` with the configured `__config_site`); `Scrt1.o`, `rcrt1.o` (no `crt1.o`), musl's `crti.o` and `crtn.o`, `libc.a`, `libc.so`, musl's empty libraries, the C++ runtime static and shared with linker scripts for the unversioned names (`libc++.so` is `INPUT(libc++.so.1 -lc++abi)`), `libwitos.a`; its own clang resource directory with compiler-rt's builtins and `clang_rt.crtbegin.o`/`crtend.o` for the triple; ICU's headers alone (R1.2b: the `unicode/` headers of ICU4C's common and i18n libraries from the source tarball `src/Substrate/icu.lock.json` pins), never an ICU library until a scenario needs culture data; and CMake's platform modules for the system WitOS from `src/Sysroot/cmake` (`CMAKE_EFFECTIVE_SYSTEM_NAME` Linux, so CMake's ELF rules apply, while `CMAKE_SYSTEM_NAME` stays WitOS and `LINUX` unset). `Sysroot.DriverOptions` builds WitOS code with clang's plain driver; the `sysroot` scenario of both suites runs `tests/User/sysroot_init.cpp` so built as `/bin/init` and requires its last line.
- The runtime is the Unix form, `TargetOS=witos`. Its patch set is `patches/runtime/`, each patch named by the path it changes with `/` as `.`, listed in `RuntimeWitos.PATCHES` and pinned with the commit in `build/runtime/runtime.lock.json` (a file WitOS adds is a patch from no text); `runtime-witos` applies it to the pinned dotnet/runtime in a worktree on a Linux host and builds with upstream's `build.sh -os witos` (R1.1: CoreLib for both ISAs, which must name `WITOS`; R1.2b: NativeAOT's native part, `AsmOffsets.cs` and its CoreLib, cross-compiled with the pinned clang and lld against the sysroot, `ROOTFS_DIR`). The native build recognizes the sysroot by `etc/witos-release` in `eng/common/cross/toolchain.cmake`, names CMake's system WitOS, never Linux (`CLR_CMAKE_HOST_WITOS`, `CLR_CMAKE_TARGET_WITOS`, `TARGET_WITOS`), links C++ with libc++ through the existing `CLR_CMAKE_CXX_STANDARD_LIBRARY` knob and builds no GSSAPI or OpenSSL shim; R1.3: ILC knows `TargetOS.WitOS` (`--targetos witos`) and is built with the host's JITs for the x64 Linux host by the pinned clang (`clr.alljits+clr.tools -os linux`, with the Linux host's development packages); `tests/Runtime.Witos/Platform.cs`, compiled against the witos CoreLib alone, becomes an ELF object for each ISA whose `Main` the JIT folds to returning zero, which `runtime-witos` requires. R2.3a: `runtime-witos` also builds upstream's shared framework for witos (`libs.sfx`, the libraries' Unix flavors) and the reference pack; the acceptance compiles against the reference pack as an SDK build compiles a program, ILC takes the shared framework's libraries beside the NativeAOT ones, and its output goes through `System.Console`, which needs the libc's `dup` and a pipe for System.Native's signal handling thread. R2.2: the M3 acceptance `tests/Runtime.Witos/Acceptance` carries the probes of the frozen line's NativeAotBoot experiment, removed with it at K8.2 (hardware faults, exception dispatch, finalization, managed threads, thread creation beside parked threads) with the libc's `mmap`, `munmap` and `gettid` where they called kernel32, and adds an allocation the GC cannot serve, the thread pool and waits; it calls the libc as a direct P/Invoke for its native pages and the thread's id, and the `runtime-acceptance` scenario requires `[M3] NativeAOT on <isa>: 32 runs passed, 0 failed` on both ISAs. `eng/native/tryrun.cmake`'s witos answers are measured, never reasoned: `runtime-witos` configures once with `build/runtime/tryrun-measure.cmake`, which forgets them, so that CMake keeps every probe it compiles, runs each in the guest under the system layer's root task (`tests/User/tryrun_init.c` as `/bin/init`, the `runtime-tryrun` scenario) and requires that tryrun.cmake answers as the guest does; change an answer only with that measurement; the set started empty at step R1, is measured against the FreeBSD/Haiku budget at every R step, and follows the order of preference of RFC 0015 §4: an existing configure check, then an existing runtime knob, then a `TARGET_WITOS` branch beside the other platforms' branches, never a change to CoreLib semantics, the GC, the JIT or the hosts' logic. Platform identity is `OSPlatformName` (`WITOS`) and the RID graph (`witos-x64`, `witos-arm64`); no `IsWitOS()` public API. Never emulate `/proc`, cgroups, `fork` or Win32; an unsupported API fails explicitly.
- ADRs and implementation documents are English in `@Docs/Implementation/`; the plan is Russian; vision documents in `@Docs/` change only by a decision recorded in an ADR, and their section numbers stay stable because other documents cite them.

## Kernel and UHI rules

These describe the kernel as it is and are carried into phase K. Where RFC 0011 §8 changes a mechanism (join becomes a wait, `THREAD_COMPLETE` merges into `THREAD_EXIT`, APCs become activations, the delivered-tick clock goes), the rule holds until the K step that changes it, and that step rewrites the rule.

- The kernel and its EFI loader (T3: x64 in T3.1, ARM64 in T3.2) are C17 compiled by the pinned clang for the architecture's `KernelArchitecture.KernelTriple`, `x86_64-unknown-windows` or `aarch64-unknown-windows` (PE/COFF, the Microsoft conventions; x18 stays the platform register clang never allocates on ARM64): freestanding with `-nostdinc`, `-fno-stack-protector`, `-O0` as MSVC's `/Od` was, `-Wall -Wextra -Werror`, CodeView records, linked by the pinned `lld-link` with `link.exe`'s options; MSVC builds no part of the kernel. Its assembly is GNU syntax (`.S`; `.intel_syntax noprefix` on x64) through clang's integrated assembler. The x64 privileged, port and identification instructions are the inline functions of `witos/x64_instructions.h`, each that changes processor state or reaches a device a compiler barrier; never declare an MSVC intrinsic; ARM64's system registers are read and written in its assembly. Each architecture's `compiler.S` holds `memcpy`, `memset` and `__chkstk`. The kernel policy's fixtures probe with `src/Runtime.Native/X64/chkstk.asm` until K8.4. `release --arch arm64` checks the ARM64 release kernel with the release suite, as CI does.
- Keep UEFI details in `src/Boot.Uefi/`.
- Keep x64 instructions, descriptor tables and QEMU-specific test mechanisms in `src/Kernel.Arch.X64/`, and ARM64 instructions in `src/Kernel.Arch.A64/`. QEMU virt board devices (PL011, GICv3, generic timer, Arm semihosting exit) stay in `src/Kernel.Platform.QemuVirt/`.
- The common kernel and the loader learn the architecture only from `wit_arch_identity()`. The kernel path needs `kernel-boot` and `kernel-foundation` only; an architecture links `kernel-common` (objects and user-mode policy) together with the architecture functions that policy calls, which for ARM64 is A2. Board devices needed before on-demand mapping (a memory-mapped console) come from `wit_platform_boot_devices`, never from the architecture layer. On boards whose interrupts share one vector, the board claims and completes interrupts through `wit_platform_interrupt_claim`; the architecture never programs the interrupt controller.
- ARM64 user threads run at EL0t with their frame at the top of their own kernel stack; resume an EL0 frame only from there. The raw TLS base is TPIDRRO_EL0 (read-only at EL0), compiler TLS is x18, which the kernel sets on every return to EL0, and TPIDR_EL0 is per-thread frame state. Kernel level-0 entries deny EL0 access and execution at table level; user pages are nG and always PXN. An ARM64 thread context carries X0–X30, SP, PC, PSTATE as the condition flags alone, V0–V31, FPCR and FPSR; TPIDR_EL0 stays frame state outside the context and x18 is reset to the compiler TLS on every return to EL0, so validate PSTATE and the FPCR mask probed at boot before applying a context and never let a context change either register. Keep the compiler helpers (`memcpy`, `memset`, `__chkstk`) in assembly. Every frame resume clears the exclusive monitor (`CLREX`) before `ERET`. User PE images must match `wit_arch_identity()->PeMachine`, and an exception directory is accepted only where the identity has `WIT_ARCH_PE_UNWIND`; host harnesses that link `pe.c` share `HostIdentity.c`.
- Publish every page that received code with `wit_arch_publish_code_page` before `wit_arch_publish_code`: ARM64 cleans the data cache to the point of unification, which TCG cannot check.
- Keep the common kernel independent of firmware structure definitions.
- Keep board devices in `src/Kernel.Platform.Q35/` and kernel self-tests under `WITOS_SELFTEST`: architecture-independent tests in `tests/Kernel/`, the expectations and suites of one ISA in `tests/Kernel.<isa>/`, and the fixture protocol in `tests/User/protocol.h`. Kernel sources are listed only in `build/kernel-<arch>.json` and `build/layers/*.json`; each kernel C source belongs to exactly one layer, and the release kernel links no self-test layer. User-mode code never returns to `src/Kernel.Arch.X64/`. The mechanism fixtures are C sources of `tests/User/Fixtures`, one for both ISAs (K8.3): built by the pinned clang for the layer-2 triple with `-Os` and linked by `fixture.ld` into one executable segment at `WIT_USER_CODE` that starts with the entry and has no writable data, the code window `wit_user_create` maps up to the startup block (three pages); their state lives at fixed offsets of the data page (a failed status at 1304, the checks at 1312), they call the kernel through `witos/syscall.h`, their threads are of the one form on stacks of their own reservations (`fixture.h`; a thread's record carries its stack, its index and the word that is its TLS base), a faulting thread's stack is the reservation at `WIT_THREAD_TEST_STACK` whose guards the kernel tests name, and they write assembly only where the register itself is tested.
- Use ordinary .NET for development tools.
- Do not add speculative public resource APIs, distributed services or GUI work to a boot milestone.
- The kernel now owns its page tables, but firmware memory remains reserved until reclamation is explicitly designed and tested.
- Treat mapping/physical-page operations as serialized bootstrap APIs. Current allocation and mapping setup runs with interrupts disabled.
- Context switching currently preserves baseline x87/SSE state; do not introduce AVX/XSAVE assumptions without extending state management and tests.
- Keep shared kernel mappings supervisor-only. Never reuse the kernel scratch branch as a user page-table branch.
- Validate user handles and complete buffer ranges before copying/output. Close handles and free only component-owned pages on teardown.
- A call's buffer is copied through the kernel's view of each page (S6.2, `wit_virtual_view`): usable memory through the identity map, a page of the boot package through the storage window, which is the only kernel mapping of the package; a device region's page (`WIT_PAGE_DEVICE`) is never a call's buffer, even where the kernel maps the region for itself, and the validation refuses it with `BAD_ADDRESS` before any state changes. Cache maintenance of a published package page goes through the same view.
- Reservations at a fixed address and the release of a part (S5.1): `MEMORY_RESERVE` with a nonzero address reserves exactly there or refuses (`BUSY` on overlap), `MEMORY_RELEASE` with a nonzero size frees that part of one plain reservation, shrinking or splitting it (a split needs a free slot), and a mapping of an object is released whole; `MEMORY_PROTECT` covers one reservation or a run of adjacent ones (S7.2), each part, a mapping within its own rights, validated before any page changes; every unused argument of a call is zero, in fixtures too. A file of at least a page starts at a page boundary in the boot package (`wit_package_open` requires it) and the root task's package handle carries `EXECUTE`, so that code maps from the package without a copy.
- Keep dynamic reservations separate from fixed image/stack mappings. Reservation must not consume backing RAM; failed commit must roll back additions; decommit retains the reservation and recommit zeroes pages.
- Reset must validate one entire committed dynamic range with interrupts disabled before zeroing owned backing. Preserve permissions, reservations and all commitment/accounting; never decommit/recommit to simulate reset. Reject unsupported unlock semantics before mutation.
- Keep memory-discovery snapshots consistent through IF-disabled validation and copy-out; reject the full destination before any write. Report fixed mappings and private tables as ownership costs, and retain no-access commitments in accounting.
- Track committed no-access pages as owned. Invalidate active translations before reuse, reclaim empty private page tables, and keep memory-call work bounded by prototype quotas.
- Validate user return addresses/selectors/flags and the selected thread's owning stacks, or its alternate stack (S3.1), before IRETQ. An empty stack sits at its top: a stack pointer equal to the top of the thread's stack or alternate stack is valid on a return, in a context `THREAD_CONTEXT_GET` reads or `THREAD_CONTEXT_SET` and `EXCEPTION_CONTINUE` apply, and at a fault delivery, whose frame goes below it (K8.2); never treat it as a lost frame. Timer returns must preserve condition codes; syscall flags follow the explicit ABI.
- Switch TSS.RSP0, raw FS TLS and optional compiler GS TLS with the selected user thread. Keep FSGSBASE disabled and restore zero FS/GS bases on kernel supervision and idle; the current kernel has no segment-based TLS.
- Detached creation returns no join capability. Keep its private generation-bearing identity live through user-space TLS cleanup, deny joins, and automatically reap only after entry to the exit syscall. Free user pages, never the currently executing fixed kernel stack; last-thread completion must restore kernel FS/GS/CR3.
- Reference-bearing thread creation validates the copied request and the entire optional native-ID output before allocation, then atomically publishes the independent reference and initial suspended state. Roll back the observer, private identity and every stack/TLS page on failure. Closing a reference must not terminate the thread; private detached ownership lasts through user-space cleanup and THREAD_COMPLETE. Preserve the typed DWORD native callback ABI, fixed-stack limits and explicit normal-only priority policy.
- Coordinated full-runtime components require THREAD_COMPLETE after user-space TLS/runtime notifications; raw THREAD_EXIT terminates the entire component before any peer can resume. Keep ordinary native raw-exit behavior separate. Completion is a lifecycle assertion, not a security capability or kernel implementation of ThreadStore/GC detach. Preserve kernel-owned abrupt caller/cause diagnostics and never reclaim the currently executing kernel stack.
- Publish join wait edges and wakeup results with interrupts disabled. Reject cycles before parking, preserve thread resources until exit/join/close, and roll back all partial thread creation.
- Serialize event state checks, parking and completion publication with interrupts disabled. Expire parked deadlines before later signal/close calls; completed waits must not follow a reused event handle.
- Distinguish join edges from event/sleep waits. Idle IRQs must resume their CPL0 frame without replacing saved user contexts; use the adjacent STI/HLT/CLI path with zero kernel FS base.
- Keep legacy delivered-PIT deadlines separate from the HPET monotonic domain. HPET is the explicit q35 profile: supervisor-only UC mapping, comparator IRQs disabled, no reset after publication, and serialized reads with IF clear. Neither clock is UTC; PIT still limits wake scheduling.
- Define kernel quotas only in `src/Kernel/include/witos/limits.h` and user-space native quotas only in `src/Runtime.Native/native_limits.h`; keep format constants (ABI structure arrays, layout addresses) beside their structures.
- Keep every change to a pinned upstream file in `patches/<repository>/<output>.patch` with its Source, Output, Before and After header and a purpose; apply it only through `UpstreamPatches`, which has no fuzz. Never add string replacements of upstream text to the tool; slices of unchanged bodies may stay in code.
- Calculate source pins from canonical upstream download bytes, not CRLF-converted Git worktree copies. Keep exact-byte verification; do not normalize away a hash mismatch in the audit.
- Keep process write barriers in the architecture/kernel layer. The UP implementation requires the same single-online-CPU invariant reported by discovery; refuse unsupported topology until remote-CPU fencing exists. Preserve argument validation, zero result and native error state. A data fence is not managed suspension, instruction-cache maintenance or SMP support.
- Keep CPUID/cache decoding in the architecture layer. Bound enumeration and arithmetic, return unknown for unsupported/malformed data, and distinguish reported cache capacity from host measurements or allocation limits. Cache publication is serialized on the sole online processor; broader CPU topology requires a new discovery policy.
- WaitAny must copy and validate every handle before consuming any event, retain only kernel-owned generation-bearing snapshots while parked, and publish one winner index atomically. Share ordering with single-event waiters, expire the proper deadline domain first, clear snapshots on completion, and never let close/reuse overwrite a completed wait. Keep the four-handle quota and the unsupported wait-all mode explicit; an activation ends a parked wait or sleep with `INTERRUPTED` after its callback ran, and a caller that wants the rest of the wait restarts it at its absolute deadline.
- Channels: `CHANNEL_SEND` validates the request, the bytes, every handle (live, `TRANSFER`, a movable kind, named once) and the peer's queue before it moves anything, then moves the handles out of the sender's table atomically with the message; `CHANNEL_RECEIVE` validates the buffers and that the handles fit the receiver's table before it dequeues, and a refused message stays queued; closing the last handle of an endpoint drops its queue with the capabilities it carried and wakes the peer's waiters with `PEER_CLOSED`; the kernel knows no message format. The channel table is the kernel's (32 channels; a component creates at most four live ones, charged while it lives) and a change of an end re-evaluates the waits of every component; a capability of a kind whose record belongs to one process (an event, a device, an interrupt binding, a pin) carries the Id of the process it left and is received by that process alone, while endpoints, memory objects, process handles, thread handles, the clock and the kernel log (S5.2: the root task delegates its output with `DUPLICATE` and `TRANSFER`) cross processes; a component's end voids its own capabilities in flight, releases its endpoint handles and collects the ends only cycles of queues hold. Keep the four-message, 256-byte and four-handle quotas explicit, and never count a wait for queue room as implemented.
- Memory objects: `MEMORY_OBJECT_CREATE` takes an object's pages from the component's quota eagerly and zeroed, all or none; `MEMORY_OBJECT_MAP` validates the whole request (version, size, flags, a protection among NONE, READ, READ|WRITE and READ|EXECUTE, the target `WIT_PROCESS_SELF`, the handle's `MAP` right and its `WRITE` or `EXECUTE` right for the protection, alignment, the window within the object) before it reserves anything, and a mapping is a reservation of alias entries that remembers the object and the mapping handle's rights: protect stays within those rights, commit, decommit and reset are `DENIED`, release unmaps. An object ends with its last handle or mapping, never earlier; a message holds a reference for a handle in flight. `CODE_PUBLISH` requires every page mapped READ|EXECUTE and publishes through the architecture's cache maintenance. The object table is the kernel's (64 objects): an anonymous object owns its pages from the kernel allocator, charged to its creator's page quota beside the creator's own pages while the creator lives, and a component creates at most eight live objects of 64 pages, a system layer process (the root task and the processes it creates) 32 (`ObjectLimit`, S6.1). A component's references end with it: its handles, pins and capabilities in flight at the exit, its mappings at the teardown, in that order, and a channel queue takes a message out before releasing what it carried; an object a torn-down component created lives on uncharged with the references others hold. `MEMORY_OBJECT_MAP` maps into the caller or into a live process a handle with `MANAGE` names; the mapping is the target's reservation.
- Devices: the platform enumerates once at boot into `WitDeviceDescriptor` records the kernel validates and publishes unchanged in one read-only page; the common kernel never parses ACPI or a device tree and never reads a descriptor's meaning, so nothing in `src/Kernel` knows a vendor, a class or a driver. The device table is a memory object of kind `TABLE` whose `ACQUIRE` right is the authority to take devices; `DEVICE_ACQUIRE` keeps one holder per descriptor until that component's last handle, in its table or in flight, is gone, and a component's end frees what it held. `DEVICE_MEMORY` publishes a memory region as an object of kind `DEVICE` mapped through `WIT_PAGE_DEVICE` (PAT entry 3 UC on x64, device-nGnRnE on ARM64), never executable; port regions are described, never mapped. The boot contract carries the firmware tables as physical addresses, zero when absent, and the virt board boots with `acpi=off` so that the firmware publishes the device tree. Keep the 16-descriptor table explicit.
- Interrupts and DMA: a binding is one per line kernel-wide, holds the device and the event, and ends with its last handle, masking the line; the architecture masks and completes a device line before the kernel sets the bound event and dispatches like a tick, and a line nobody bound stays masked. x64 device vectors 0x21–0x2F enter through `wit_x64_device_entry` with the vector noted in `wit_x64_device_vector` on the one processor with interrupts disabled; virt claims SPIs in `wit_platform_interrupt_claim` and programs the distributor for group 1 routed anywhere. `DMA_PIN` needs the device handle with `BIND` and an anonymous object with `MAP`: the pin holds the object, the ranges are physical and merged, a window the caller's buffer cannot take pins nothing, and device regions and the table are never DMA memory. There is no `PIN` right and no IOMMU; the device holder is the trust boundary, and the kernel programs no device. Keep the eight-binding and eight-pin quotas explicit.
- The root task: the loader reads `WITROOT.BIN` into extents the boot contract names (v6, optional) and the kernel maps them beside the package; `wit_flat_validate` checks the whole flat image (magic, version, header size, count, alignment, protection, file ranges, the image window, disjointness, the entry in executable code, zero reserved words) before `wit_user_create_flat` maps a page, and a failed creation destroys the component. The startup descriptor at `WIT_USER_INFO` carries a counted handle table (log, package, device table) so K6 appends without a layout change; the package is a memory object of kind `PACKAGE` over the boot extents that the kernel never parses for the root task, and one mapping of any object covers at most 64 pages. The root task has the full profile's pages, tick budget and window (2048 pages, the runtime tick budget, the fixed window to `WIT_RUNTIME_USER_LIMIT`, S1.3), the system layer's reservation table (`WIT_PROCESS_RESERVATION_CAPACITY`, 256, S5.4), which every space's arrays are sized by, and the system layer's threads, handles and events (`WIT_PROCESS_THREAD_CAPACITY` 16, four in the self-test kernel until K8.4, `WIT_PROCESS_HANDLE_CAPACITY` 64, `WIT_PROCESS_EVENT_CAPACITY` 32, K5.3), which every process record's arrays are sized by; the PE components' full profile keeps 32 reservations, four threads, 32 handles and 16 events until K8.4. The release kernel starts the root task after the hello marker and panics on a nonzero exit; the flat format is a boot format for the root task, not an application format, and the PE loader stays unreachable from the release kernel's component path.
- The one thread form: a version 2 `THREAD_CREATE` validates the whole request (size, flags, a 16-byte aligned stack pointer whose byte below lies in a committed writable reservation of the caller, whose bounds become the thread's — a reservation is looked up strictly inside `[base, base + size)`, since a stack's top may be the next reservation's base (S4), a TLS base in user space or zero, an executable entry) and maps nothing; the kernel's stacks and TLS pages belong to version 1 alone, which the mechanism and policy fixtures keep until K8.4 and which takes one of the first `WIT_USER_THREAD_CAPACITY` slots, the windows of `user_layout.h`, while versions 2 and 3 take any slot below the process's `ThreadLimit` (K5.3). `THREAD_EXIT` checks a named reservation before the exit and releases it only after the thread no longer runs, at the reap, and its third argument (S2.1, `WitThreadExitRequest`) names a user word the kernel zeroes and an event it sets at that same moment — what a libc's thread list needs, as `CLONE_CHILD_CLEARTID` gives Linux — validated whole before the exit so that a refusal returns and nothing of a refused request is served; `THREAD_SET_TLS` changes the caller's FS base from its next return on x64 and is `UNSUPPORTED` on ARM64, whose TPIDR_EL0 EL0 writes and the kernel preserves. x64 accepts `SYSCALL` (RDI, RSI, RDX; EFER.SCE, STAR 0x23/8, LSTAR, SFMASK clearing IF, TF, DF, AC) beside `INT 0x80`: the entry switches to the selected thread's kernel stack and builds the interrupt gate's frame, so one restore path serves both; the first thread's argument is in RCX and RDI. Never let a version 2 thread's exit free pages it does not own.
- The alternate stack (S3.1): `THREAD_STACK_ALTERNATE` records for the calling thread one 16-byte aligned range of at least `WIT_EXCEPTION_STACK_MINIMUM` bytes inside one committed writable reservation of the caller and apart from its stack, validated whole before the record changes, cleared by a zero request and `BUSY` while the caller's stack pointer is inside it; `validate_return`, the context validation and the fault delivery accept the thread's stack pointer in either range (`wit_user_thread_stack_range`), and a delivery whose interrupted stack has no room for the callback frame enters the callback at the top of the alternate stack when the thread is not on it already. On x64 the callback frame leaves the 128-byte SysV red zone below the interrupted stack pointer (`RED_ZONE_BYTES`), since layer-2 leaf functions keep data there. The kernel knows no signal, no `SA_ONSTACK` and no handler: the libc switches stacks itself for ordinary signals and needs the kernel only where the interrupted stack is exhausted.
- Processes: the registry has eight slots with a static kernel stack per thread of every slot on both ISAs, and `PROCESS_CREATE` takes records from a pool of eight; a new process is an empty address space with one capability, the endpoint the request names (moved with its rights), the full profile's quotas bounded by the page quota asked and the creator's tick budget, the system layer's reservation table (S5.4) and its threads, handles and events (K5.3), no thread, and it is scheduled from creation. `THREAD_CREATE` version 3 names the process (`MANAGE`): the stack lies in the target's reservations, the entry is executable there, the handle stays with the caller and serves `OBJECT_WAIT` and `THREAD_QUERY` alone across processes. The dispatcher round-robins the live components and their threads, switching the address space, kernel stack and TLS (`wit_arch_space_switch`); deadlines and pressure expire for every component on one clock read; a device line reaches its binding's owner. A created process that ends is settled, torn down at once with its space left for the kernel root, taken off the registry and its waiters woken; if it was running, the dispatcher resumes another frame directly (`wit_arch_resume_frame`) and its kernel stack is abandoned; its record lives for `PROCESS_QUERY` until the last handle; a threadless process whose last handle goes ends. The root's end ends every created process; nothing of the pool survives a run. Never run a created process's teardown while its space is active, never charge a tick to a component that is not running, and never let events, devices, bindings or pins cross a process boundary until their records leave the process.
- Clocks: UTC is the board's real-time clock read once at boot (`wit_platform_realtime_seconds`: the CMOS RTC on q35, the PL031 at the virt profile's fixed base) plus the monotonic time since, converted in whole seconds and remainder so that no product overflows; its frequency is 10^9 and a board without a real-time clock reports `UNSUPPORTED`, never an invented time. `CLOCK_SET` needs the clock capability (kind `CLOCK`, the handle itself, no record), sets UTC alone, refuses a value before the boot or beyond 2^63, and the root task alone receives it, as its fourth initial handle. The monotonic domain, the delivered-tick clock and `MONOTONIC_QUERY` are unchanged until K8.4.
- Processors: the platform enumerates them once at boot (`wit_platform_processors`: the MADT reached from the loader's RSDP on q35 with every table's signature, length and checksum verified and nothing else of ACPI read; the `/cpus` nodes of the device tree on virt) and the common kernel keeps a table of eight with the boot processor first, panicking on a table without it or with a repeated identity; every present processor is started at boot (K7.2) and `wit_processors_online()` counts the started ones, while `wit_processors_scheduling()` (1 until phase P) replaces the old constant wherever the single scheduling processor is required: `CPU_CACHE_SIZE`, the suspension and context calls. `PROCESSOR_QUERY` keeps the 4-byte form for the mechanism fixtures until K8.3 and adds the record form with the caller's version and size; features and cache sizes are reported for online processors, each by itself at its start. `THREAD_AFFINITY` records a mask the scheduler does not honour yet: nonzero, within the table, with an online processor, read with `QUERY` and set with `AFFINITY`. A scenario asks for processors through `BootRequest.Processors`; `boot-smp2` must keep passing on both boards with `Processors present/online: 2/2`.
- Secondary processors (K7.2): `cpus.c` starts every processor of the table at boot through the architecture (`wit_arch_secondary_prepare`, `wit_arch_secondary_start`: INIT and two start-up interrupts through the local APIC in xAPIC mode with a trampoline in a page claimed below 1 MiB on q35, PSCI `CPU_ON` through `hvc` on virt) and waits for each to report itself ready within a bounded monotonic time, panicking otherwise; a started processor idles with interrupts enabled and serves the kernel's two requests alone, a fence and the invalidation of one page, each sent one at a time (`wit_arch_ipi`: vectors 0xF0/0xF1 by the interrupt command register; SGI 0/1 through ICC_SGI1R_EL1) and acknowledged within a bounded wait. `PROCESS_WRITE_BARRIER` fences the caller and every online processor through `wit_cpus_fence_all`. No thread runs on a secondary processor until phase P: it takes no system call, no user fault and no activation, it loads no task register on x64, and a kernel exception there is a panic. The platform maps and enables a processor's interrupt frames (`wit_platform_processor_prepare`, `wit_platform_processor_interrupts_enable`) and sends and completes its inter-processor interrupts (`wit_platform_ipi`, `wit_platform_ipi_complete`); q35 keeps the local APIC on only when more than one processor is online, and the PIC's line then enters through LINT0 as ExtINT. Keep the request kinds, the one-in-flight rule and the bounded waits explicit; never queue requests in the kernel and never let a request's acknowledgement be assumed.
- `THREAD_ACTIVATE` validates the handle's `ACTIVATE` right, the callback (executable, not writable), the registered fault callback and the per-thread quota before it marks the target. An activation is delivered only at the target's return to user mode, through the one fault callback with the interrupted context and the activation vector; a thread inside a delivery or suspended keeps its activations pending in order, `EXCEPTION_REGISTER` is `BUSY` while one is pending, and a stack with no room for the callback frame ends the component as a fault of the thread. Never run an activation's callback in CPL0 and never add a user-space dequeue.
- Memory-pressure events are kernel-controlled, wait-only manual events sharing existing quotas. Derive pressure from settled physical/quota headroom, count no-access backing and private tables, preserve explicit hysteresis, expire deadlines before notifying, and never publish transient failed-allocation pressure. Purge closed generations before reuse; kernel notification authority must not leak to user Set/Reset. Dispatch a caller made Ready by the final expiration pass.
- Keep native initializer execution in user space. Kernel image descriptors are readonly; ReadyToRun/TypeManager/GC-table initialization belongs to the actual runtime, not the kernel.
- Keep __chkstk in the x64 layer and follow its special compiler ABI: RAX supplies size and is preserved; do not allocate/move the caller stack or clobber argument/nonvolatile/SIMD registers. Probe downward one 4 KiB step at a time plus the final partial span; never skip a guard page via an endpoint-only check or wrapped size. Fixed-stack overflow remains a contained user fault, not automatic growth or managed exception handling.
- Treat the boot handoff and experimental user ABI as evolving contracts, not a frozen public SDK.

## Kernel policy that leaves at K8.4

The PE loader, the DLL lifecycle and static PE TLS, the file namespace over the boot package, the kernel-held environment and current directory, and the kernel's PE unwind validation are policy that RFC 0011 §8 moves to the system layer. The rules apply while the code exists; do not extend it; it is removed at plan step K8.4, with `src/Runtime.Native`, its user side, and the fixtures and host harnesses that test it.

- Validate static PE TLS before allocation; require real directory fixups. Accept a nonempty TLS callback list only in the library TLS profile, bounded, with one DIR64 fixup per entry and every entry in executable code; the executor runs a library's callbacks before its entry point for every reason, as on Windows, and a library without an entry point gets them for the process attach alone. DLL `thread_local` support must keep the Windows trace of the MSVC CRT. Load a library with an entry point while other threads run only when each follows the notification protocol, and reserve their notification resources before the attach begins. Capture the relocated seed before publishing the component, preserve raw FS storage, and roll back/reap the extra compiler TLS page. Never treat static template copying as dynamic TLS initialization or runtime attachment.
- Validate immutable, kernel-owned PE bytes before allocation. Keep parsing in the common kernel and page-table work in the architecture layer; unsupported directories must fail explicitly.
- Publish a PE component only after all sections, fixups and thread state exist. Preserve RX/RO/RW separation, keep image gaps unmapped, and roll back the entire unpublished component on allocation failure.
- The kernel keeps a component's environment and current directory for every module (`WIT_CALL_PROCESS_STATE`); adapters never cache them, and every operation is atomic and changes no state or output on failure. Seed the environment from an image only after validating the complete readonly table and all terminated strings, before TLS constructors/workers: a variable the creator set wins, and failed seeding removes what it added. Seeding makes system calls from GS-checked runtime code, so a process entry initializes its GS cookies first. Preserve native last-error, Windows' `SetEnvironmentVariableW` semantics and equivalent direct/import bindings. UTF conversion must use the real native heap with bounded input and caller-owned cleanup; environment transport is not GCConfig or PalInit execution.
- Accepted plain unwind metadata is structural evidence only. Reject handler/chained forms and relocation into validated unwind ranges; do not claim stack unwinding or managed exception support from parsing tables.

## Removed: the Windows-form user space

The runtime line of P6.4 — the NativeAOT adapters written against the Windows PAL, the guest C++ runtime, UCRT subset and pinned STL, the guest host build, `coreclr-guest`, the Win32 and COM binding surface, with their fixtures, self-tests, experiments, commands, overlay patches and workflows — was frozen by ADR 0024 and removed at plan step K8.2, after the Unix-form runtime passed the M3 acceptance (R2). Its plan stays as history in `@Docs/Implementation/P6.4-Plan.md` and its documents in `@Docs/Implementation/`. Never bring a Win32 surface back: .NET runs in its Unix form over the system layer.

Absolute deadlines may expire between a user clock read and kernel entry. Test deadline completion separately from mandatory idle-path coverage; do not require every successful sleep to park. Keep preemption and resource-accounting assertions independent and diagnostic.

Expected boot markers live in `tests/Expectations/*.json`; add a suite's new marker there, never as a list in `BootValidation`, and keep every expected marker emitted by a guest source. Contained user faults are accounted by the guest: a test accepts each expected fault through `wit_test_faulted`, and the host requires the closing `[TEST-SUMMARY] faults=N checked=N` to match the fault lines; never add a hand-counted fault total.

Guest boots run in QEMU virtual time (`-icount shift=2,sleep=off` in `BootScenarioRunner`): a 10 ms tick is 2.5 million instructions on every host. Keep tick budgets and timer expectations in guest instructions, never tuned to host speed; wall-clock boot limits only stop a hung QEMU.

A Linux host (T2.1a) builds everything but the self-test kernels' fixtures, which need MSVC: `setup` verifies the pinned LLVM Linux archive and builds QEMU from its pinned source release; the process runner starts a child through `setsid` as a process group and needs an init that reaps (`docker run --init`); a scenario looks for MSVC only when it builds fixtures; host tests that need Windows carry `[Platform(Include = TestPlatforms.WINDOWS, Reason = ...)]`; local work runs in `build/linux/Dockerfile` on a volume copy of the tree, never in the Windows checkout's `.tools` or `artifacts`, and CI's `linux-host` job is its gate, with the layer-2 scenarios of both ISAs on the release kernel (T2.1b). Keep images independent of the host and the directory: the kernel links with `/pdbaltpath:%_PDB%`, and `fingerprint` compares builds.

Use `setup` once for the pinned local QEMU package, clang and the musl tarball. `libc` builds the pinned musl and boots the first libc program on x64 alone; the `test` suites of both ISAs include the scenario. The test tool must distinguish successful boot, panic, unexpected exit and timeout. Never infer a passing boot from an exit code or log line alone.

For changes of the runtime port (phase R), its patch set or its pin, run `runtime-witos` for both ISAs on a Linux host (the image of `build/linux/Dockerfile`, on a volume copy of the tree); its `runtime-acceptance` scenario is the guest proof of .NET, and CI's `linux-host` job runs it.

Keep generated images, binaries, firmware, downloads, logs and credentials out of Git. They belong in ignored `artifacts/` or `.tools/`. Record actual results and limitations in documentation; do not mark a future milestone complete based on M0 boot.
