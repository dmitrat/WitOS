# Working on WitOS

## Project direction

The core objective is standard upstream .NET above a minimal native kernel and a hardware-independent system layer. Shells and applications eventually run on that .NET platform. [ADR 0024](@Docs/Implementation/ADR-0024-Three-Layers-and-Unix-Form-Runtime.md) (2026-10-06) fixes the architecture: a nano-kernel of mechanisms whose hardware part (`Kernel.Arch.*`, `Kernel.Platform.*`) is the UHI; a user-space system layer that owns loading, process state and the runtime substrate; unchanged upstream .NET in its Unix form (`TargetOS=witos`), whose POSIX-shaped substrate is private to the system layer. Neither Win32 nor POSIX is an external contract of WitOS. The specifications are [RFC 0011 v3](@Docs/RFC-0011-Kernel-Architecture-and-ABI.md) (kernel architecture, ABI-1 between the kernel and the system layer, ABI-2 between the system layer and .NET) and [RFC 0015 v2](@Docs/RFC-0015-DotNet-Runtime-Port-and-Compatibility-Contract.md) (the runtime port and the compatibility contract); the Implementation Strategy §157 maps the milestones to the plan. Current guest code includes the M1 foundation, M2 ring-3 isolation, sparse user memory, bounded user threads/TLS, events/deadlines, native PE loading, user-space C bootstrap and a partial native GC OS adapter written against the Windows form of the NativeAOT PAL; host-side C# tooling must not be described as guest .NET support.

The application compatibility target is unchanged portable managed binaries under upstream CoreCLR/JIT, standard TFMs/SDK/NuGet and optional additive WitOS APIs. NativeAOT is an early system implementation/deployment tool, not the application compatibility contract; do not replace upstream CoreLib or managed semantics.

Original vision documents live in `@Docs/`. Concrete implementation status and deliberate limitations live in `@Docs/Implementation/`. Preserve original drafts unless the task calls for revising them.

Track the program in the root PLAN.md: phases A, K, T, S, R, D, N, V, P with steps such as `K2.1`. Name a slice, its commit and its PR by its step; after each completed step update the plan's checkboxes, evidence links and next step; mark a step complete only when its guest acceptance passes on every supported ISA. The plan before ADR 0024 is `@Docs/Implementation/Plan-Archive-2026-10-06.md`; the frozen host line is `@Docs/Implementation/P6.4-Plan.md`.

## Rules of the new direction

These follow RFC 0011 v3 and RFC 0015 v2 and bind every new slice in phases K, T, S, R, D and N.

- The kernel keeps mechanisms only. Nothing in `src/Kernel` learns an image format, a file, a path, a directory, a name of a thread or process, an environment variable, a library or symbol, a language's exception format, a service or a device class. A call enters ABI-1 only when no composition of existing calls provides the mechanism and a layer-2 consumer with a test needs it (RFC 0011 §5); the kernel policy RFC 0011 §8 marks "leaves" is maintained until step K8 and never extended.
- Every system call validates its whole input, including every byte of a destination buffer, before it changes any state or writes any byte; a failed call changes nothing; an object is published only after all of its resources exist. Request structures start with `Version` and `Size`; an unknown version is `UNSUPPORTED`, a wrong size `INVALID_ARGUMENT`, and the kernel never pretends success. After step K1 a call number, a status value and a rights bit are never reused; `QUERY` reports the ABI-1 version and the feature mask of the families present (RFC 0011 §10.1). `@Docs/Implementation/ABI-Reference.md` stays equal to the headers, which a host test checks; a change to RFC 0011 §7 that is not in the headers is a plan step, not a fact.
- Handles are capabilities: no ambient authority, generation-bearing tokens, attenuation only downward on `HANDLE_DUPLICATE`, transfer over channels by move with the `TRANSFER` right, and closing never terminates an object's activity except a channel endpoint's. One wait (`OBJECT_WAIT`) serves every waitable object with absolute monotonic deadlines; an activation interrupts a wait or sleep with `INTERRUPTED` and is delivered through the fault callback with the interrupted context (RFC 0011 §7.4–§7.5).
- Only the register block of a thread context and the calling convention differ between ISAs; everything else in ABI-1 is identical, and layer 2 is recompiled, not rewritten. A new platform adds `Kernel.Arch.<isa>` and `Kernel.Platform.<board>` and nothing in `src/Kernel`. Devices stay unknown to the kernel: the platform enumerates regions and lines, the kernel publishes descriptors and mints capabilities on request (RFC 0011 §7.7).
- The system layer's substrate is taken from pinned open code, never written: musl, LLVM libunwind, libc++abi and libc++, `ld.so`, patched only through `UpstreamPatches`. WitOS adds no symbols to the libc namespace; everything WitOS-specific is `libwitos` and `OutWit.OS.*`. The substrate is never an application API: applications see .NET and WitOS capability APIs (RFC 0011 §9).
- The runtime is the Unix form, `TargetOS=witos`. Its patch set lives in `patches/runtime/`, starts empty at step R1, is measured against the FreeBSD/Haiku budget at every R step, and follows the order of preference of RFC 0015 §4: an existing configure check, then an existing runtime knob, then a `TARGET_WITOS` branch beside the other platforms' branches, never a change to CoreLib semantics, the GC, the JIT or the hosts' logic. Platform identity is `OSPlatformName` (`WITOS`) and the RID graph (`witos-x64`, `witos-arm64`); no `IsWitOS()` public API. Never emulate `/proc`, cgroups, `fork` or Win32; an unsupported API fails explicitly.
- ADRs and implementation documents are English in `@Docs/Implementation/`; the plan is Russian; vision documents in `@Docs/` change only by a decision recorded in an ADR, and their section numbers stay stable because other documents cite them.

## Kernel and UHI rules

These describe the kernel as it is and are carried into phase K. Where RFC 0011 §8 changes a mechanism (join becomes a wait, `THREAD_COMPLETE` merges into `THREAD_EXIT`, APCs become activations, the delivered-tick clock goes), the rule holds until the K step that changes it, and that step rewrites the rule.

- Keep UEFI details in `src/Boot.Uefi/`.
- Keep x64 instructions, descriptor tables and QEMU-specific test mechanisms in `src/Kernel.Arch.X64/`, and ARM64 instructions in `src/Kernel.Arch.A64/`. QEMU virt board devices (PL011, GICv3, generic timer, Arm semihosting exit) stay in `src/Kernel.Platform.QemuVirt/`.
- The common kernel and the loader learn the architecture only from `wit_arch_identity()`. The kernel path needs `kernel-boot` and `kernel-foundation` only; an architecture links `kernel-common` (objects and user-mode policy) together with the architecture functions that policy calls, which for ARM64 is A2. Board devices needed before on-demand mapping (a memory-mapped console) come from `wit_platform_boot_devices`, never from the architecture layer. On boards whose interrupts share one vector, the board claims and completes interrupts through `wit_platform_interrupt_claim`; the architecture never programs the interrupt controller.
- ARM64 user threads run at EL0t with their frame at the top of their own kernel stack; resume an EL0 frame only from there. The raw TLS base is TPIDRRO_EL0 (read-only at EL0), compiler TLS is x18, which the kernel sets on every return to EL0, and TPIDR_EL0 is per-thread frame state. Kernel level-0 entries deny EL0 access and execution at table level; user pages are nG and always PXN. An ARM64 thread context carries X0–X30, SP, PC, PSTATE as the condition flags alone, V0–V31, FPCR and FPSR; TPIDR_EL0 stays frame state outside the context and x18 is reset to the compiler TLS on every return to EL0, so validate PSTATE and the FPCR mask probed at boot before applying a context and never let a context change either register. Keep the compiler helpers (`memcpy`, `memset`, `__chkstk`) in assembly. Every frame resume clears the exclusive monitor (`CLREX`) before `ERET`. User PE images must match `wit_arch_identity()->PeMachine`, and an exception directory is accepted only where the identity has `WIT_ARCH_PE_UNWIND`; host harnesses that link `pe.c` share `HostIdentity.c`.
- Publish every page that received code with `wit_arch_publish_code_page` before `wit_arch_publish_code`: ARM64 cleans the data cache to the point of unification, which TCG cannot check.
- Keep the common kernel independent of firmware structure definitions.
- Keep board devices in `src/Kernel.Platform.Q35/` and kernel self-tests under `WITOS_SELFTEST`: architecture-independent tests in `tests/Kernel/`, the expectations and suites of one ISA in `tests/Kernel.<isa>/`, and the fixture protocol in `tests/User/protocol.h`. Kernel sources are listed only in `build/kernel-<arch>.json` and `build/layers/*.json`; each kernel C source belongs to exactly one layer, and the release kernel links no self-test layer. Uniform PAL fixtures are described by `build/fixtures/*.json` and share `PalFixtureCompiler`; user-mode code never returns to `src/Kernel.Arch.X64/`.
- Use ordinary .NET for development tools.
- Do not add speculative public resource APIs, distributed services or GUI work to a boot milestone.
- The kernel now owns its page tables, but firmware memory remains reserved until reclamation is explicitly designed and tested.
- Treat mapping/physical-page operations as serialized bootstrap APIs. Current allocation and mapping setup runs with interrupts disabled.
- Context switching currently preserves baseline x87/SSE state; do not introduce AVX/XSAVE assumptions without extending state management and tests.
- Keep shared kernel mappings supervisor-only. Never reuse the kernel scratch branch as a user page-table branch.
- Validate user handles and complete buffer ranges before copying/output. Close handles and free only component-owned pages on teardown.
- Keep dynamic reservations separate from fixed image/stack mappings. Reservation must not consume backing RAM; failed commit must roll back additions; decommit retains the reservation and recommit zeroes pages.
- Reset must validate one entire committed dynamic range with interrupts disabled before zeroing owned backing. Preserve permissions, reservations and all commitment/accounting; never decommit/recommit to simulate reset. Reject unsupported unlock semantics before mutation.
- Keep memory-discovery snapshots consistent through IF-disabled validation and copy-out; reject the full destination before any write. Report fixed mappings and private tables as ownership costs, and retain no-access commitments in accounting.
- Track committed no-access pages as owned. Invalidate active translations before reuse, reclaim empty private page tables, and keep memory-call work bounded by prototype quotas.
- Validate user return addresses/selectors/flags and the selected thread's owning stacks before IRETQ. Timer returns must preserve condition codes; syscall flags follow the explicit ABI.
- Switch TSS.RSP0, raw FS TLS and optional compiler GS TLS with the selected user thread. Keep FSGSBASE disabled and restore zero FS/GS bases on kernel supervision and idle; the current kernel has no segment-based TLS.
- Detached creation returns no join capability. Keep its private generation-bearing identity live through user-space TLS cleanup, deny joins, and automatically reap only after entry to the exit syscall. Free user pages, never the currently executing fixed kernel stack; last-thread completion must restore kernel FS/GS/CR3.
- Reference-bearing thread creation validates the copied request and the entire optional native-ID output before allocation, then atomically publishes the independent reference and initial suspended state. Roll back the observer, private identity and every stack/TLS page on failure. Closing a reference must not terminate the thread; private detached ownership lasts through user-space cleanup and THREAD_COMPLETE. Preserve the typed DWORD native callback ABI, fixed-stack limits and explicit normal-only priority policy.
- Coordinated full-runtime components require THREAD_COMPLETE after user-space TLS/runtime notifications; raw THREAD_EXIT terminates the entire component before any peer can resume. Keep ordinary native raw-exit behavior separate. Completion is a lifecycle assertion, not a security capability or kernel implementation of ThreadStore/GC detach. Preserve kernel-owned abrupt caller/cause diagnostics and never reclaim the currently executing kernel stack.
- Publish join wait edges and wakeup results with interrupts disabled. Reject cycles before parking, preserve thread resources until exit/join/close, and roll back all partial thread creation.
- Serialize event state checks, parking and completion publication with interrupts disabled. Expire parked deadlines before later signal/close calls; completed waits must not follow a reused event handle.
- Distinguish join edges from event/sleep waits. Idle IRQs must resume their CPL0 frame without replacing saved user contexts; use the adjacent STI/HLT/CLI path with zero kernel FS base.
- Keep legacy delivered-PIT deadlines separate from the HPET monotonic domain. HPET is the explicit q35 profile: supervisor-only UC mapping, comparator IRQs disabled, no reset after publication, and serialized reads with IF clear. Neither clock is UTC; PIT still limits wake scheduling.
- Define kernel quotas only in `src/Kernel/include/witos/limits.h` and user-space native quotas only in `src/Runtime.Native/native_limits.h`; keep format constants (ABI structure arrays, layout addresses) beside their structures.
- Keep every change to a pinned upstream file in `patches/<repository>/<output>.patch` with its Source, Output, Before and After header and a purpose; apply it only through `UpstreamPatches`, which has no fuzz. Never add string replacements of upstream text to the tool; slices of unchanged bodies may stay in code.
- Calculate source pins from canonical upstream download bytes, not CRLF-converted Git worktree copies. Keep exact-byte verification; do not normalize away a hash mismatch in the audit.
- Keep process write barriers in the architecture/kernel layer. The UP implementation requires the same single-online-CPU invariant reported by discovery; refuse unsupported topology until remote-CPU fencing exists. Preserve argument validation, zero result and native error state. A data fence is not managed suspension, instruction-cache maintenance or SMP support.
- Keep CPUID/cache decoding in the architecture layer. Bound enumeration and arithmetic, return unknown for unsupported/malformed data, and distinguish reported cache capacity from host measurements or allocation limits. Cache publication is serialized on the sole online processor; broader CPU topology requires a new discovery policy.
- WaitAny must copy and validate every handle before consuming any event, retain only kernel-owned generation-bearing snapshots while parked, and publish one winner index atomically. Share ordering with single-event waiters, expire the proper deadline domain first, clear snapshots on completion, and never let close/reuse overwrite a completed wait. Keep the four-handle quota and the unsupported wait-all mode explicit; an activation ends a parked wait or sleep with `INTERRUPTED` after its callback ran, and the frozen line restarts such a wait at its absolute deadline.
- Channels: `CHANNEL_SEND` validates the request, the bytes, every handle (live, `TRANSFER`, a movable kind, named once) and the peer's queue before it moves anything, then moves the handles out of the sender's table atomically with the message; `CHANNEL_RECEIVE` validates the buffers and that the handles fit the receiver's table before it dequeues, and a refused message stays queued; closing the last handle of an endpoint drops its queue with the capabilities it carried and wakes the peer's waiters with `PEER_CLOSED`; the kernel knows no message format. Keep the four-channel, four-message, 256-byte and four-handle quotas explicit, and never count a wait for queue room as implemented.
- Memory objects: `MEMORY_OBJECT_CREATE` takes an object's pages from the component's quota eagerly and zeroed, all or none; `MEMORY_OBJECT_MAP` validates the whole request (version, size, flags, a protection among NONE, READ, READ|WRITE and READ|EXECUTE, the target `WIT_PROCESS_SELF`, the handle's `MAP` right and its `WRITE` or `EXECUTE` right for the protection, alignment, the window within the object) before it reserves anything, and a mapping is a reservation of alias entries that remembers the object and the mapping handle's rights: protect stays within those rights, commit, decommit and reset are `DENIED`, release unmaps. An object ends with its last handle or mapping, never earlier; a message holds a reference for a handle in flight. `CODE_PUBLISH` requires every page mapped READ|EXECUTE and publishes through the architecture's cache maintenance. Keep the eight-object and 64-page quotas explicit, and never map into another process before K5.2.
- Devices: the platform enumerates once at boot into `WitDeviceDescriptor` records the kernel validates and publishes unchanged in one read-only page; the common kernel never parses ACPI or a device tree and never reads a descriptor's meaning, so nothing in `src/Kernel` knows a vendor, a class or a driver. The device table is a memory object of kind `TABLE` whose `ACQUIRE` right is the authority to take devices; `DEVICE_ACQUIRE` keeps one holder per descriptor until that component's last handle, in its table or in flight, is gone, and a component's end frees what it held. `DEVICE_MEMORY` publishes a memory region as an object of kind `DEVICE` mapped through `WIT_PAGE_DEVICE` (PAT entry 3 UC on x64, device-nGnRnE on ARM64), never executable; port regions are described, never mapped. The boot contract carries the firmware tables as physical addresses, zero when absent, and the virt board boots with `acpi=off` so that the firmware publishes the device tree. Keep the 16-descriptor table explicit.
- Interrupts and DMA: a binding is one per line kernel-wide, holds the device and the event, and ends with its last handle, masking the line; the architecture masks and completes a device line before the kernel sets the bound event and dispatches like a tick, and a line nobody bound stays masked. x64 device vectors 0x21–0x2F enter through `wit_x64_device_entry` with the vector noted in `wit_x64_device_vector` on the one processor with interrupts disabled; virt claims SPIs in `wit_platform_interrupt_claim` and programs the distributor for group 1 routed anywhere. `DMA_PIN` needs the device handle with `BIND` and an anonymous object with `MAP`: the pin holds the object, the ranges are physical and merged, a window the caller's buffer cannot take pins nothing, and device regions and the table are never DMA memory. There is no `PIN` right and no IOMMU; the device holder is the trust boundary, and the kernel programs no device. Keep the eight-binding and eight-pin quotas explicit.
- The root task: the loader reads `WITROOT.BIN` into extents the boot contract names (v6, optional) and the kernel maps them beside the package; `wit_flat_validate` checks the whole flat image (magic, version, header size, count, alignment, protection, file ranges, the image window, disjointness, the entry in executable code, zero reserved words) before `wit_user_create_flat` maps a page, and a failed creation destroys the component. The startup descriptor at `WIT_USER_INFO` carries a counted handle table (log, package, device table) so K6 appends without a layout change; the package is a memory object of kind `PACKAGE` over the boot extents that the kernel never parses for the root task, and one mapping of any object covers at most 64 pages. The release kernel starts the root task after the hello marker and panics on a nonzero exit; the flat format is a boot format for the root task, not an application format, and the PE loader stays unreachable from the release kernel's component path.
- `THREAD_ACTIVATE` validates the handle's `ACTIVATE` right, the callback (executable, not writable), the registered fault callback and the per-thread quota before it marks the target. An activation is delivered only at the target's return to user mode, through the one fault callback with the interrupted context and the activation vector; a thread inside a delivery or suspended keeps its activations pending in order, `EXCEPTION_REGISTER` is `BUSY` while one is pending, and a stack with no room for the callback frame ends the component as a fault of the thread. Never run an activation's callback in CPL0 and never add a user-space dequeue.
- Memory-pressure events are kernel-controlled, wait-only manual events sharing existing quotas. Derive pressure from settled physical/quota headroom, count no-access backing and private tables, preserve explicit hysteresis, expire deadlines before notifying, and never publish transient failed-allocation pressure. Purge closed generations before reuse; kernel notification authority must not leak to user Set/Reset. Dispatch a caller made Ready by the final expiration pass.
- Keep native initializer execution in user space. Kernel image descriptors are readonly; ReadyToRun/TypeManager/GC-table initialization belongs to the actual runtime, not the kernel.
- Keep __chkstk in the x64 layer and follow its special compiler ABI: RAX supplies size and is preserved; do not allocate/move the caller stack or clobber argument/nonvolatile/SIMD registers. Probe downward one 4 KiB step at a time plus the final partial span; never skip a guard page via an endpoint-only check or wrapped size. Fixed-stack overflow remains a contained user fault, not automatic growth or managed exception handling.
- Treat the boot handoff and experimental user ABI as evolving contracts, not a frozen public SDK.

## Kernel policy that leaves at K8

The PE loader, the DLL lifecycle and static PE TLS, the file namespace over the boot package, the kernel-held environment and current directory, and the kernel's PE unwind validation are policy that RFC 0011 §8 moves to the system layer. The rules apply while the code exists; do not extend it; it is removed at plan step K8.

- Validate static PE TLS before allocation; require real directory fixups. Accept a nonempty TLS callback list only in the library TLS profile, bounded, with one DIR64 fixup per entry and every entry in executable code; the executor runs a library's callbacks before its entry point for every reason, as on Windows, and a library without an entry point gets them for the process attach alone. DLL `thread_local` support must keep the Windows trace of the MSVC CRT. Load a library with an entry point while other threads run only when each follows the notification protocol, and reserve their notification resources before the attach begins. Capture the relocated seed before publishing the component, preserve raw FS storage, and roll back/reap the extra compiler TLS page. Never treat static template copying as dynamic TLS initialization or runtime attachment.
- Validate immutable, kernel-owned PE bytes before allocation. Keep parsing in the common kernel and page-table work in the architecture layer; unsupported directories must fail explicitly.
- Publish a PE component only after all sections, fixups and thread state exist. Preserve RX/RO/RW separation, keep image gaps unmapped, and roll back the entire unpublished component on allocation failure.
- The kernel keeps a component's environment and current directory for every module (`WIT_CALL_PROCESS_STATE`); adapters never cache them, and every operation is atomic and changes no state or output on failure. Seed the environment from an image only after validating the complete readonly table and all terminated strings, before TLS constructors/workers: a variable the creator set wins, and failed seeding removes what it added. Seeding makes system calls from GS-checked runtime code, so a process entry initializes its GS cookies first. Preserve native last-error, Windows' `SetEnvironmentVariableW` semantics and equivalent direct/import bindings. UTF conversion must use the real native heap with bounded input and caller-owned cleanup; environment transport is not GCConfig or PalInit execution.
- Accepted plain unwind metadata is structural evidence only. Reject handler/chained forms and relocation into validated unwind ranges; do not claim stack unwinding or managed exception support from parsing tables.

## Frozen: the Windows-form user space

The runtime line of P6.4 — the NativeAOT adapters written against the Windows PAL, the guest C++ runtime, UCRT subset and pinned STL, the guest host build, `coreclr-guest` and its inventory, the Win32 and COM binding surface — is frozen with ADR 0024: do not extend it or start new slices on it. Its code stays in the tree as the kernel's running workload until the Unix-form runtime passes the M3 acceptance again (plan step R2); then it is removed. The rules below apply to any touch of that code until then.

- Keep the GC event pool component-private. Release its gate before parking, capture generation-bearing handles, and never dereference a reusable slot after a wait. Serialize lifecycle changes against upstream's plain IsValid read; finite waits use monotonic deadlines with upward rounding and saturation; process both deadline domains before later signal/close operations.
- Native QPC/QPF output must use kernel whole-range validation and IF-disabled copy-out; reject invalid sizes/selectors and preserve every destination byte on failure. Keep direct/import clock bindings equivalent and import slots readonly. Preserve prior native error on success and keep errno independent. All three clock APIs use the existing monotonic domain, never UTC or delivered-PIT ticks.
- Keep minipal time independent of compiler TLS, native errno and PAL initialization. Use kernel monotonic ticks/frequency, upward-rounded finite microsecond deadlines and saturation; zero delay preserves busy accounting, the sleeping branch clears it, and short-spin accumulation must not wrap. Preserve the source-built archive/guest object identity and plain-unwind compile profile. PerThreadRandom constructor evidence is native TLS initialization, not GC execution or cryptographic entropy.
- Keep minipal mutex ownership tied to kernel-provided generation-bearing thread identity, not writable TLS. Release the registry gate before parking; count signaled entrants until they acquire or re-register. Never destroy active locks or hide Crst initialization failure. Mutex lifecycle is externally serialized; contended locks share event quotas and owners must release before thread exit.
- Drive dynamic C++ TLS in user space after validating the whole readonly initializer table. Set the compiler guard before constructors, pop destructors before calls, fail fast on lost cleanup or unbounded re-registration, and use lifecycle-aware thread exit for orderly cleanup. Raw exits/faults remain abrupt; do not claim ThreadStore attachment or managed TLS from this layer.
- Keep the guest C++ runtime in `src/Runtime.Cxx/`, built from source: own `__CxxFrameHandler4`/`_CxxThrowException` checked against the vcruntime trace of `tests/User.X64/cxx_exceptions.cpp`, and microsoft/STL only from its pinned source. Never link the toolset's vcruntime or msvcp into a guest image, and treat the public `ehdata4_export.h` as format documentation, not code to copy. A consolidating guest `RtlUnwindEx` ends the abandoned search's stack lease, retires its own and that search's exceptions together, runs the callback under the machine frame of `unwind_consolidation.asm` and restores the target through `THREAD_CONTEXT_RESTORE`; never resume the dead dispatch. Runtime functions with C linkage that unwind objects (the array iterators) are `noexcept(false)`, guest GS cookies need startup initialization before C++ code runs, and `__guard_dispatch_icall_fptr` is a plain jump: do not claim CFG enforcement. A module's startup runs its `.CRT$XI*`/`.CRT$XC*` initializers once through `wit_cxx_run_initializers`, after the GS cookies and compiler TLS and before its own code. Guest character classes come only from the Latin-1 table checked against Windows; beyond it, fail fast rather than guess.
- Take microsoft/STL only as the files `src/Runtime.Cxx/stl.lock.json` pins by canonical-byte hash, compiled unchanged with the STL's own options; a change to a pinned file is an upstream patch, and `src/Runtime.Cxx/stl/internal_shared.h` stays WitOS's own. Everything that sees STL headers compiles against the pinned `stl/inc` ahead of the toolset's, so headers and separately compiled sources are one version. A behavior change must keep `StlTests` equal to msvcp140 and `Code.StlSupport` passing. A module's startup calls `wit_cxx_initialize_isa` before the vectorized algorithms run; AVX levels need OSXSAVE and XCR0, so never execute `XGETBV` without OSXSAVE. Win32 functions only the STL calls stay in `native_stl.*`, out of the NativeAOT runtime archive and its default-profile probe images. The STL's sources compile with libcpmt's options except the Windows 10 level (no run-time lookup through `winapisupp.cpp`), no GS and no ASan annotations. Guest SRW locks and condition variables park threads on pooled auto-reset events: queue before releasing the lock or gate, never hold the gate across a wait, set events only under it, return events unsignaled, and keep shared mode explicitly unsupported. Without a UTC clock, `GetSystemTimePreciseAsFileTime` ends the component; never return an invented time. The C++, UCRT and STL scenarios run in the host runtime fixture under the full runtime profile; do not grow the mapper fixture's quota for them.
- Build the guest host from the corehost sources of the runtime checkout `runtime-source` verifies, unchanged except through `UpstreamPatches`, with upstream's options against the pinned STL; WitOS's PAL objects replace only `pal.windows.cpp` and `longfile.windows.cpp`. Keep `experiments/CoreClrHost/guest-link.json` exact in both directions: remove what a slice implements, never add an expectation to hide a regression. Do not link an adapter whose state belongs to the process (the console) into a library until every module sees the same process state; the environment and current directory adapters are linked because the kernel holds that state. A C++ library links the library startup (`wit_library_cxx_entry`) and dynamic TLS in place of the process entry, the process's compiler TLS and its TLS directory; its startup seeds its GS cookies, publishes the process context from `WIT_USER_INFO`, sets the ISA level and stream options and runs its initializers, and its atexit is module-local, run after DllMain at the detach. A library starts no thread until a thread lifecycle spans modules; refuse explicitly, never borrow the process entry's. The dispatcher of every module accepts a loaded library's code only in its executable, non-writable sections under a module reader; only registered dynamic code takes the funclet gate, and a catch in another module than the raising one stays unsupported until one process dispatcher exists. Module paths come from kernel records (`LIBRARY.MODULE_PATH`): a main image has a path only when the kernel created it from a package file, and an address outside every module image is `ERROR_MOD_NOT_FOUND`; never invent a path. `coreclr-memory` builds both libraries from that checkout, loads them in the guest from its boot package's .NET root layout and fails on any unresolved symbol. The host is compiled for Windows and joins paths with `\`; WitOS's PAL hands it every path as the Windows API would, `\`-separated with `\` as the root, and WitOS's paths accept both separators back, so never patch upstream's path joining. .NET is installed in `/dotnet`, never at the namespace root, whose trailing separator upstream drops. `coreclr-guest` links the reference build's own CoreCLR objects, with the reference build's linker, as a WitOS C++ library; keep `experiments/CoreClr/guest-link.json` exact in both directions and never add a symbol to it to hide a regression. Its link forces past the first pass's unresolved externals only to reach code generation, where calls to the compiler's intrinsic functions first become references; it deletes the forced image and never publishes or loads it. Like the host, it links without CFG or EH continuation metadata. CoreCLR stays a Windows target with COM interop compiled in, under the next rule. WitOS's PAL follows the Unix PAL's policies over the immutable package where Windows reads Program Files or the registry: nothing is writable (no breadcrumbs, no bundle extraction), no UTC time is invented, the runtime identifier platform is `witos`; Win32 functions only the host calls stay in `native_host.*`, out of the NativeAOT archive.
- CoreCLR's Win32, COM and OLE imports are the binding surface of unchanged upstream binaries, not a second Windows. Implement a function only on a path .NET needs, with the contract .NET relies on, checked against Windows; give statically imported functions outside the supported scenarios a documented Win32 failure their callers handle, or fail fast; leave lazily bound P/Invokes and delay-loaded DLLs absent until a scenario reaches them. Prefer upstream configuration that keeps .NET off Windows services, and never emulate the registry, GUI, services, ETW or NLS. COM, OLE and WinRT functions that are data or memory (interface identifiers, `BSTR`/`VARIANT`/`SAFEARRAY` helpers) are real, and so is the multithreaded apartment, per-thread bookkeeping that CoreCLR's Main and finalizer threads require; single-threaded apartments, activation, type libraries and WinRT fail explicitly. Never return a pretended success.
- Keep the host's UCRT subset in `src/Runtime.Crt/`, WitOS's own: never use the Windows SDK's UCRT sources or link UCRT into a guest image. A behavior change must keep `CrtTests` equal to UCRT, the scenario trace and the in-process differential; record any accepted difference in the plan document. Platform calls stay in `platform_windows.cpp`/`platform_witos.cpp`, the hosted subset build imports only kernel32, and a module's startup calls `wit_crt_initialize_stdio_options` before formatted output. Report actual yield switching and never hide invalid void frees.

Keep direct/import bindings equivalent and readonly, preserve prior error on success/normal timeout, and preserve the original failure through rollback. ## Validation

For native, boot, image or runner changes, run:

```powershell
dotnet build WitOS.slnx --configuration Release
dotnet run --project tools/WitOS.Dev --configuration Release -- test
```

Absolute deadlines may expire between a user clock read and kernel entry. Test deadline completion separately from mandatory idle-path coverage; do not require every successful sleep to park. Keep preemption and resource-accounting assertions independent and diagnostic.

Expected boot markers live in `tests/Expectations/*.json`; add a suite's new marker there, never as a list in `BootValidation`, and keep every expected marker emitted by a guest source. Contained user faults are accounted by the guest: a test accepts each expected fault through `wit_test_faulted`, and the host requires the closing `[TEST-SUMMARY] faults=N checked=N` to match the fault lines; never add a hand-counted fault total.

Guest boots run in QEMU virtual time (`-icount shift=2,sleep=off` in `BootScenarioRunner`): a 10 ms tick is 2.5 million instructions on every host. Keep tick budgets and timer expectations in guest instructions, never tuned to host speed; wall-clock boot limits only stop a hung QEMU.

Use `setup` once for the pinned local QEMU package. The test tool must distinguish successful boot, panic, unexpected exit and timeout. Never infer a passing boot from an exit code or log line alone.

For runtime experiment or source-pin changes of the frozen line, run `runtime-audit`, `runtime-probe` and `runtime-target` through the same tool. Their results are hosted Windows evidence, including native C-host bootstrap, never proof that .NET runs in the guest. Preserve the source/package pins and explicit profile limitations unless the task deliberately updates them. `runtime-port` builds and boots the native GC memory adapter in QEMU; it is guest adapter evidence, not managed runtime execution. For full native source-build or overlay changes, also run `runtime-source`: it builds the upstream native libraries, executes the Windows reference and checks unresolved WitOS port requirements. The Unix-form build and its guest acceptance get their own commands in phase R (RFC 0015 §9); until then no command proves .NET in the guest.

Keep generated images, binaries, firmware, downloads, logs and credentials out of Git. They belong in ignored `artifacts/` or `.tools/`. Record actual results and limitations in documentation; do not mark a future milestone complete based on M0 boot.
