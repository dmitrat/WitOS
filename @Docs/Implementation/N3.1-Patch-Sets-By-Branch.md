# N3.1 — A pin and a patch set per release branch

N3 installs .NET 8 LTS beside .NET 10 (RFC 0015 §7). The RFC builds each version from its own release branch, with its
own patch set under `patches/runtime/<branch>/`. N3.1 lays out the existing set that way. Nothing it builds changes.

## The layout

| | Before | Now |
| --- | --- | --- |
| Patch set of `release/10.0` | `patches/runtime/` | `patches/runtime/release-10.0/` |
| Its pin | `build/runtime/runtime.lock.json` | `build/runtime/release-10.0.lock.json`, which also names its `branch` |

A branch's name gives its directory and its pin, with `/` as `-`, as a patch's name gives its path with `/` as `.`.
`RuntimeWitos` knows the runtime's branch (`BRANCH`), its pin (`LOCK`) and its set (`PATCH_SET`), and `UpstreamPatches`
reads the set as the repository `runtime/release-10.0`. A host test checks that the three agree and that the pinned
version is of the branch. The patch tests treat a patch's directory under `patches/` as its repository, so a second
branch's set is checked the same way.

`runtime-rebase --tag <tag>` carries the set to any tag and reports what it took. `--apply` moves the pin only to a
tag of the pinned branch: another branch has a pin and a set of its own, and a backport is a person's work, which the
carry measures.

## The backport, measured

The carry of the `release/10.0` set to `v8.0.31` (`1219a42122cf`), the latest servicing tag of `release/8.0` at this
step, is what N3.2 starts from:

| Outcome | Files |
| --- | --- |
| Carried without a conflict (9) | `eng/build.sh`; the PAL suite's `pal_sxs` test; ILC's command line and target details; `vm/gcenv.ee.cpp`; the RID graph's `runtime.json`; CoreLib's `Environment.WitOS.cs` (a file WitOS adds) and `OperatingSystem.cs`; the native libraries' libunwind and Globalization CMake files |
| Conflicts (14) | the cross toolchain file, `configurecompiler.cmake`, `configureplatform.cmake` and `tryrun.cmake`; CoreCLR's `CMakeLists.txt`, the DAC's, `gc/unix/gcenv.unix.cpp`, `pal/src/init/pal.cpp` and `pal/src/thread/process.cpp`; NativeAOT's Unix targets; CoreLib's shared project items; the cryptography project; the static apphost's and the native libraries' `CMakeLists.txt` |
| Absent from 8.0 (2) | `eng/RuntimeIdentifier.props` and the portable RID graph, which 8.0 does not have |

The set adds 180 lines and removes 22 at the 10.0 pin. The carried patches add 42 and remove 6.

N3 needs less of the runtime on 8.0 than on 10.0. The shared framework needs CoreCLR, the JIT, CoreLib, the libraries
and their native part, and `hostpolicy`. One `hostfxr`, 10.0's, serves both frameworks. So NativeAOT's targets and the
static apphost need no backport, and two of the conflicts drop out. The rest are build files that 8.0 shapes
differently, and the PAL's and GC's `TARGET_WITOS` branches.

## Limits kept explicit

- The 8.0 set does not exist yet; N3.2 makes it, and N3.3 installs both versions side by side.
- Historical documents name the paths of their time.
