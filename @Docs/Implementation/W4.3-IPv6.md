# W4.3 — IPv6

Plan step W4.3 (phase W, M7; the inventory `W0-Network-Inventory.md` listed IPv6 under W4), 2026-10-22. IPv6 joins the
network service's managed stack and the libc, so that a program speaks it as on Linux: `AF_INET6` sockets that serve
both families unless `IPV6_V6ONLY` is set, with IPv4 peers in the mapped form `::ffff:a.b.c.d`; the loopback `::1`; a
link-local address from the adapter's hardware address and a global one from the router's advertisement, with neighbour
discovery for the next hops; `sockaddr_in6` names, `getaddrinfo`'s `AAAA` records, the IPv6 nameserver in
`/etc/resolv.conf`, and the addresses and routes over netlink. .NET's `Socket.OSSupportsIPv6` is true, a `Socket` made
without a family is dual-mode, and Kestrel's `ListenAnyIP` binds `[::]` as it does on Linux.

## 1. One address space in the socket layer

Every socket address of the stack (`OutWit.OS.Networking`) and of the service is an `Ipv6Address`, an IPv4 address in its
mapped form, so that one code path serves both families and the IP layer tells them apart at its boundary:

| Where | What |
| --- | --- |
| `UdpSocket`, `TcpSocket`, `Datagram` | `LocalAddress`, `RemoteAddress` and a datagram's `Source` are `Ipv6Address`; a socket has a `Family` (`AF_INET` or `AF_INET6`) and `V6Only` |
| `NetworkStack.Bind`, `Connect`, `SendTo` | take an `Ipv6Address` (the `Ipv4Address` forms map and stay for the tests); `OpenUdp` and `OpenTcp` take `ipv6` |
| `Takes(address, family, v6only)` | whether a socket takes an address's family: an `AF_INET` socket the mapped form alone, an `AF_INET6` one IPv6 and, unless `IPV6_V6ONLY`, IPv4 too |
| `Overlaps` | Linux's `bind` rule: equal addresses overlap; the unspecified address overlaps an address of a family the socket takes; two unspecified addresses overlap when they share a family — so `[::]` of a dual-stack socket holds the port's IPv4 side (`EADDRINUSE` for `0.0.0.0` of the same port), while `[::]` of an `IPV6_V6ONLY` socket leaves it free |
| `Bindable` | the unspecified address, a loopback, the interface's IPv4 address or one of its IPv6 addresses, of a family the socket takes; `EADDRNOTAVAIL` otherwise |
| `SourceFor(destination)` | the loopback's for a loopback, the interface's address of the destination's family (the link-local one for a link-local or multicast destination, the global one beyond); Any, which is `ENETUNREACH`, when the stack has none |
| `SendIp` | a mapped destination goes over IPv4 (`SendIpv4`: ARP, the gateway), any other over IPv6 (`SendIpv6`, §2) |
| `UdpHeader`, `TcpHeader` | read and write with `Ipv6Address` endpoints; `InternetChecksum.PseudoHeader(Ipv6Address, Ipv6Address, …)` sums the IPv4 pseudo header when the destination is mapped (a DHCP request's unspecified source maps to `::`, so the destination decides) and RFC 8200's otherwise; a UDP checksum of zero is valid over IPv4 and refused over IPv6 (RFC 8200 section 8.1) |
| `ReceiveTcp(source, destination, segment)` | one for both versions: the IPv4 path maps its header's addresses; a listener takes a segment whose destination's family it takes, the most specific binding first, `SO_REUSEPORT`'s groups as before; a connection a listener accepts has the listener's family, its IPv4 peer mapped, and its MSS follows the peer's IP header (1460 over IPv4, 1440 over IPv6 on a link of 1500) |
| `DeliverUdp` | the same for datagrams; a datagram nobody takes is answered with ICMP's or ICMPv6's port unreachable, and a report of either version reaches the connected socket as `ECONNREFUSED` |

## 2. The IPv6 host (`NetworkStack.Ipv6.cs`)

RFC 8200's host on the stack's one interface, with RFC 4861's neighbour discovery and RFC 4862's stateless
autoconfiguration, as slirp (QEMU's user networking) serves them: a router at `fe80::2` that advertises the prefix
`fec0::/64` with the on-link and autonomous flags, itself as the default router, and `fec0::3` as the DNS server
(RFC 8106), and that answers neighbour solicitations for its addresses.

- **Addresses.** `StartIpv6`, which the service calls with DHCP when it has an adapter, makes the link-local address
  from the hardware address (the modified EUI-64, `Ipv6Address.LinkLocal`: `52:54:00:12:34:56` gives
  `fe80::5054:ff:fe12:3456`) and sends one neighbour solicitation for it from the unspecified address to its
  solicited-node group; after a second without an advertisement, or a solicitation of the same address from another
  node, the address is assigned (one transmission, `RetransTimer`, as RFC 4862's defaults). A duplicate stays unassigned
  (`Statistics.DuplicateAddresses`), and the stack sends nothing over IPv6 from the link. Once the link-local address is
  assigned, up to three router solicitations go to `ff02::2` four seconds apart until an advertisement comes; an
  advertisement's autonomous prefix of 64 bits gives the global address (the prefix and the same interface identifier),
  which goes through the same detection; its on-link prefix is the route; its router lifetime keeps the router as the
  default router until it runs out; its recursive DNS servers are the IPv6 nameservers. Every change announces
  `ConfigurationChanged`, as a lease does (W4.2), so the netlink sockets hear of it.
- **Neighbours.** A next hop is resolved as ARP resolves one: a solicitation to the solicited-node group with the
  source link-layer option, three attempts a second apart, the packets that wait bounded to four, an entry kept for five
  minutes; a solicitation's or an advertisement's link-layer option is learned at once, so a reply needs no round trip.
  A solicitation for an address of ours is answered with a solicited, overriding advertisement to the asker (to all
  nodes when it asked from the unspecified address). Discovery messages are taken only with a hop limit of 255.
- **Routing.** `::1` and the interface's own addresses go to the loopback queue, which `Advance` drains as it did for
  IPv4 (the first byte's version tells the two apart); a multicast destination goes to its `33:33:…` hardware address
  (RFC 2464), and `Receive` takes frames at such addresses beside the adapter's own and the broadcast; a link-local
  destination or one in the advertised prefix is on the link; anything else goes through the default router, or is
  unreachable without one. Extension headers are not read: a packet with one is dropped. Fragmentation is not done:
  the largest datagram is the link's MTU less the headers.
- **ICMPv6.** The echo request is answered; port unreachable is sent for a datagram nobody takes and taken for a
  connected socket's datagram; the discovery messages above. Nothing else is read.
- **Tests.** `SimulatedNetwork` gets slirp's IPv6 router (`Ipv6Router`: the advertisement for a solicitation, the
  advertisement of its addresses); `Ipv6StackTests` covers autoconfiguration through it (the detection frame from `::`
  at the solicited-node group's hardware address, the link-local address after a second, the solicitation and the
  advertisement, the global address a second later, three announcements, no solicitation after an advertisement), a
  duplicate address left unassigned, UDP between two stacks over link-local addresses (one solicitation and its
  advertisement, the reply without one, the port unreachable and `ECONNREFUSED`, an echo request answered), the loopback
  and the dual-stack rules; `TcpTests` adds TCP over `::1`, between two stacks over link-local addresses, and a
  dual-stack listener taking an IPv4 and an IPv6 client while an `IPV6_V6ONLY` one refuses IPv4; `SocketMessagesTests`
  the `AF_INET6` address and the IPv6 configuration.

## 3. The protocol and the service

| `witos/socket.h` | What |
| --- | --- |
| `WitSocketAddress` | `AF_INET6` (10) with all sixteen bytes; `AF_INET` as before (additive: version 1 stays) |
| `OPEN` | `Argument[0]` `AF_INET6` opens a dual-stack socket |
| `BIND` | takes the socket's family alone (`EAFNOSUPPORT` otherwise, as `inet_bind` and `inet6_bind`) |
| `CONNECT_TO`, `SEND` | an `AF_INET` address on a dual-stack datagram socket is taken, as Linux's `connect` and `sendto` map it; on an `IPV6_V6ONLY` socket the stack answers `ENETUNREACH` (Linux: `EAFNOSUPPORT` for a `sockaddr_in`, `ENETUNREACH` for the mapped form); a stream socket takes its family alone |
| `ACCEPT`, `RECEIVE`, `NAME` | an address in the socket's family: an `AF_INET6` socket's IPv4 peer in the mapped form, as Linux names it |
| `GET_OPTION`/`SET_OPTION` `IPPROTO_IPV6` (41), `IPV6_V6ONLY` (26) | of an `AF_INET6` socket; `ENOPROTOOPT` of an `AF_INET` one, `EINVAL` once bound (Linux refuses the change then); off by default, as Linux's `bindv6only` |
| `CONFIGURATION6` (16) | `WitSocketConfiguration6` in the window: the link-local and global addresses, the on-link prefix's length, the default router, the DNS servers the router advertised, and `Flags` saying which addresses are assigned |

`StackHost` starts the IPv6 host with DHCP and logs the addresses as they are assigned (`[NETWORK] pci/…: IPv6 link-local
…, global … of fec0::/64, router fe80::2, DNS fec0::3`). The probes of the device manager print a `SocketAddress`'s
`AddressText`, the dotted quad of an `AF_INET` address, so the lines `runtime-devices` requires are unchanged.

## 4. The libc

| Linux | WitOS (`src/Substrate/libc`) |
| --- | --- |
| `socket(AF_INET6, …)` | opens through the service (`socket.c`); a raw socket is `ESOCKTNOSUPPORT` whatever the family |
| `sockaddr_in6` in `bind`, `connect`, `sendto`, `sendmsg`; out of `accept`, `recvfrom`, `recvmsg`, `getsockname`, `getpeername` | `address_in` and `address_out` by the family; a link-local address comes back with `sin6_scope_id` 2, `eth0`'s index; an address of a family the socket's calls do not take is `EAFNOSUPPORT` |
| `SO_DOMAIN` | the socket's family, kept in its record |
| `IPV6_V6ONLY` | served by the service (`served`); other `IPPROTO_IPV6` options are `ENOPROTOOPT` |
| `/etc/resolv.conf` | the lease's nameservers, then the router's IPv6 nameservers once the interface has a global address to reach them from (`__wit_resolv_refresh`, `CONFIGURATION6`); musl's resolver then asks both over one `AF_INET6` socket, the IPv4 servers mapped |
| `/etc/hosts` | `::1 localhost` is in the install since R5, so `getaddrinfo("localhost")` with `AF_INET6` gives `::1` |
| netlink `RTM_GETADDR` | `::1/128` of `lo` (scope host), the link-local address of `eth0` (`/64`, scope link) and the global one (the prefix's length, scope universe), each `IFA_ADDRESS` alone, after the IPv4 addresses, as the kernel orders a dump of both families |
| netlink `RTM_GETROUTE` | `fe80::/64` (`RTPROT_KERNEL`), the advertised prefix and the default route through the router (`RTPROT_RA`), with `RTA_OIF` 2 |
| `RTMGRP_IPV6_IFADDR`, `RTMGRP_IPV6_ROUTE` | an address that came or went (`RTM_NEWADDR`, `RTM_DELADDR`), the routes again, when the service announces a change; `System.Native`'s change listener binds `RTMGRP_IPV6_ROUTE` beside the IPv4 groups |

The libc's tables grow by the socket records' family and `/etc/resolv.conf`'s room (400 bytes: four lines of each
family); the netlink queues stay 4 KiB, where a dump of both families' addresses and routes takes some 1200 bytes.

## 5. .NET

`Socket.OSSupportsIPv6` opens an `AF_INET6` datagram socket and is true; `new Socket(SocketType, ProtocolType)` then
makes a dual-mode `AF_INET6` socket and maps the IPv4 endpoints it is given, as on Linux; a `TcpListener` on
`IPAddress.IPv6Any` with `DualMode` takes `TcpClient`s of both families and names an IPv4 one `::ffff:127.0.0.1`
(`IsIPv4MappedToIPv6`). Kestrel's `ListenAnyIP` binds `[::]` with dual mode and reports
`http://[::]:8080` — the `runtime-aspnetcore` scenario's line changed from `0.0.0.0` — and the runner's IPv4 connections
through the port forward reach it mapped. `NetworkInterface.GetAllNetworkInterfaces` lists `eth0`'s link-local and
global addresses and `lo`'s `::1` beside the IPv4 ones. The suite's `Network.IPv6` check passes and leaves
`expectations.json`; `Network.IPv6Loopback` (TCP and UDP over `::1`) and `Network.DualMode` (an IPv4 client of a
dual-mode listener, named mapped) join the Network area.

## 7. Differences from Linux

- **Beyond the guest network.** slirp forwards IPv6 TCP and UDP to the host's `::1` and its IPv6 nameserver, which a
  host may lack (CI's runners have neither), so the guest's IPv6 reaches the loopback, the link and slirp's addresses;
  the scenarios require nothing of the host's IPv6. An IPv4 install of QEMU's user networking is the same for a Linux
  guest.
- **Not served.** Multicast group membership (`IPV6_JOIN_GROUP`, `IP_ADD_MEMBERSHIP`), `IPV6_RECVPKTINFO` and every
  other ancillary datum, `IPV6_UNICAST_HOPS` and the other `IPPROTO_IPV6` options (`ENOPROTOOPT`), raw sockets
  (`ESOCKTNOSUPPORT`), extension headers (dropped), fragmentation and path MTU discovery (the link's MTU bounds a
  datagram), temporary addresses (RFC 4941), DHCPv6 (the router's advertisement gives the prefix and the DNS servers), and
  more than one router. `.NET`'s `Socket` asks for none of them on its way to a connection.
- **Error codes.** A mapped address on an `IPV6_V6ONLY` socket's `connect` or `sendto` is `ENETUNREACH` (Linux gives
  `EAFNOSUPPORT` to a `sockaddr_in` there and `ENETUNREACH` to the mapped form).
- **Scope.** A link-local address comes back with `sin6_scope_id` 2, the adapter's index, as Linux's does; a
  `sin6_scope_id` given to `bind` or `connect` is ignored, since there is one link.
