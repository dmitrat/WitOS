# P1.5 native thread references

User ABI v20 adds checked duplicate/query operations for component-private thread references. They are distinct from generation-bearing join identities and are stored in kernel-owned records. GetCurrentThread/GetCurrentProcess supply the standard pseudo values; DuplicateHandle resolves the current-thread pseudo value to the actual current kernel thread and returns a newly granted reference capability, never a cast thread ID.

The duplicate operation supports same-process, non-inheritable current-thread/reference duplication and same/reduced supported rights. Kernel-side checks reject unsupported rights, escalation, stale/wrong-kind handles and bad destination ranges before granting an output. A failed copy rolls back the unpublished grant. References share the existing handle quota; no extra backing pages are allocated.

On thread exit, terminal identity and exit code are published before join/detached reaping. References retain no freed stack/TLS pointers. A terminal snapshot reports zero stack bounds and cannot bind to a reused slot. Closing one reference does not join, stop, reap or invalidate another reference. Process finish clears all reference records and handles. Native error is preserved on successful direct/import operations; GetThreadPriority validates a reference/current kernel snapshot before reporting the scheduler's actual fixed normal priority.

The query interface validates the entire output before any write and copies a versioned 48-byte snapshot with IF clear. Its identity is observational data, not a new authority token. Rights reserved for waits/contexts do not implement those operations: native alertable waits and PAL context/suspension remain open work. The existing Thread::Construct absent-context policy has not been replaced by a fake handle.

Tests execute in a separate compact native PE so the existing image/unwind limits are not raised. Coverage includes distinct duplicate tokens, same target identity, reduced rights and denied escalation, stale close/reuse, quota recovery after a rejected readonly output, terminal query after join/reap, repeated thread slot reuse, no compiler TLS and unchanged physical ownership after teardown. The final pass also tests partial-page rejection and valid cross-page query copy-out.

Validation passed: Release build, all 20 boot scenarios, audit/hosted probe, target/source/readiness and all four runtime-config profiles (226 user groups and 54 expected contained faults each). The compact thread fixture is 11776 bytes with 39 plain unwind records. Full source archive: 105 members; configuration archive: 29 objects. Minimal/broad strict boundaries: 47/53 unresolved symbols. All changes remain local; this is not managed ThreadStore attachment or a runnable guest runtime.
