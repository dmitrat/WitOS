# Compatibility differences

This list covers how a .NET program on WitOS behaves differently from the same program on Linux. RFC 0015 §8
requires every absent or unsupported area to fail explicitly and to appear here. Each row names the behaviour, how a
program observes it, and the step that verified it. Rows change only together with a check that verifies the new
behaviour. The public compatibility matrix rendered from the suite and this list is
[Compatibility-Matrix.md](Compatibility-Matrix.md) (N4.5).

| Area | On WitOS | How a program sees it | Verified by |
| --- | --- | --- | --- |
| Files | The boot package is the root of the file system, read-only. The namespace service mounts the disks' volumes below it: ext4 at `/data`, FAT at `/fat` and the boot disk's FAT at `/boot`, read-only; and `/tmp`, a volume in the service's memory of 64 MiB whatever disks there are, whose files last the boot (N4.1). There are no symbolic links in the package, and the libc follows none on a volume. `/etc/mtab`, which the libc serves from the namespace's mount points, lists the package at `/` and each mounted volume, so `DriveInfo.GetDrives()` and `Environment.GetLogicalDrives()` report them as Linux reports its mounts (C1.2; `DriveType` is `Unknown`, sizes are not reported). `HOME` is `/data/home`, a directory the namespace service makes on the data volume. | Reads, `File.Exists`, directory enumeration, `FileStream` seeking and relative paths behave as on Linux. On `/data`, `/fat` and `/tmp`, files and directories are created, written, copied, cut, moved, replaced and deleted as on Linux. A write, a create or a `mkdir` in the package or on `/boot` throws `IOException` or `UnauthorizedAccessException` (`EROFS`, or `EEXIST` for an existing name). On `/fat`, a file open for writing cannot be opened again, nor an open file deleted (`EBUSY`, `IOException`). `Path.GetTempPath()` is `/tmp/` unless `TMPDIR` says otherwise. | R4.1, `libc_hello.c`, D5.1, D5.2, N4.1, `devices_init.c`, `Files.cs`, the N1 suite |
| Memory-mapped files | A private mapping of a volume's file is a copy taken when it is made, and an executable one a copy that executes. A shared mapping shows the namespace service's pages of the file, the same in every process; the service writes them back at `msync` and when the last handle that mapped the file writable closes. A shared mapping past the page that holds the file's end is `ENXIO`. | `MemoryMappedFile` views of every access work as on Linux; a `ReadWrite` view's writes reach the file at `Flush` or when it is disposed. CoreCLR loads assemblies, and the dynamic linker libraries, from a volume. | D5.2, D5.3, R4.2, `devices_init.c`, `Files.cs`, the runtime-devices scenario |
| File modes and times | A volume's files show the modes and times their volume records; `chmod`, `fchmod`, `fchmodat`, `utimensat` and `futimens` set what the volume's format keeps (N4.1): ext4 and `/tmp` keep the bits and the times to the nanosecond; FAT keeps read-only alone, so a mode without a write bit sets the attribute (0444, 0555), one with the owner's clears it (0644, 0755), and any other mode, and any time set by hand, is `EPERM`, as Linux's vfat answers for a mode its masks cannot represent. The package is `EROFS`. There is no `umask`, no `chown`. | `File.SetUnixFileMode`, `File.GetUnixFileMode`, `File.SetAttributes(ReadOnly)`, `File.SetLastWriteTimeUtc` and `File.Copy`, which copies the source's mode and times, work on `/data` and `/tmp` as on Linux; on `/fat`, a mode other than read-only or not and a time set by hand throw `UnauthorizedAccessException`, while `File.Copy` completes, since System.Native tolerates `EPERM` for a copy's metadata, as on a FAT volume under Linux. | N4.1, `devices_init.c`, the N1 suite, N2.2 (Roslyn's analyzer loading tests) |
| File locks | `flock` locks are those of the process's own open file descriptions. | `FileShare` behaves as on Linux within the process. No other process sees the locks. | R4.1, `libc_hello.c` |
| Startup profiles | CoreCLR gathers no MultiCoreJit profile: the install's environment sets `DOTNET_MultiCoreJitNoProfileGather=1`, since on two or more processors the runtime writes a profile a record at a time, 4 bytes a `write`, and every write of a volume's file is a durable transaction of the namespace service's journal with its flushes (pwsh's 60 KiB profile, 15,000 writes, took a session's exit minutes). A profile that exists is still played. | `ProfileOptimization.StartProfile` records nothing; a program's startup is not sped up by a profile of its earlier runs. | S8.1; the suite's `FileIO.SmallWritesUnderContention` check guards the libc's part of the cost |
| Shared memory | `shm_open` and `memfd_create` files live within the process, on memory objects. `/dev/shm` is the one directory in which a process creates files, and each process has its own. | CoreCLR's double mapping works. Files of `/dev/shm` are read, written, appended to and mapped as on Linux's tmpfs; a private mapping is a copy taken when it is made. `/dev/shm` holds no subdirectories (`mkdir` is `ENOSYS`), and its files are 0600 until `chmod` changes them (N4.1). Another process does not see them. | R3.2b, R7.2a, N4.1, `libc_hello.c`, the PAL suite |
| Time | UTC from the board's real-time clock. The .NET install carries tzdata's TZif files under `/usr/share/zoneinfo` with `zone.tab` (N4.1). There is no `/etc/localtime`, so the local zone is UTC unless `TZ` names one. | `DateTime.UtcNow` is right; `TimeZoneInfo.FindSystemTimeZoneById`, conversions and `GetSystemTimeZones` work with IANA ids as on Linux; `TimeZoneInfo.Local` is UTC. | R4.1, N4.1, the N1 suite |
| Globalization | ICU 78.3 with its full release data, in `/usr/lib` of the .NET install. | Cultures, culture-aware formatting, comparison and casing, normalization and IDN work as on Linux. A package without the install (NativeAOT programs, `corerun`) runs in invariant mode by its own configuration. | R4.3, N1 |
| Cryptography | OpenSSL 3.5, the long-term support series, built by the system layer from its pinned release for each ISA by OpenSSL's own Configure and make with the pinned clang: shared libraries, the C implementations (`no-asm`), no tests, programs or loadable modules, no secure memory and no AF_ALG engine (they include the Linux kernel's headers), `/usr` and `/etc/ssl` as its paths; `libcrypto.so.3` and `libssl.so.3` in `/usr/lib` of the install, which the portable shim `System.Security.Cryptography.Native.OpenSsl` opens at run time, as on Linux. The root store is Mozilla's CA bundle, one PEM file at `/etc/ssl/certs/ca-certificates.crt`; there is no `/etc/ssl/openssl.cnf`, so OpenSSL runs with its defaults, and the user stores live under `$HOME/.dotnet/corefx/cryptography/x509stores` on the data volume as on Linux. | The algorithms, X.509 and chains work as on Linux (the suite's Cryptography area: the hashes and HMAC, PBKDF2, AES in CBC and GCM, RSA with PSS and OAEP, ECDSA, ECDH, certificates made and signed, PEM and PKCS#12, a chain to a custom root, the machine's root store). What differs from a distribution: the root store is the pinned bundle, not a package the user updates, and OpenSSL's algorithms run in C without the assembly of a distribution's build. .NET 8 beside .NET 10 (N3, the `release/8.0` set) still takes the browser's managed set (the hashes, HMAC and the KDFs; `PlatformNotSupportedException` for the rest) until the same change follows for it. | W3.1, the N1 suite, `runtime-system-native` |
| Console | A process started after the terminal service (N4.3: every process `/bin/init` descends from, when the machine has a virtio console) has the terminal as its standard streams: one terminal of 80 by 24 with Linux's standard line discipline in the service, shared by every such process; a process without one (the device services, a machine without a console) writes to the kernel log and reads an input that ends at once. | `Console.WriteLine`, `ReadLine`, `ReadKey`, `KeyAvailable`, `WindowWidth`, `WindowHeight`, `CancelKeyPress` and `PosixSignalRegistration` for `SIGINT` work as on Linux's console; `Console.IsInputRedirected` is false. `TreatControlCAsInput` and the terminal's attributes act on the one terminal for every process, as on Linux. No `TERM`: no colors or cursor movement through terminfo until a terminal says what it is. Without a terminal, `Console.ReadLine` returns null and `IsInputRedirected` is true (R4.1). | R4.1, N4.3, `terminal_init.c`, the N1 suite |
| Processes | `Process.Start` starts a program of the package or of a mounted volume in a new process through the process manager (N4.2): the libc's `posix_spawn` with the arguments, the environment, the working directory and the redirected standard streams, which are pipes shared between the two processes; `epoll` serves pipe ends (what System.IO.Pipes' asynchronous reads and writes go through on Unix) and sockets (W2.1b). There is no `fork`, no `exec`, one user and no process group; a child is signalled with `SIGKILL` alone, and there is no `/proc`. | `Process.Start` with `UseShellExecute = false`, `StandardInput`, `StandardOutput`, `StandardError`, `WaitForExit`, `ExitCode` (128 + 9 after `Kill`) and `Kill` work as on Linux, through the unix flavor of `System.Diagnostics.Process` built for witos. `UserName`/`Password` on start throw `Win32Exception` (`ENOTSUP`). `Process.GetProcesses`, `GetProcessesByName`, `GetProcessById` of another process, another process's `ProcessName`, `StartTime`, processor times and `Modules`, `Kill(entireProcessTree: true)`, `ProcessorAffinity` and the working set throw `PlatformNotSupportedException`, since there is no `/proc` and the kernel reports none of it; the current process's name, module and processor times work. `Environment.ProcessId` works. | N4.2, `process_init.c`, the N1 suite |
| Shell | There is no `/bin/sh`: WitOS's shell is PowerShell, a base application of the data volume's layer (ADR 0027). The default environment sets `SHELL` to its launcher `/data/apps/bin/pwsh` and puts `/data/apps/bin` on `PATH`. | An application that runs commands through `$SHELL` gets PowerShell, whose `-c` runs a command; one that starts `/bin/sh -c` gets `Win32Exception` (`ENOENT`) from `Process.Start`. A base application's command (`pwsh`) is found on `PATH` as on Linux. | C4.1, `runtime-powershell` (`shell=/data/apps/bin/pwsh`, `sh=False`) |
| File change notifications | The namespace service sends no change notifications. | `FileSystemWatcher` throws `PlatformNotSupportedException`. | N1 |
| Named synchronization objects | .NET keeps named mutexes and semaphores as files under the fixed `/tmp/.dotnet`, which is on the `/tmp` volume since N4.1, locked with `flock` and mapped shared; `flock` is the process's own. | A named `Mutex` is created, taken and released within a process as on Linux. Two processes that open the same name do not exclude each other, since the lock is the process's. | N1, N4.1 |
| Signals | `SIGINT` and `SIGQUIT` come from the terminal's interrupt and quit characters (N4.3) and reach every process that holds the terminal, since there are no process groups; `SIGHUP` when the terminal goes; `SIGWINCH` never, since the console's size never changes; job-control signals (`SIGTSTP`, `SIGTTIN`, `SIGTTOU`) never. A signal is raised on a thread of the libc's own, as Linux raises it on a thread that does not block it. | `PosixSignalRegistration.Create(SIGINT)` and `Console.CancelKeyPress` run their handlers on Ctrl-C; a `SIGINT` nobody cancels ends the process. `Console.TreatControlCAsInput` makes Ctrl-C a key. | R4.1, N4.3, the N1 suite |
| Platform identity | `OSPlatform.Create("WITOS")`, `PlatformID.Unix`, and the RIDs `witos-x64` and `witos-arm64`. | `RuntimeInformation.IsOSPlatform(OSPlatform.Create("WITOS"))` is true, and `OperatingSystem.IsWindows`, `IsLinux`, `IsMacOS` and `IsFreeBSD` are all false: an application that infers Windows from "not Linux and not macOS" misbehaves. Under `corerun`, the RID arrives as a property. | R2.3a, R3.3, R4.1, N1 |
| Processors | Threads run on every processor the board gives, each within its affinity (P1); there is one memory node. | `Environment.ProcessorCount` counts the processors of the process's affinity and `Thread.GetCurrentProcessorId` names the processor a thread runs on (the libc's `getcpu`, node 0), as on Linux; the server collector keeps a heap per processor and the thread pool's minimum is the processor count. `Process.ProcessorAffinity` throws `PlatformNotSupportedException` (Processes). | P2, `runtime-processors`, `process_init.c` |
| Thread priority | Every thread runs at one priority, which is `SCHED_OTHER` at 0. | Setting `Thread.Priority` succeeds and has no effect on scheduling. A native call that asks for a real-time policy gets `ENOSYS`. | R7.1, `process_init.c` |
| Executable memory | Plain memory never executes. Code comes from the package or from the double mapping of a shared memory file. | The JIT works. A native library that maps anonymous memory executable (`mmap` with `PROT_EXEC`, `VirtualAlloc` with `PAGE_EXECUTE*` under the PAL) gets an error. | R3.2b, R7.1 |
| Threads and resources | A process may run 32 threads and hold 2048 handles, 64 events, 1024 memory objects, 1024 descriptors and 1024 shared memory files (`shm_open`'s, `memfd_create`'s and every volume file mapped shared, N4.1), and own 1 GiB of memory; the kernel holds 4096 memory objects in all, and a file of a volume mapped shared takes one for every 256 KiB. The root task tells the GC the smaller of that and the memory free when the system started (`DOTNET_GCTotalPhysicalMemory`), as a container's limit would, and the GC keeps its heap to 75% of it; `GC.RefreshMemoryLimit` does nothing, as the GC does under that knob on Linux. Thread stacks are 1.5 MiB and the main thread's 2 MiB (Linux gives 8 MiB), committed when the thread starts. A process may run an hour of processor time; past it, it ends as if by `SIGXCPU`. | Beyond a quota, thread creation fails with `OutOfMemoryException` and `open` with `EMFILE`. An allocation past the GC's heap throws `OutOfMemoryException`. A stack overflow on a thread ends the thread without the "Stack overflow" report. | R6, N2.2 |
| Hosts | `dotnet`, `hostfxr` and `hostpolicy` are upstream's, unpatched, in the shared-framework layout under `/dotnet`. The framework's deps.json is written by WitOS's tool, since upstream's CoreCLR runtime pack needs crossgen. | `dotnet App.dll` works as on Linux. The SDK's commands are not installed. | R5 |
| Code | Every method is JIT-compiled. No ReadyToRun code exists for `witos`. | Startup is slower than on Linux, and the behaviour is the same. | R3.2 |
| Networking | The network service's managed TCP/IP stack (W1.2) over the virtio adapter, IPv4 alone: TCP, UDP and the loopback, an address from DHCP, names through musl's resolver with `/etc/hosts` and the servers the service names in `/etc/resolv.conf` (W2.1a). The libc refuses `AF_INET6`, `AF_UNIX` and `socketpair` until W4; TLS is OpenSSL's (W3.1), through `System.Net.Security`'s unix flavour. | `Socket`, `TcpListener`, `TcpClient`, `NetworkStream`, `UdpClient` and `Dns` work over IPv4 as on Linux, synchronously and asynchronously (the socket engine's `epoll` serves sockets since W2.1b): an echo, a receive's timeout, options, a refused connection, the end of a stream, `localhost`. `Socket.OSSupportsIPv6` is false, so .NET speaks IPv4. `HttpClient` works over HTTP/1.1 through `SocketsHttpHandler` (W2.2): a GET, a POST answered chunked, one connection kept for several requests; `SslStream` and HTTPS work over OpenSSL (W3.1: TLS 1.3 on the loopback, a certificate trusted by its thumbprint), and HTTP/3 stays off. | W2.1a, W2.1b, W2.2, W3.1, `sockets_check.c`, the N1 suite |
| Diagnostics | No `createdump`, no EventPipe transport and no diagnostic IPC. | The runtime's diagnostic server fails to open its socket and runs without it. | R3.2a (trace) |
