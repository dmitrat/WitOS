# K8.4a — the kernel policy leaves

RFC 0011 §8 lists what the kernel kept from the Windows-form line only until the system layer could do it: the PE
loader, libraries, files, the package's parser, the environment and current directory, thread names, stack leases,
software exception scopes and fatal reports. [K8.2](K8.2-Frozen-Line-Removal.md) removed the user space that needed
them. K8.4a removes the kernel side, with its calls, its fixtures and its tests. The kernel no longer knows an image
format, a file, a path, a library or a name.

K8.4 has four slices. This is the first. The version 1 thread form and raw and compiler TLS go in K8.4b. The startup
block and the first thread's layout go in K8.4c. The limits and ABI-1 1.0 come in K8.4d.

## What left the kernel

**Calls.** Numbers 207–222 are retired:

| Number | Call | Where its job went |
| --- | --- | --- |
| 207 | `MONOTONIC_QUERY` | `CLOCK_READ` and `CLOCK_FREQUENCY` |
| 208 | `CPU_CACHE_SIZE` | the record form of `PROCESSOR_QUERY` |
| 209 | `THREAD_CONTEXT_RESTORE` | a delivery to the own thread (K8.1) |
| 210–212 | `STACK_LEASE_ACQUIRE`, `STACK_LEASE_QUERY`, `STACK_LEASE_RELEASE` | left with the Windows-form line |
| 213 | `EXCEPTION_BEGIN` | left with the Windows-form line |
| 214–215 | `FATAL_ARM`, `FATAL_REPORT` | left with the Windows-form line |
| 216–217 | `THREAD_NAME_SET`, `THREAD_NAME_QUERY` | the libc's thread record |
| 218 | `CODE_MEMORY` | memory objects and `CODE_PUBLISH` |
| 219–222 | `FILE`, `STORAGE_QUERY`, `LIBRARY`, `PROCESS_STATE` | the system layer |

The rest of the ABI changes with them:

- **Statuses.** `DEADLOCK` (11) and `INITIALIZATION_FAILED` (17) are retired.
- **Thread flag.** `LIBRARY_NOTIFICATIONS` (2) of `WitThreadCreateRequest` is retired.
- **Handle kinds.** 6–9 (file, library, module reader, library lifecycle) are gone.
- **Startup block.** `WitUserStartup.ImageInfo` is now `Reserved` and is always zero.
- **Version.** The ABI is v70.

**Kernel sources.** Sixteen files are deleted:

- `pe.c`, `pe_imports.c`, `pe_exports.c`, `user_image.c`;
- the four `user_library*.c`;
- `files.c`, `user_files.c`, `user_process_state.c`;
- `user_thread_name.c`, `user_stack_lease.c`, `user_code.c`;
- `package.c`, `storage.c`.

Fifteen headers are deleted with them, `user_abi_frozen.h` among them.

The files that stay lose their policy parts:

- **The process record** loses the file table, the libraries and their TLS, lifecycle and readers. It also loses the
  image name, the PE TLS template, the stack leases, the fatal report, the environment and the current directory.
- **The thread record** loses its library notifications, library TLS, name and nested exception records.
- **The address space** loses code views and library ranges. An alias entry now only ever maps a memory object's page.
  `MEMORY_COMMIT` no longer mirrors pages into views, and decommit, reset, protect and release no longer guard against
  them.
- **Fault delivery** no longer nests. A delivery already requires that the thread has no record, so `EXCEPTION_BEGIN`
  was the only source of nesting. `EXCEPTION_CONTINUE` accepts only the current token as `RetireThroughToken`, and the
  libc always passed it.
- **Component creation** has two paths, both without PE:
  - `wit_user_create`, a fixture's code window;
  - `wit_user_create_flat`, the root task.

  The PE TLS template is gone. A version 1 thread therefore gets no compiler TLS page: its `CompilerTls` is zero until
  K8.4b removes the field.
- **The package** is no longer parsed at boot, and the "Invalid readonly boot package" panic is gone. The loader still
  reads the package into the boot extents. The root task receives it as a memory object of kind `PACKAGE`, as before,
  and the libc validates its table when it first mounts it (`src/Substrate/libc/files.c`).
- **`witos/package.h`** keeps only the format's limits. The loader reads at most `WIT_PACKAGE_MAX_BYTES`.

## What left the tests

- **`src/Runtime.Native`**, the user side of the policy. Its only consumers were the PE fixtures and the host harnesses.
- **The PE fixtures.** That is all of `tests/User.X64` (`image.asm`, `bootstrap.c`, `compiler_tls*.c` and the library
  fixtures) and `tests/User.A64/image.asm`.
- **The self-tests** `user_image_tests.c`, `user_bootstrap_tests.c` and `user_tls_tests.c`, with their markers:
  - x64 loses 31: 16 `User.Image*`, 11 `User.Bootstrap*` and 4 `User.CompilerTls*`;
  - ARM64 loses the 16 `User.Image*`.
- **The PE fault tables** of `tests/Kernel.<isa>/user_arch_tests.c`.
- **Nine host tests of the policy.** These are the Windows references for PE TLS, TLS callbacks, thread notifications
  and DLL `thread_local`, the PE import corpus, and the `Runtime.Native` file, directory, path and library harnesses.
  The PE coverage helper and the `PeImportsAsan` category go with them.
- **The package host test stays.** The kernel's parser is now the test's reference reader
  (`tests/WitOS.Dev.Tests/Native/PackageReader.c`). It checks `AssemblyPackage`'s output and is not kernel code.

## The tool

No kernel image needs MSVC any more, release or self-test, on either ISA:

- `UserImage` builds only the clang fixtures (K8.3) and the root task.
- The PE fixture builders are gone: `UserPeImage`, `UserBootstrapImage`, `UserTlsImage` and the `Native*LibraryImage`
  builders.
- So is the generation of `user_abi.inc` and `user_abi_a64.h`.
- `KernelImageBuilder` no longer looks for MSVC.
- `KernelArchitecture` keeps only the `lld-link` machine name.

The host tests that compile native harnesses with `cl.exe` (the package and virtual-gap tests) still run on Windows
alone.

Two host tests guard the result:

- **Retired numbers.** `KernelAbi.RetiredCalls` reads the "N was retired" and "N-M were retired" comments of
  `user_abi.h`. The ABI reference test then requires three things:
  - no call carries a retired number;
  - the reference names every retired number with the call it was;
  - the next free number follows both the calls and the retired numbers.
- **Kernel layout.** The kernel layering test lists the policy files that remain.

## Tests

- `format-check` and the host tests pass.
- `test`: all 27 x64 scenarios pass, with the self-test kernel built without MSVC.
- `test --arch arm64`: all 21 foundation scenarios pass.

The layer-2 scenarios and the .NET acceptance are unchanged. They never used a retired call (K8.1).

## Limits kept explicit

- **Version 1 threads.** A fixture's first thread, and the threads the kernel's own thread self-test creates, are still
  version 1, with the kernel's stack and raw TLS windows. Raw TLS, compiler TLS, the x18 reset and `NativeId` leave
  with that form in K8.4b.
- **The startup block.** `WitUserStartup` stays at `WIT_USER_INFO` until K8.4c gives the first thread its new form.
- **`INT 0x80`.** The x64 transport has no user left. It leaves when K8.4b–c rewrite the transport rules.
- **The Linux host.** It can now build the self-test kernels, but CI runs them there only from step T2.2.
