# S1.3 — musl's libc-test on WitOS

Plan step S1.3 is the acceptance of the C library (plan: "libc-test из musl и дифференциальные тесты против musl на
Linux, где это возможно"): musl's own test suite, pinned by commit, runs unchanged over the substrate of S1.1 and
S1.2 as one static program, the root task of the `libc-test` scenario, on x64 and ARM64. 76 functional and
regression tests pass on both; the rest wait for threads, signals, processes, writable files, resource limits or a
newer musl, each with its reason below. The differential run against musl on Linux waits for the Linux build host
(T2).

## What changed

**The pin.** `src/Substrate/libc-test.lock.json` names the repository (`https://repo.or.cz/libc-test`) and the commit
(`7b95dfa5f5d5ca4d949221e0228ccc290bacc14e`). `setup` checks it out once with Git under `.tools/libc-test/<commit>`,
fetching the commit alone, and every build verifies the remote, the revision and the clean tree as the runtime
checkout is verified; the server answers unreliably, so the fetch retries over HTTPS and then over the Git
protocol before it gives up. Nothing of libc-test is patched.

**The selection and the program.** `tests/User/libc-test.json` lists the tests and the support sources
(`src/common`: `print.c`, `rand.c`, `utf8.c`, `path.c`, `memfill.c`, `vmfill.c`, `setrlim.c`). `LibcTestSuite`
(tools/WitOS.Dev/Substrate) compiles each listed test unchanged with libc-test's own options
(`-std=c99 -D_POSIX_C_SOURCE=200809L -D_FILE_OFFSET_BITS=64 -fno-builtin -frounding-math`) and its `main` renamed
(`-Dmain=libc_test_<name>`), generates the table `libc_test_table.h`, compiles `tests/User/libc_test_driver.c` and
links them all with crt1, `libc.a` and the builtins (`MuslLibc.CompileAsync`, `LinkAsync`). The driver runs the tests in
order; libc-test's runner starts every test in a fresh process, so the driver resets `t_status` and `errno` before
each, prints `[LIBC-TEST] <name>: ok` or `FAILED (result, status)` — a test's own messages reach the log through
`t_printf` on standard output — and ends with `[LIBC-TEST] musl 1.2.5 on <isa>: all N tests passed`, the line the
scenario requires, exiting with the number of failures. There is no per-test process, stack limit or timeout yet: a
test that faults ends the program.

**The root task's profile.** A libc program with 76 tests is 650 KiB and needs more pages than the default profile's
128: the root task now gets the full profile's capacities, as a created process does (K5.2c) — 2048 owned pages, 32
reservations, 32 handles, 16 events, the runtime tick budget and the fixed window to `WIT_RUNTIME_USER_LIMIT`
(4 MiB), which `wit_flat_validate` now accepts for the flat image. `/dev/zero` joins `/dev/null` in the file layer
(reads give zeros).

## What waits, and why

- Threads (S2 brought `pthread_cond`, `pthread_tsd`, `tls_local_exec`, `pthread_once-deadlock`, `pthread_rwlock-ebusy`,
  `pthread_condattr_setclock`); still waiting: `sem_init`, `tls_init`, `pthread_cond-smasher` and `pthread_create-oom`
  (more threads at once than the kernel's quota of four, or a resource limit; K5.3 brought back all but
  `pthread_create-oom`), `pthread_mutex` (leaves a deadlocked
  thread on a returned stack frame by design, which needs a process per test), `pthread-robust-detach`,
  `pthread_robust` and `pthread_mutex_pi` (robust and priority-inheriting futexes), `pthread_atfork-errno-clobber`,
  `pthread_exit-dtor` and `raise-race` (fork or signals), `tls_get_new-dtv` (dlopen), `sem_open` and `sem_close-unmap`
  (named semaphores need files).
- Signals: S3 brought `setjmp` (the signal mask of `sigsetjmp`), `sigaltstack`, `sigprocmask-internal` and
  `sigreturn`; `raise-race` (a thousand signals and `fork`) waits for processes.
- Processes, pipes and sockets (S6, later): `daemon-failure`, `fcntl`, `fflush-exit`, `fgetwc-buffering`, `ipc_*`,
  `popen`, `spawn`, `socket`, `vfork`, `execle-env`, `syscall-sign-extend` needed `/dev/zero` and has it.
- Writable or temporary files (the namespace service, D5): `fdopen`, `flockfile-list`, `fscanf`,
  `ftello-unflushed-append`, `fwscanf`, `lseek-large`, `mntent`, `rewind-clear-error`, `stat`, `ungetc`, `utime`,
  `wordexp`, `rlimit-open-files`, `statvfs`.
- Dynamic loading (S5): `dlopen`, `tls_align*`, `tls_init_dlopen`, `tls_get_new-dtv_dso`.
- Resource limits and memory exhaustion (`setrlimit`, Linux overcommit): `malloc-oom`, `setenv-oom`,
  `sscanf_long` (an 8 MiB block beyond the prototype quota of 2048 owned pages; the kernel's per-page accounting is
  the bound and its rework is a K-phase step).
- Users and groups: `getpwnam_r-crash`, `getpwnam_r-errno`.
- A newer musl than 1.2.5: `strptime` (libc-test's head tests `%F`, `%s` and `%z`, which 1.2.5's `strptime` lacks);
  `strtold` on binary128 (ARM64): 1.2.5's hexadecimal conversion keeps `LDBL_MANT_DIG/4+1` digits, one too few when
  the leading digit is small, so the tail's half-unit sticky lands on the rounding bit and two of the test's cases
  come out one unit off; musl's master keeps `(LDBL_MANT_DIG+3)/4+1`. A probe of the same steps on WitOS showed every
  binary128 operation of compiler-rt's builtins rounding correctly; the fix arrives with the next musl release, not
  with a WitOS patch of library code. On x64 (the x87 format) the test passes and is still excluded for parity.
- The math suite (`src/math`, 206 programs with their tables) and the API checks (`src/api`) are not selected yet.

## Tests

The `libc-test` scenario of both suites requires `[LIBC-TEST] musl 1.2.5 on x86_64: all ` (and `aarch64`); the `libc-test`
command builds and boots it on x64. The root task's wider window is covered by the kernel self-test's
`Root.ImageValidation` (a segment at `WIT_RUNTIME_USER_LIMIT` refused).

## Limits kept explicit

- One process for every test: no stack limit, no timeout, no isolation; a crashing test ends the run, which is why
  the selection is explicit and the excluded tests are named with their reasons.
- The root task's capacities are the full profile's prototype quotas (2048 pages, 32 reservations); larger programs
  wait for the kernel's accounting rework.
- No differential run against Linux until the Linux build host exists (T2).
