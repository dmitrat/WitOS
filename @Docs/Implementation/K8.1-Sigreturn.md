# K8.1 — sigreturn without THREAD_CONTEXT_RESTORE

Plan step K8 removes from the kernel the policy that layer 2 has taken over
([RFC 0011 v3 §8](../RFC-0011-Kernel-Architecture-and-ABI.md)). Of the 13 calls that leave ABI-1, layer 2 still used
one: `THREAD_CONTEXT_RESTORE`, through which the libc's `__wit_sigreturn` resumed the context a signal interrupted.
K8.1 takes that use away. The libc now uses no call that K8 removes.

## What changed

**Why user code cannot do it alone.** RFC 0011 §8 lets `THREAD_CONTEXT_RESTORE` leave and resumes fault frames through
`EXCEPTION_CONTINUE`. A signal handler's return must resume every register exactly, because the signal may have
interrupted any instruction. On ARM64 that cannot be done in user code: the final branch needs a register that holds
the target address, and `x16`/`x17` may be live at the interrupted instruction. libunwind's jump to a context may
clobber them, since it resumes at a call boundary; a signal return may not.

**The composition.** `__wit_sigreturn` now resumes through a delivery of its own (`signal.c`):

1. It carries the handler's changes into the saved context and sets the mask, as before. It also prepares the frame's
   `Transfer` with that context, flagged `EXCEPTION_ACTIVE` as a delivery continues it.
2. It holds the thread's signals and leaves the frame in the thread's record (`WitThreadLocal.Resuming`).
3. It raises an activation of its own thread with the marker `__wit_sigreturn_activation`. When the activation queue
   is full it yields and tries again, since each return to user mode drains one activation.
4. The kernel delivers the activation at that call's return. The fault callback recognizes the marker before any mask
   or hold applies (`resume_frame`) and takes the frame from the record.
5. `resume_frame` ends the hold and re-arms the signals that arrived meanwhile. As activations they queue behind this
   delivery and follow the resumed context.
6. It continues the frame's `Transfer` with `EXCEPTION_CONTINUE`, which validates and applies the whole context as
   the old call did.

Holding the thread's signals from step 2 to step 5 matters. Without it, an activation from another thread could run a
handler in between, and that handler's own `sigreturn` would take the frame's place in the record. `resume_frame` uses
no stack beyond the callback's frame: the transfer lives in the signal frame.

**Room on the alternate stack.** The kernel enters the fault callback only with `WIT_EXCEPTION_STACK_MINIMUM` (8 KiB)
free below the stack it was raised on. An alternate stack of `SIGSTKSZ` that already holds the signal frame lacks it:
libc-test's `sigaltstack` failed there with the activation's fault. So a handler that ran on the alternate stack
returns from the interrupted stack, below its red zone (128 bytes on x64, none on ARM64): `__wit_sigreturn_switch`
moves the stack pointer there and raises the marker.

## Tests

- **The libc.** `libc` passes with 137 checks on x64 and 135 on ARM64. Its signal checks cover dispositions, masks,
  the alternate stack, nested handlers, a fault repaired by its handler, a fault left with `siglongjmp`, and signals
  between threads.
- **libc-test** passes 386 runs on x64 and 388 on ARM64, `regression/sigaltstack`, `sigreturn` and
  `sigprocmask-internal` among them.
- **The .NET acceptance.** `runtime-witos` on both ISAs passes the acceptance. NativeAOT suspends threads for the
  GC with activations whose handlers return through `sigreturn`.

## Limits kept explicit

- **The interrupted stack needs room.** A handler that ran on the alternate stack returns only when the interrupted
  stack has `WIT_EXCEPTION_STACK_MINIMUM` left below its stack pointer. A handler of a stack overflow that returns
  without that room ends the process as a fault of the activation; one that leaves with `siglongjmp` is unaffected.
- **A return costs a second entry.** A handler's return now enters the kernel twice, for the activation and for the
  continue, where it entered once.
- **The call itself stays until K8.4.** `THREAD_CONTEXT_RESTORE` remains in the kernel for the frozen line until
  K8.4 removes it.
