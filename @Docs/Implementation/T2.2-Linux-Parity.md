# T2.2 — the Linux host's parity

[T2.1a](T2.1a-Linux-Host.md) made Linux a development host for everything except the self-test kernels. Those
embedded the frozen line's fixtures, which MSVC built. [T2.1b](T2.1b-Layer2-On-Release-Kernel.md) ran the layer-2
scenarios there on the release kernel.

Since then, K8.3 rewrote the mechanism fixtures in C for clang and K8.4a removed the PE fixtures with the kernel policy,
so no kernel image needs MSVC. T2.2 finishes the job:

- the Linux CI host runs the same suites as Windows;
- the two native host harnesses that still required MSVC now build on Linux.

## CI

- **A new job, `linux-selftest`, runs `test` and `test --arch arm64`.** These are both whole suites: the self-test
  kernels with their fixtures, the boot, fault and timeout scenarios, and the layer-2 scenarios on the release kernel.
  The job has its own runner, so the suites and the runtime build run side by side rather than one after the other in a
  single 90-minute job. It shares the cache key of the pinned LLVM and QEMU with `linux-host`.
- **`linux-host` loses its two loops of layer-2 scenarios**, since `test` runs them. It keeps:
  - the host tests;
  - the QMP cleanup;
  - the release kernels;
  - the runtime;
  - the source style check.
- **The Windows jobs are unchanged.** Both hosts now run the same suites.

## Native host harnesses

Two host tests compiled their C harness with `cl.exe` and ran on Windows alone:

- **the boot package**: the reference reader `PackageReader.c`, with the UEFI loader's `storage.c` against
  fault-injected firmware callbacks;
- **the kernel's virtual-gap search.**

`NativeHarness` (`tests/WitOS.Dev.Tests/Support`) now builds a harness for the host it runs on:

- on Windows, MSVC with the Windows SDK, with the options as before;
- on Linux, the pinned clang against the system C library (`-std=c17 -O2 -Wall -Wextra -Werror`).

The harnesses keep their host's memory calls behind `#if defined(_WIN32)`:

- the guarded window of the package cases is `VirtualAlloc`/`VirtualProtect` on Windows and `mmap`/`mprotect` on
  Linux;
- the firmware's pages at fixed addresses below 4 GiB use `MAP_FIXED_NOREPLACE` on Linux;
- standard file calls replace `fopen_s` and `sprintf_s`.

`TestPlatforms.MSVC` is gone. Only the tests of a Windows API itself (job objects, command-line quoting) stay
Windows-only, and `doctor` on Linux reports that MSVC is not needed.

## Evidence

- **Windows:** the host tests pass (57), including both harnesses with MSVC.
- **Linux, in the container of `build/linux/Dockerfile`:** the host tests pass (55), including both harnesses with the
  pinned clang. The two skipped tests are those of the Windows API; the QMP cleanup has its own CI step.
- **The suites on Linux** are judged by the `linux-selftest` job of this step's pull request: every scenario of `test`
  on both ISAs.
