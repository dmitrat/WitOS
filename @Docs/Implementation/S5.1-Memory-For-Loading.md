# S5.1 — memory for loading (ABI v67)

Plan step S5.1 opens the ELF loader of S5 ([RFC 0011 v3 §7.2, §9.1](../RFC-0011-Kernel-Architecture-and-ABI.md)) with
the memory a loader needs: reservations at a fixed address, the release of a part of a reservation, code mapped from
the boot package without a copy, and Linux's mapping semantics in the libc over them. musl's `ld.so` maps a library as
a span and then lays every segment over it with `MAP_FIXED`; .NET's GC decommits with an anonymous `MAP_FIXED` mapping
over its own reservation and releases parts of what it reserved. Neither worked before: a reservation could not be
placed, nor shrunk, nor split, and no file's code could execute.

## What changed

**The kernel (ABI v67).** `MEMORY_RESERVE(size, alignment, address)` takes a nonzero, page-aligned address aligned as
asked and reserves exactly there inside one dynamic arena: `BUSY` when the range overlaps a reservation or a mapping,
`DENIED` over a library range, `BAD_ADDRESS` outside the arenas — what RFC 0011 §7.2 already promised.
`MEMORY_RELEASE(base, size)` keeps its meaning for size 0, the whole reservation at its exact base; a nonzero size
releases `[base, base + size)` of one plain reservation: its committed pages are freed, and the reservation shrinks at
an end or splits in two around a middle part, which needs a free reservation slot (`NO_MEMORY` otherwise); a range
past the reservation's end is `INVALID_ARGUMENT`, a range a code view reads `BUSY`, and a mapping of a memory object is
released whole (`DENIED` for a part). Both arguments were ignored until now, and ABI-1 asks for zero in every unused
argument: the entry fixtures of both ISAs, which left them unset, now zero them.

**The boot package.** The root task's package handle gains `EXECUTE`: code loads from the boot package, which the
release kernel and the loader already treat as read-only, never as writable. A file of at least a page starts at a page
boundary in the package (the writer pads with zeros, and the kernel's boot validator `wit_package_open` requires the
padding and the boundary), so that a loader maps a file's pages straight from the package object.

**The libc (`src/Substrate/libc/memory.c`).** The library keeps a table of its mappings, each one kernel reservation:
a plain reservation — anonymous memory, committed under the requested protection or, for `PROT_NONE`, reserved without
pages; or a file's bytes copied into committed pages — or a mapping of the package object, which shows a file's pages
without a copy and is the only way a file's code executes: an executable private mapping of a page-aligned package
file is made of package mappings of at most `WIT_MEMORY_OBJECT_PAGES` pages at consecutive addresses, each published
with `CODE_PUBLISH`, and the pages past the file's last are plain reserved memory. `MAP_FIXED` replaces whatever of
the library's mappings lies in its range, as Linux does: a plain part is released from its reservation (the kernel
splits it), and a package mapping only partly covered is mapped again around the range; `MAP_FIXED_NOREPLACE` refuses
an occupied range with `EEXIST`; `munmap` of any range does the same over every mapping it touches and leaves memory
outside them alone; `mprotect` commits the missing pages of a plain range and then sets the protection, and changes a
package mapping within the handle's rights (an executable mapping of a file is never writable, `EACCES`). `madvise`'s
`MADV_DONTNEED` over pages never committed succeeds. A shared writable mapping of the package is `EACCES`; files other
than the package's and `/dev/zero` (anonymous memory) are `ENODEV`.

## Tests

- `User.MemoryFixedAndPartial` (both ISAs): a fixed reservation and its refusals (overlap on either side, an unaligned
  address, an alignment the address does not meet, the fixed window), a middle release that splits a committed
  reservation and frees its pages, commits refused in the hole, the ends released, the remains released by their full
  size and whole, the range reserved again, and the split refused without a free slot while a shrink needs none.
- The root task fixture maps a package page `READ|EXECUTE`, publishes it and releases a mapping by its own size.
- `libc_hello.c` (117 checks on x64, 115 on ARM64, whose integer division does not trap): `MAP_FIXED` over the own mapping replaces its range alone,
  `MAP_FIXED_NOREPLACE` refuses an occupied range, a middle part unmapped and taken again at its address, an unmap
  across several mappings, a package file mapped as a writable private copy, and `test/code.bin` mapped executable
  from the package at the page of the ISA (`mov eax, 42; ret` on x64, `mov w0, #42; ret` on ARM64) and called, its
  protection changed within its rights and never to writable, a shared writable package mapping refused.
- The package writer's host test requires a page-sized file at a page boundary.

## Limits kept explicit

- A read-only private file mapping is a copy, like a writable one; only executable mappings show the package's pages
  without a copy. Shared mappings of files and anonymous shared memory between processes are not here.
- Every mapping and every split costs a kernel reservation: the full profile's 32 bound a process's mappings, and a
  middle unmap of the last free slot fails with `ENOMEM`.
- A package mapping partly covered by `MAP_FIXED` or `munmap` is released and mapped again around the range; between
  the two another thread could take those addresses, which then fails the call with `ENOMEM`.
