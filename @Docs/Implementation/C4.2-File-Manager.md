# C4.2 — the file manager

Plan step C4.2 (phase C, ADR 0027 decisions 1–7, RFC 0020 §28): the early console's file manager, Arlecchino.Commander,
becomes a base application of the data volume's layer, built from its source, and runs on the display's console, driven
through the keyboard. Made on 2026-10-18.

## 1. The application

`build/apps/Arlecchino.Commander.json` pins Arlecchino.Commander (MIT, Midnight Commander's layout on the Arlecchino
framework) with the command `arlc` of `arlc.dll`:

- **A source, not a release.** The project's releases are NativeAOT and self-contained binaries of Linux, macOS and
  Windows alone, which cannot run on WitOS; its code reads input and writes output through `System.Console` alone and
  needs no native part, so a build by the stock SDK without a RID can (ADR 0027 decision 2).
- **The commit.** The release v2026.9.2 names a commit of its Arlecchino submodule that the library's repository no longer
  holds (its history was rewritten), so it cannot be checked out. The pin is the commit of 2026-09-19 after it,
  `697750104b83f7b7db5fd6e0850bccf58f70c36e`, whose submodule is the library's release v2026.9.3, the version ADR 0027
  decision 7 names; the application's version in the layer is that date, `2026.9.19`.
- **The properties.** The project publishes NativeAOT by default; the entry's `properties` turn it off
  (`PublishAot=false`), so the publish is a portable framework-dependent application. The catalog checks each property as
  one `Name=Value` without a `;`.

## 2. The source kind

`AppSourceBuild` lays an entry of the `source` kind (ADR 0027 decision 2), the first since C4.1 checked it:

- The repository is fetched once at the commit, shallow, with its submodules, under
  `.tools/apps-src/<ApplicationId>-<commit12>`; a checkout at another commit is refused, never changed.
- The project is published by the stock SDK — `dotnet publish -c Release -p:UseAppHost=false -p:NuGetAudit=false` and
  the entry's properties — into `.tools/apps/<ApplicationId>-<version>`, once for the commit and the properties (a stamp
  beside the output holds both). No RID and no apphost: the layer writes its own launcher (C4.1). The checkout lies under
  the repository's `.tools`, so the SDK is the one WitOS's `global.json` pins; the application's own
  `Directory.Build.props` applies unchanged.
- Every command's assembly must be in the publish; the files go into the layer as the publish wrote them, beside the
  manifest.

`AppsLayer.ApplicationFilesAsync` takes the `source` kind for any entry; the `tool` kind waits for C2.5.

## 3. The scenario

`runtime-commander` (`RuntimeCommander`, after `runtime-powershell` in `runtime-witos`, or alone) boots the display, the
keyboard and the virtio console as the display's mirror (C2.2), with the device services, the .NET install and a data
volume of 1 GiB made by `AppsDisk.VolumeFilesAsync` — the layer with PowerShell and the file manager, the home
directory — and a note `/data/zz-note.txt`, the last entry of `/data`'s listing. `/bin/init` (`apps_init.c`) runs
`cd /data` and the launcher `/data/apps/bin/arlc`. The runner performs the actions through QMP (C2.3):

| After | Action | What it does |
| --- | --- | --- |
| the terminal probe's prompt | `hello` and Enter | the device manager's probe (C2.2) |
| `Quit`, the hint bar's word for F10 | End | the cursor to the note |
| at once | Enter | the viewer opens the note (Arlecchino's F3 is Edit, which runs the configured editor) |
| the note's text | the screendump | once the guest wrote nothing for a second |
| at once | F3 | the viewer's own key back to the panels (no lone Escape to tell from a sequence) |
| `zz-note.txt · 68 B`, the panel's line of the entry under the cursor | F5 | the copy dialog, its field the other panel's folder `/data` with the caret at its end |
| at once | `/tmp` and Enter | the note is copied into `/data/tmp` |
| `Copied 1 file` | F10 | the commander quits |

F5 waits for the panel's line because the panels read the folder again after the viewer: a key that arrives before
finds no entry under the cursor, and the commander says `Nothing selected`.

The scenario requires the services' lines, `Quit`, the note's text, `Copied 1 file`, the launcher's exit with 0
(`[APPS-INIT] /data/apps/bin/arlc  exited with 0`, `[APPS-INIT] 1 commands, 0 failed`), the services' stop and the root
task's report. Then the host requires the screendump equal, pixel for pixel, to the frame it renders from the mirror's
transcript with the same emulator, renderer and font (C2.3), the viewer's text on that screen, and the copy on the data
volume: the ext4 partition copied out of the disk, unmounted by the guest (no `needs_recovery`), clean by `e2fsck -fn`,
and `/tmp/zz-note.txt` read by debugfs equal to the note (`RuntimeDataDisk.ReadExt4Async`).

## 4. The commander on WitOS

Read in its code and seen on the screen:

- **The screen.** 100 by 37 cells on 800 by 600, above its minimum of 100 by 20 (the serial console's 80 by 24 is too
  small). It draws in 24-bit colour, which the emulator reduces to its palette (C2.6), enters the alternate screen, hides
  the cursor, and pops the kitty keyboard mode on exit (`CSI < u`, swallowed).
- **What it falls back from.** No pseudo-terminal (commands under the panels run through pipes), no inotify (folders are
  polled), no trash (deletion is for good), as its code does for an operating system it does not know; commands go
  through `SHELL`, which is PowerShell (C4.1).
- **Invariant globalization** comes from its own `Directory.Build.props`.
- **No editor** is configured: F3 says so and offers `!` to set one.

## 5. The second workload and CSharpFar

Measured on x64 in the Linux host's image, each built from its source by the stock SDK without a RID and run
unchanged by `dotnet` from the boot package on the same screen, keyboard and mirror; neither is a gate (ADR 0027
decision 7).

- **Terminal.Gui's UICatalog** (MIT, release v2.5.0, commit `ece73d25c37df9bb17cb0c0d2171abd4d98eeaff`):
  - Started plainly, it ends at once with `TypeInitializationException`: `UICatalog.Runner` holds two
    `FileSystemWatcher`s in static fields for its configuration watcher, and System.IO.FileSystem.Watcher throws
    `PlatformNotSupportedException` on WitOS (Compatibility-Differences: File change notifications, N1).
  - With `--disable-cm`, which turns configuration management and its watcher off, it runs: the categories and the
    scenarios on the whole 100 by 37 screen, the menu bar and the status bar, Esc quits, and `dotnet` exits with 0.
  - Its default driver on an unknown Unix is `ansi` (the status bar says `Unknown , ansi`). That driver asks
    `TIOCGWINSZ` by the BSD value whenever `IsLinux()` is false, which WitOS's libc refuses, and then takes the size from
    the terminal's answer to `CSI 18 t`, which the display gives (C2.6); `--driver dotnet` (`Unknown , dotnet`) takes it
    from `System.Console` and runs as well. Neither needs a change of Terminal.Gui; the two generic fixes for upstream are
    the size query by the libc's constant, or `Console.WindowWidth` when the ioctl fails, and watchers made only when the
    configuration watcher starts.
- **CSharpFar** (MIT, release v1.0.96, commit `584e7045950bb8fd625eba209f451daeeb46d05f`, its Linux host
  `CSharpFar.Host.Linux` published portably): it stops at start
  with `CSharpFar stopped because of an unexpected error` and its crash report on the volume
  (`/data/CSharpFar/crashes/`): `CSharpFar.App.Updates.UpdateCheckService` holds an `HttpClient` in a static field for
  its update check, made unconditionally at start, and System.Net.Http throws `PlatformNotSupportedException` from
  `HttpClient`'s constructor on WitOS, which has no network until M7. Its file system watchers catch the platform's
  refusal, and its terminal input reads the libc's termios through `DllImport("libc")`; how far it gets after the update
  check is the network milestone's measurement.

## 6. What ran

In the Linux host's image, whose runtime trees of x64 and riscv64 it holds whole, with the commander published by SDK
10.0.300:

- `runtime-commander` on x64: PASS in 75 s — the panels of `/data` (10 items), the viewer, the copy (`Copied 1 file,
  68 B`), the launcher's exit with 0 after 70 s with 772 MiB free; the screendump in the viewer equal to the host's
  frame, and `/tmp/zz-note.txt` on the clean ext4 volume.
- `runtime-commander` on riscv64: PASS in 102 s, the same, the launcher's exit after 101 s with 785 MiB free.
- Host tests: `AppsLayerTests` (7: the file manager's entry, the properties' check), `format`.

ARM64 is CI's `linux-host` leg, which runs `runtime-commander` after `runtime-powershell` with the rest of
`runtime-witos`, as do the other two legs.

Two tries of the gate taught its waits: Arlecchino's F3 is Edit (`No editor set — press ! and type editor vim`), so the
viewer is Enter; and F5 sent at once after the viewer found the panels still reading the folder (`Nothing selected`),
so it waits for the panel's line of the entry.

## 7. Limits

- The Spleen font has no glyph for some symbols the commander draws (`⇄`, U+21C4, between the two panels' sources in the
  title bar), which the display draws as the font's default glyph.
- FTP and SFTP need the network (M7).
- Building from source needs git and the SDK on the host; the installer in the guest (C4.3) takes published files.
