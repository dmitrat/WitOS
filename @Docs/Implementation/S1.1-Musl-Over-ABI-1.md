# S1.1 — musl over ABI-1

Plan step S1.1 starts the substrate of the system layer ([RFC 0011 v3 §9.1](../RFC-0011-Kernel-Architecture-and-ABI.md)):
the C library is musl at a pinned release, built from the verified tarball by the pinned clang (T1) for both triples,
with WitOS's system-call dispatch in place of the Linux instruction. The first libc program — stdio, malloc, strings,
conversions, sorting, setjmp, clocks, entropy, thread-local storage of the main thread, atexit — runs as the root
task on x64 and ARM64 and prints `[LIBC] musl 1.2.5 on x86_64: 32 checks passed, 0 failed` (or `aarch64`). Files
(S1.2), threads (S2), signals (S3) and the C++ runtime (S4) follow; their calls return `ENOSYS` today and nothing
pretends otherwise.

## What changed

**The pin.** `MuslLibc` (tools/WitOS.Dev/Substrate) pins musl 1.2.5 by the SHA-256 of its release tarball
(`a9a118bbe84d8764da0ea0d28b3ab3fae8477fc7e4085d90102b8596fc7c75e4`, musl.libc.org). `setup` downloads it into
`.tools/downloads`, verifies it and extracts it once with .NET's tar reader into `.tools/musl-1.2.5`, marked by the
hash; a build requires the marked tree and names `setup` when it is missing. CI caches the tarball in both kernel
jobs.

**The build.** WitOS.Dev replicates musl's Makefile instead of running it: every `src/*/*.c` and
`src/malloc/mallocng/*.c`, with an architecture's `src/*/<arch>/*` replacing the generic file of the same name
(`SelectSources`); `bits/alltypes.h` from the two `alltypes.h.in` through the rules of `tools/mkalltypes.sed`
(`AllTypes`); `bits/syscall.h` as the `__NR_` definitions plus their `SYS_` copies (`SyscallNumbers`); `version.h`;
musl's options in clang's terms (`-std=c99 -nostdinc -ffreestanding -fexcess-precision=standard -frounding-math
-fno-strict-aliasing -Wa,--noexecstack -fno-stack-protector -D_XOPEN_SOURCE=700 -Os -fomit-frame-pointer
-fno-unwind-tables -fno-asynchronous-unwind-tables -ffunction-sections -fdata-sections`) plus `-fPIE` for the fixed
link above 4 GiB and `-ffixed-x18` on ARM64; `llvm-ar` archives `libc.a`. The build runs in parallel, once per set of
inputs (a stamp of the pin, the patches, the sysdeps, the options and the compiler) under `artifacts/substrate/<arch>`.
The assembly that issues Linux system calls or builds on Linux's thread and signal entry is left out
(`__set_thread_area.s`, `__unmapself.s`, `clone.s`, `syscall_cp.s`, `restore.s`, `vfork.s`), and musl's generic C takes
its place: `clone` and `vfork` report `ENOSYS` until S2, cancellation points call through the dispatch.

**The compiler's helpers.** clang emits calls to compiler-rt's soft-float builtins for `long double` on aarch64 (IEEE
binary128: musl's `printf`, `strtod` and the `long double` mathematics), and the pinned LLVM package ships no builtins
for the Linux triples. `src/Substrate/compiler-rt.lock.json` pins the generic soft-float sources and `aarch64/fp_mode.c`
of compiler-rt at the toolchain's own tag (`llvmorg-20.1.8`) by SHA-256, with the license; `CompilerRtBuiltins`
downloads them once into `.tools/compiler-rt`, verifies them on every use and compiles them unchanged into
`builtins.a` per architecture, linked after `libc.a`. On x64 `long double` is the x87 format and nothing is pulled in.

**The patches.** `patches/musl/syscall_arch.x86_64.h.patch` and `syscall_arch.aarch64.h.patch` turn musl's inline
`SYSCALL` and `SVC` stubs into calls of `__wit_syscall(n, a1..a6)` and drop the vDSO names (there is no vDSO, so
`clock_gettime` takes the system-call path). They apply through `UpstreamPatches`, exactly, into an overlay include
directory ahead of `arch/<arch>`; the host test that reproduces every patch covers them from the extracted tree.

**The sysdeps.** `src/Substrate/libc` is WitOS's part of the library, compiled inside the build with musl's internal
headers, the kernel's ABI headers and the sysroot's transport, with strict warnings:
- `syscall.c`: `__wit_syscall` dispatches by Linux number. `exit`/`exit_group` → `PROCESS_EXIT`; `write`/`writev` on
  descriptors 1 and 2 → `DEBUG_WRITE` on the startup descriptor's log handle, in chunks of at most 64 KiB, the
  vectors of one `writev` joined so that a line arrives whole; `read`/`readv` on 0 → end of input; `ioctl
  TIOCGWINSZ` on 0–2 → 80×25, so musl line-buffers standard output and `isatty` is true, other requests `ENOTTY`;
  `mmap`/`munmap`/`mprotect`/`madvise` → memory.c; `mremap` → `ENOSYS` (musl copies); `brk` → `ENOMEM` (musl's
  allocators fall back to mmap); `clock_gettime`/`clock_getres` → `CLOCK_READ`/`CLOCK_FREQUENCY` (UTC for
  `CLOCK_REALTIME`, the monotonic counter for the others, scaled without overflow); `nanosleep`/`clock_nanosleep` →
  `SLEEP_UNTIL` on the monotonic clock; `getrandom` → `RANDOM`; `sched_yield` → `THREAD_YIELD`; `set_tid_address`,
  `gettid`, `getpid` → 1; the identity calls → 0; `uname` → WitOS and the ISA; `arch_prctl(ARCH_SET_FS)` →
  `THREAD_SET_TLS` on x64; everything else → `ENOSYS`. ABI-1 statuses map to errno (`__wit_errno`).
- `memory.c`: an anonymous private `mmap` is `MEMORY_RESERVE` of the rounded length and `MEMORY_COMMIT` under the
  requested protection (`PROT_NONE`, read, read-write; `PROT_EXEC` is `EACCES`: code arrives through memory objects),
  remembered in a table of 256 so that `munmap` of a whole mapping is `MEMORY_RELEASE`; `munmap` of a part is
  `MEMORY_DECOMMIT` with the reservation kept; `mprotect` → `MEMORY_PROTECT`; `madvise(MADV_DONTNEED)` →
  `MEMORY_RESET`, other advice changes nothing. File mappings are `ENODEV`, fixed and shared mappings `ENOTSUP`.
- `thread.c`: `__set_thread_area` on x64 through `THREAD_SET_TLS`, which takes effect at the return of that very
  call; ARM64 keeps musl's `msr tpidr_el0`, which the kernel preserves.
- `crt1.c`: `_start` saves the startup descriptor and hands `__libc_start_main` a program stack image in the shape
  musl reads: `argc` 1, `argv[0]` "root", no environment, and the auxiliary vector — `AT_PAGESZ`, `AT_PHDR`/`AT_PHENT`/
  `AT_PHNUM` from the ELF header the linker script maps with the first segment (static TLS reads `PT_TLS` through
  them), `AT_RANDOM` from `RANDOM` for the stack protector, the identity entries at zero and `AT_SECURE` 0, so musl
  does not poll the standard descriptors.
- `static.ld`: a static `ET_EXEC` at the image window whose ELF headers share the read-only segment, with the code and
  the writable data (TLS template, initializer arrays) each starting a page; `-e _start`, no interpreter, no dynamic
  section, no relocations.

**The scenario.** `libc` builds the self-test kernel with `tests/User/libc_hello.c` as the root task
(`KernelImageBuilder.LIBC_SCENARIO`): both suites run it and require the last line of the program. The `libc` command
of WitOS.Dev builds and boots it alone on x64. `FlatImage.FromElfAsync` now accepts a `PT_TLS` entry, which describes
bytes a loadable segment carries; an interpreter or a dynamic section is still refused.

## Tests

- `tests/User/libc_hello.c` (both ISAs, 32 checks): `snprintf` of integers, strings and floating point; string
  functions; `strtol`/`strtoul`/`atoi`/`strtod`/`atof`; `sqrt`/`pow`; `malloc` small and 3 MiB, `realloc`, `calloc`,
  `qsort`, `bsearch`; `mmap`/`mprotect`/`munmap` and the refusal of executable anonymous memory; `setjmp`/`longjmp`;
  `getppid`; `open` reporting `ENOSYS` before files exist; `clock_gettime` monotonic and real-time, `time`,
  `getrandom` with nonzero entropy, `nanosleep` advancing the clock; a `__thread` variable; `isatty`; `uname`;
  `fprintf(stderr)`; `atexit` printing the summary. Both suites require `[LIBC] musl 1.2.5 on <isa>: ` in the log.
- Host: `UpstreamPatchesTests` reproduce the musl patches from the extracted tree; `FlatImageTests` accept a TLS
  entry; the compiler-rt pin is checked on every build.

## Limits kept explicit

- Freestanding of everything but the kernel: no files (every `open` is `ENOSYS`; S1.2 brings the read-only
  package), no threads (`clone` and `futex` are `ENOSYS`; S2), no signals (S3; `abort` ends in musl's crash
  instruction, a contained fault), no C++ runtime (S4), no dynamic linking (S5), no environment or arguments (S6).
- Standard output and error are the kernel log; standard input is empty. `[USER]` prefixes come from the kernel's
  `DEBUG_WRITE`.
- A partial `munmap` keeps the reservation; the mapping table holds 256 whole mappings, beyond which `munmap`
  decommits. `MAP_FIXED`, shared and file mappings are refused.
- `CLOCK_REALTIME` is the board's clock at boot plus the monotonic time (K6); `clock_nanosleep` with `TIMER_ABSTIME`
  serves the monotonic clock alone.
- The libc is static; a program is the root task at the fixed image window of at most 1 MiB per segment.
- The differential run against musl on Linux waits for the Linux build host (T2); libc-test is S1.3.
