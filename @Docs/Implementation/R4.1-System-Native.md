# R4.1 — System.Native over the system layer

R4 makes the class libraries' Unix flavour work over the system layer (RFC 0015 §5 and §8). Its gate is "System.Native
over the package, time, environment, invariant globalization, explicit refusals" with guest markers and the
differences list (§9). R4.1 meets that gate for the read-only boot package. R4.2 moves files onto the namespace
service once D5 exists.

## The check

`tests/Runtime.Witos/SystemNative/SystemNative.cs` runs under upstream's `corerun`, as in R3.2. It checks twelve
areas from managed code and prints one line for each:

| Area | What it checks |
| --- | --- |
| files | `File.ReadAllText`, `FileInfo.Length`, `File.Exists`, `Directory.Exists` and `GetFiles` on the package's `/test`, a `FileStream` seek and read, and a 5 MiB read of CoreLib |
| writes refused | `File.WriteAllText` and `Directory.CreateDirectory` throw `IOException` or `UnauthorizedAccessException` |
| current directory | the process starts in `/`; after `SetCurrentDirectory("/test")`, relative paths and `Path.GetFullPath` resolve from there |
| time | `DateTime.UtcNow` is plausible, `Thread.Sleep` and `Stopwatch` agree, and the local zone is UTC |
| environment | variables can be set and read back; processor count, bitness, `PlatformID.Unix`, `OSPlatform.Create("WITOS")`, `TickCount64` and `MachineName` are all reported |
| globalization | the invariant culture, invariant number formatting, comparison and casing |
| random | `RandomNumberGenerator` draws differ |
| console | standard input is redirected and ends at once |
| signals | `PosixSignalRegistration` for `SIGTERM` and `Console.CancelKeyPress` install |
| processes refused | `Environment.ProcessId` is reported, and `Process.Start` throws `PlatformNotSupportedException` |
| hashes | SHA-256 of "abc" matches FIPS 180-2, and HMAC-SHA-256 works |
| cryptography refused | `RSA.Create` throws `PlatformNotSupportedException` |

The scenario `runtime-system-native` packs the program with the libc's own test files under `/test`. It requires
`[R4] System.Native under CoreCLR on <ISA>: 12 areas passed, 0 failed`. `runtime-witos` boots it on each ISA after
CoreCLR's acceptance.

## What it found, and what changed

A container trace of failing libc calls found every gap. These fixes landed:

| Failure | Cause | Change |
| --- | --- | --- |
| `File.ReadAllText` threw `IOException` ("Function not implemented") | `FileStream` emulates `FileShare` with `flock(LOCK_SH \| LOCK_NB)`, and `flock` was `ENOSYS` | The libc's `flock` locks the open file description, as Linux's does: descriptions of the same file conflict, duplicates share the lock, and the lock ends with the description's last descriptor. A conflicting request with `LOCK_NB` returns `EWOULDBLOCK`. Without `LOCK_NB` the caller parks on a word that every unlock bumps, outside the table lock. |
| `File.Exists` of a relative path was false; `TimeZoneInfo` probed `/etc/localtime` with `ENOSYS` | x64 musl's `lstat` is the `lstat` system call, which was missing | `lstat` is `fstatat` with `AT_SYMLINK_NOFOLLOW`. The package has no symbolic links. |
| `Directory.CreateDirectory` returned `ENOSYS` | `mkdir` and `mkdirat` were missing | A name that exists returns `EEXIST`. Anything else returns `EROFS`. |
| `Console.ReadLine` read forever | musl's `isatty` is `TIOCGWINSZ`, which the libc granted to every standard stream. .NET took standard input for a terminal and kept reading zero bytes. | `TIOCGWINSZ` succeeds on an output stream alone. Standard output and error stay the log's terminal, so musl still line-buffers them. |
| `RandomNumberGenerator` and every hash failed in `Crypto`'s type initializer | The unix flavour of `System.Security.Cryptography` loads OpenSSL's shim, which `witos` does not build (R2.3b) | A patch of the library's project: for `TargetOS=witos` the unix flavour takes the set the browser builds instead of the OpenSSL one. That gives System.Native's random bytes, the managed SHA hashes, HMAC, HKDF, PBKDF2 and SP 800-108. Every other algorithm and X.509 throw `PlatformNotSupportedException`. |
| The JIT's shared memory exhausted the 1024 mappings | `mprotect` split a chunk's mapping at its range's ends, and CoreCLR commits its executable memory page by page, so a mapping fragmented into one piece per page (795 shared pieces) | A shared mapping keeps each page's protection in two bits, and `mprotect` changes pages without splitting. An unmapping that leaves part of a mapping maps that part again and restores its pages' protections run by run. |

`libc_hello.c` checks the libc's side on both ISAs:

- `lstat` of a file and of a missing name;
- `mkdir` returning `EEXIST` and `EROFS`;
- `flock`, shared and exclusive, across two descriptions and a duplicate;
- `isatty` of the three standard streams.

`Process.Start` needed nothing: `witos` builds `System.Diagnostics.Process`'s unsupported flavour, which throws
`PlatformNotSupportedException`.

The patch set grows to 24 files. The new file belongs to the libraries.

## The differences list

[Compatibility-Differences.md](Compatibility-Differences.md) records each area where WitOS differs from Linux for a
.NET program, and how the difference shows. RFC 0015 §8 requires every absent or unsupported cell to fail explicitly
and to appear there. R4.1 starts the list with what the check verifies.

## Limits kept explicit

- **Files.** They come from the read-only boot package until the namespace service (D5), which R4.2 serves.
- **Time zones.** There is no tzdata, so the local zone is UTC.
- **Globalization.** It is invariant, so a program needs `System.Globalization.Invariant=true`. `corerun_init.c`
  passes it, and a runtimeconfig will carry it once the hosts exist (R5).
- **NativeAOT.** The check runs under CoreCLR. NativeAOT links the same System.Native statically, and its acceptance
  passes.
- **Networking.** It is absent until the network milestone, and the check does not exercise it.
