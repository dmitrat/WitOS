# N4.1 — Time zones, /tmp, file modes and the process environment

N4 is the application environment of RFC 0015 §8's "later" column and the gate N4 of §9. This first slice closes three
of the differences from Linux the compatibility suite and the libraries' suites had recorded (N1, N2.2): no time
zones, no `/tmp`, no file modes; and it moves the default environment of every process out of the root task's source.

## File modes

**The contract.** `IFileSystem.SetModeAsync(path, mode)` sets the permission bits of a file or a directory, as
`chmod` does, and returns the entry. Each provider keeps what its format keeps:

- **ext4** writes the bits of the inode's `i_mode` in one transaction (`Ext4Writer.SetModeAsync`), the type kept, the
  change time moved; e2fsprogs' `debugfs stat` reads the mode back in the host test.
- **FAT** records read-only alone. A mode without a write bit sets the attribute (the entry then reads 0444, a
  directory 0555), one with the owner's write bit clears it (0644, 0755), and any other mode is `NotPermitted`: the
  format cannot keep it, and Linux's vfat refuses a mode its masks cannot represent with `EPERM` too. `NotPermitted`
  is a new error of the contract, mapped to `EPERM`.
- **The volume in memory** (below) keeps the bits.

**Times.** `IFileSystem.SetTimesAsync(path, accessed?, modified?)` sets the times `utimensat` sets, a null one staying.
ext4 writes them into the inode (nanoseconds where the inode has room), the memory volume keeps them to the tick, and
FAT refuses with `NotPermitted`: the library records the times a write sets and sets none by hand, and `EPERM` is the
answer a volume without POSIX metadata gives on Linux, the one System.Native's `CopyFile` tolerates for a copy's
metadata.

**The protocol.** The namespace service takes `CHMOD` (a path and `Mode`), `FCHMOD` (a handle and `Mode`), `UTIMES`
(a path and a `WitNamespaceTimes` in the window at `Offset`) and `FUTIMES` (a handle and the times), each answered with
the entry's stat; the flags of the time requests say which time is set, as given or as the service's clock
(`UTIME_NOW`), a time named by neither staying (`UTIME_OMIT`). The libc routes `fchmodat`, `chmod`, `fchmod`,
`utimensat` and `futimens` (a null path names the descriptor, as musl calls): a volume's file to the service, a shared
memory file of `/dev/shm` to its own record (0600 until changed; its times stay), the devices, `/dev` and `/dev/shm`
keep theirs, and the package is `EROFS`.

**What it unlocked.** `File.SetUnixFileMode`, `File.SetAttributes(ReadOnly)`, `File.SetLastWriteTimeUtc` and,
unexpectedly, `File.Copy`: System.Native's `CopyFile` ends with `futimens` and `fchmod` of the copy and fails on
`ENOSYS`, so a copy on a volume had failed before (the first guest run of the new N1 check found it: `fchmod` served,
`futimens` not yet). The N1 suite's FileIO area gains `Copy` and `Modes` and its `Times` check sets a time; the three
Roslyn classes that copy analyzer assemblies return to the N2.2 selection.

## /tmp

`MemoryFileSystem` (`OutWit.OS.FileSystems.Memory`) is a provider in the service's memory: names, kinds, sizes, modes
and times, a capacity past which a write is `NoSpace`, a file's bytes living while a handle or a name holds them, and
the contract's errors. The namespace service mounts one at `/tmp` (64 MiB) before any disk, so `/tmp` is there in
every system that runs the services; its files last the boot. The shared mappings of R4.2 work on it as on a disk's
volume, since the service's chunks come from any `IFileHandle`.

.NET keeps named mutexes and semaphores as files under the fixed `/tmp/.dotnet`, whatever `TMPDIR` says, with the
directories' modes checked (`SharedMemoryHelpers::EnsureDirectoryExists`), `flock` and a shared mapping. With `/tmp`
and modes, a named `Mutex` is created, taken and released within a process; `Synchronization.NamedMutex` leaves
`expectations.json`, and Roslyn's `ShadowCopyAnalyzerPathResolverTests` returns to the selection. Two processes that
open the same name still do not exclude each other: `flock` is the process's own (R4.1), which the difference list
records.

## Time zones

tzdata is pinned by the SHA-256 of its tarball (`src/Substrate/tzdata.lock.json`, tzdata2026e; `setup` downloads and
extracts it), and the Linux host's `zic` compiles its sources into the TZif files of `/usr/share/zoneinfo` as tzdata's
Makefile does (the continents, `etcetera`, `factory` and `backward`; `-b fat`; `-L /dev/null`), once per pin under
`artifacts/tzdata`. The .NET install carries them with `zone.tab`, `zone1970.tab` and `iso3166.tab`, which
`TimeZoneInfo` reads on Unix (`TZDIR`'s default). There is no `/etc/localtime`, so the local zone is UTC unless `TZ`
names one; `FindSystemTimeZoneById`, conversions and `GetSystemTimeZones` work with IANA ids as on Linux. The N1 suite
gains a TimeZones area (Iana, Convert, Zones, Local), which passes on Windows, Linux and WitOS.

The zoneinfo tree is some 600 files, which the boot package's table could not hold: `WIT_PACKAGE_MAX_FILES` is 4096
since this step (1024 before); the table of 32-byte entries still fits the one mapping of 64 pages the libc reads it
through, and the package writer and the reference reader take the same limit.

## The process environment

The root task reads `/etc/environment` from the package, `KEY=VALUE` a line with `#` comments, as the default
environment of `/bin/init` and so of every process (`posix_spawn` inherits it), and appends the GC's limit it computes
(N2.2); a package without the file gives `PATH=/bin:/usr/bin` alone, as before. The .NET install writes the file:
`PATH` and `HOME=/`, the home of the one account `/etc/passwd` names.

## Checks

- `devices_init.c`: `chmod` and `fchmod` keep the mode on `/data` and `/tmp` (0640, 0600, a directory's 0777),
  `utimensat` keeps the times to the nanosecond, `UTIME_OMIT` leaves one and `futimens` with null takes the clock; FAT
  takes 0444 and 0644 and answers `EPERM` for 0600 and for times set by hand; `/tmp` serves the same calls as a disk's
  volume (the shared mapping among them), and `chmod` in the package is `EROFS`.
- The N1 suite: TimeZones (4 checks), FileIO `Copy`, `Modes` and `Temp`, `Times` setting a time; `Synchronization.NamedMutex`
  passes; 3 recorded differences remain (`KnownOperatingSystem`, `ProcessStart`, `FileSystemWatcher`).
- N2.2: the Roslyn group runs with the four class exclusions lifted, and the serialization-numerics group with
  MessagePack's `DateTimeOffsetTest` back, which finds the time zone "Cuba" by its id.
- Host tests: `MemoryFileSystemTests`, the session's `ModesFollowTheVolumeTest`, ext4's mode judged by `debugfs`,
  `TzdataTests`.

## Limits kept explicit

- **`/tmp` is memory, and one per boot.** Its capacity is the service's constant, 64 MiB; a larger temporary set
  belongs on a volume through `TMPDIR`, as the suites' runner sets it.
- **FAT's modes are read-only or not, and its times are the writes'.** A program that sets 0600 or a time on `/fat`
  gets `UnauthorizedAccessException` (`EPERM`), as on a FAT volume under Linux; `File.Copy` completes without the times.
- **No `umask`**, no ownership (`chown` stays `ENOSYS`; every file is root's), no `/etc/localtime`.
- **Named synchronization objects exclude within a process**, since `flock` is the process's.
