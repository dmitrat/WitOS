# K8.3b — the last mechanism fixtures in C

[K8.3a](K8.3a-Mechanism-Fixtures-In-C.md) carried nine of the twelve mechanism fixtures from MASM and armasm to C.
K8.3b carries the last three: `entry`, `waits` and `threads`. No mechanism fixture is now written in assembly or built
by MSVC. What MSVC still builds for a self-test kernel are the PE fixtures of the kernel policy: `image.asm`,
`bootstrap.c`, `compiler_tls*.c`, and the library fixtures of the host harnesses. They leave with that policy at K8.4.

## The three fixtures

**`entry`.** The isolation and memory fixture.

- *Assembly.* Three things are tested on the register itself:
  - the state a component starts in: user mode and zero SIMD state on x64; zero SIMD state and TPIDR_EL0 on ARM64,
    which then carries a sentinel that every return to EL0 must keep;
  - the registers a system call must keep (`entry_preserved_call`): RBX, R12–R15 and XMM6 on x64; X19–X22 and both
    halves of V8 on ARM64;
  - the preemption loop, whose condition flags, GPR and SIMD register must survive the timer.
- *Traps.* Short assembly functions, since C would not reliably emit a read of address zero or a privileged
  instruction:
  - x64: `cli`, `out`, `ud2`;
  - ARM64: `msr daifset`, `mrs ttbr1_el1`, `udf`;
  - a read and a byte write the kernel refuses;
  - a call with a noncanonical stack pointer.
- *C.* The memory life cycle, the call boundary and the data pages' zero fill.
- *Size.* 3,212 bytes on ARM64. It fits the one code page the kernel tests count as part of their nine owned pages.

**`waits`.**
- The worker threads are of the one form, created with `fixture_thread_start`. Each gets a record in the data page:
  its stack, its index and a word that is its TLS base.
- A waiting worker writes its index through its TLS: FS on x64, TPIDRRO_EL0's word on ARM64. It waits with a vector
  register holding the index (`waits_preserved_call`: XMM6, D16), and finds both intact.
- The shared counter is an atomic increment in assembly: `lock incq`, or an exclusive pair. The compiler's ARM64
  atomics could call compiler-rt's outline helpers, which a fixture does not link.
- The kernel's checks of parks, wakes, timeouts, idle ticks and owned pages are unchanged and pass.

**`threads`.** This fixture tested the version 1 form, and its checks of that form leave with it: the raw TLS block's
self and argument words, the private identity handle, and the kernel's TLS page that memory calls may not remove.
In the one form it now tests:
- a join on what is no thread or a foreign handle;
- a creation with an entry outside the code and with a reserved flag;
- two workers that preempt each other. This part is all assembly. Each first checks zero SIMD registers (and FPCR on
  ARM64) and a whole zero stack, then that its TLS (the record's word), XMM6 and XMM0 (D8 and D0), a word below its
  stack pointer and its own rounding mode (MXCSR, FPCR) survive;
- a reaped slot that comes back with another handle;
- a closed handle that detaches a live thread;
- the component's capacity: the fourth thread is refused, counted by `ReferenceThreadCapacityFailures` as before;
- a thread's faults.

**Fault addresses.** The faulting thread's stack is a reservation at a fixed address of the data arena
(`WIT_THREAD_TEST_STACK`, 16 KiB, `tests/User/protocol.h`), inside one 2 MiB region. The guard below and above it are
therefore known addresses whose page table exists. The kernel tests' fault tables (`tests/Kernel.<isa>/user_arch_tests.c`)
name those addresses in place of the version 1 stack windows; the syndromes are the same.

**What did not change.** The kernel-side test of version 1 creation rollback (`allocation_failure`) stays until K8.4,
since it builds its request in the kernel.

## The tool

`UserImage` builds no mechanism fixture with ml64, armasm64 or link.exe any more. `BuildFixtureAsync`,
`BuildArm64FixtureAsync`, `LinkFixtureAsync` and the PE embedding are removed. The ABI constants still go to
`user_abi.inc` and `user_abi_a64.h` for the PE fixtures' `image.asm`.

`fixture.h` gains:
- `fixture_stack`, which reserves a stack, at a fixed address when one is given;
- `fixture_thread`, a creation with any argument and TLS base;
- `fixture_thread_start` with its `FixtureThreadRecord`;
- `fixture_deadline_ticks`.

## Tests

The fixtures report the same markers as before. On both ISAs:
- the preemption workers switch on the timer with their state intact;
- the waits park and wake as counted;
- the faults land at the fixed addresses.

The results:
- `format-check` and the host tests pass;
- `test`: all 27 x64 scenarios pass;
- `test --arch arm64`: all 21 foundation scenarios pass.

## Limits kept explicit

- **The first thread.** A fixture's first thread is still the kernel's version 1 form, with its stack at
  `WIT_USER_STACK_BOTTOM`. The entry fixture's guard tests use that stack, and the thread fixture's bad return lands on
  it. The new first-thread form is K8.4's.
- **MSVC.** The PE fixtures of the kernel policy keep MSVC until K8.4. The Linux host therefore still runs only the
  release kernel's scenarios, which keeps T2.2 open.
