# H5.1 — A session boots without the gates' probes

The author's VMware session of 2026-10-25 asked why WitOS took longer to boot than Windows 11. A timeline answered it:
most of the time went to probes that only the QEMU gates need.

## 1. The measurement

`timeline.py`, a scratch script, starts a VMware machine without a window (`vmrun -T ws start … nogui`). It stamps each
new line of the machine's serial log with the host's seconds since the start, and takes a VNC frame every five seconds.
The machine is H5's SATA machine with the PC's one disk that `shell --pc --prepare` writes, which is the session the
author runs.

| Seconds | Before | After |
| --- | --- | --- |
| 3.5 | the UEFI loader | the same |
| 4.8–5.2 | `Kernel initialized.`; the root task starts the device manager | the same |
| 5.9 | the storage probe: the partitions' test writes and readbacks, the FAT volumes' writes | `[DEVICES] probes: skipped in a session (/etc/witos/session)` |
| 10.7 | the ext4 probe's writes and second mount (4.8 s) | — |
| 20.7 | the ARP probe for QEMU's gateway 10.0.2.2: no reply within 10 s, since VMware's NAT is not slirp | the namespace service ready at 5.9 s |
| 21.8 | the network service ready, DHCP leased by VMware's NAT | at 7.1 s |
| 43.8 | the TCP probe's connection to the runner's echo server 10.0.2.100:7: refused after 21 s | — |
| 44.4 | the display probe's test pattern; the display, terminal and device manager ready | at 7.6 s |
| ~58 | `PS /data>` | ~22 |

So 36 of the 44 seconds before the device manager answered ready were probes. The probes also wrote to the person's
volumes: the test partition, `/guest` on the FAT and ext4 volumes. PowerShell then took about 14 seconds to its prompt.

## 2. The change

A session's package holds `/etc/witos/session` (C2.7), which the `shell` command writes and no gate's package has.
`Session` (`src/Services/DeviceManager/Session.cs`) reads the mark once. In a session the device manager:

- opens each disk for the namespace service without probing it (`StorageProbe.RunAsync(driver, probe: false)` prints
  the disk's line and returns it);
- hands each adapter's packet channel to the network service without the ARP exchange
  (`NetworkProbe.Run(driver, probe: false)`);
- runs neither the DNS and TCP probes, nor the display's test pattern, nor the terminal's prompt. The terminal's skip
  was the only one before.

Everything a session uses still starts: the drivers, the namespace service with its volumes, the network service, the
display and the terminal.

## 3. The gate

| Check | Result |
| --- | --- |
| `runtime-services --arch x64` (container) | passed: `runtime-devices`' boots, whose packages are no session, print and require every probe as before |
| VMware, the session's disk (§1) | the device manager ready at 7.6 s and the prompt at about 22 s, against 44.4 s and 58 s |

## 4. What is not yet

- **PowerShell's own 14 seconds**, which compiling its startup takes. Its assemblies carry ReadyToRun code, and whether
  CoreCLR on WitOS uses it is not measured here.
- **The keyboard on VMware**, which H5.2 brings through the i8042 ([ADR 0031](ADR-0031-PC-PS2-Keyboard.md)).
