# W4.2 — Network interfaces and their changes

Plan step W4.2 (phase W, M7; the inventory's decision 8 named the interfaces beside the local sockets of W4.1), 2026-10-22.
What a program asks about its network interfaces — `getifaddrs`, `if_nameindex`, `if_nametoindex`, the `SIOCGIF*` ioctls,
and above them .NET's `System.Net.NetworkInformation`: `NetworkInterface.GetAllNetworkInterfaces`, the interface's
addresses, hardware address, MTU and index, `NetworkChange`'s notifications — is answered by the libc from the network
service's configuration, as Linux's kernel answers it over a netlink route socket. WitOS adds no API: musl's functions
and the runtime's Linux files work unchanged.

## 1. What Linux gives and how the libc gives it

| Linux | WitOS |
| --- | --- |
| `socket(PF_NETLINK, SOCK_RAW, NETLINK_ROUTE)`; `RTM_GETLINK` and `RTM_GETADDR` dumps (musl's `__rtnetlink_enumerate` behind `getifaddrs` and `if_nameindex`), `RTM_GETROUTE` | `src/Substrate/libc/netlink.c`: a descriptor of kind `KindNetlink` over a record with a queue of messages; a request's answers are queued by the request itself — `RTM_NEWLINK` for the loopback (index 1, `lo`, `ARPHRD_LOOPBACK`, MTU 65536) and for the adapter the service runs its stack on (index 2, `eth0`, `ARPHRD_ETHER`, its MAC and MTU), `RTM_NEWADDR` for 127.0.0.1/8 and the lease's address with its mask, broadcast and label, `RTM_NEWROUTE` for the adapter's subnet and the default route through the gateway, each dump ending with `NLMSG_DONE`; a request of another kind or without `NLM_F_DUMP` is `NLMSG_ERROR` with `EOPNOTSUPP`; an IPv6 dump answered `DONE` alone until W4.3, which lists the IPv6 addresses and routes ([W4.3-IPv6.md](W4.3-IPv6.md)) |
| `recvmsg` of whole messages, `MSG_TRUNC` for one the buffer cannot take, `MSG_PEEK`, `MSG_DONTWAIT`; a blocking read waits for a message | the same over the queue; a receive into no room waits for a message and takes none (.NET's zero-byte receive waits for readiness so); a reader parks on the record's sequence word, which every enqueue bumps and which `epoll`'s edge is; `poll` and `epoll` serve the descriptor |
| `bind` with `nl_groups`, `NETLINK_ADD_MEMBERSHIP`; `RTMGRP_LINK`, `RTMGRP_IPV4_IFADDR`, `RTMGRP_IPV4_ROUTE` multicast | the groups are recorded; when the service's configuration changes, every socket that bound the groups gets `RTM_DELADDR` for the address that went, `RTM_NEWADDR` for the one that came, `RTM_NEWLINK` for the link and the routes again (§2) |
| `getsockname` (`sockaddr_nl` with the port), `SO_TYPE`, `SO_DOMAIN`, `SO_PROTOCOL`, `SO_RCVBUF` | answered; the first socket's port is 1, the process, each beyond its own number |
| `SIOCGIFINDEX`, `SIOCGIFNAME`, `SIOCGIFFLAGS`, `SIOCGIFMTU`, `SIOCGIFHWADDR`, `SIOCGIFADDR`, `SIOCGIFNETMASK`, `SIOCGIFBRDADDR`, `SIOCGIFCONF` on any socket | `__wit_interface_ioctl`, asked first by the AF_INET sockets' (`socket.c`), the local sockets' (`unix.c`) and the netlink sockets' ioctl; `ENODEV` for an interface that is not there, `EADDRNOTAVAIL` for an address an interface lacks |
| `socket(AF_UNIX, SOCK_DGRAM)` for an ioctl (musl's `if_nametoindex`) | a datagram socket of its own opens (W4.1 refused it with `ESOCKTNOSUPPORT`) and serves the interface ioctls, `getsockopt` and `shutdown`; a name or a transfer is `EOPNOTSUPP`, since no name takes a datagram. .NET's `OSSupportsUnixDomainSockets`, which opens one, stays true |

The interfaces come from `WIT_SOCKET_CONFIGURATION` (`__wit_socket_configuration`, which `/etc/resolv.conf` used
already): a process without the network service, or one whose service has no adapter (the stack of a board without one
runs on no link, its address zero), has the loopback alone. Linux's structures and numbers (`nlmsghdr`, `ifinfomsg`,
`ifaddrmsg`, `rtmsg`, `rtattr`, the `RTM_`, `IFLA_`, `IFA_`, `RTA_` values) are written in `netlink.c` as the ABI fixes
them, since musl ships no `<linux/netlink.h>`. The libc's tables stay within the root task's bounded segment: four
sockets with queues of 4 KiB, where a dump of the two interfaces takes some 600 bytes.

## 2. The change notifications

The stack announces `ConfigurationChanged` when `Configure` changes the address, the mask, the gateway or the DNS servers
(a lease taken, renewed with other values or lost; a renewal that changes nothing announces nothing), the service tells
every live session with a `WitSocketEvent` whose socket is `WIT_SOCKET_CONFIGURATION_EVENT` (`SocketConnection.NotifyAll`),
and the libc's events thread, which hears every event of the session, asks the configuration again and tells the netlink
sockets what went and what came (`__wit_netlink_notify`); the configuration as it was at the session's start is read
once the session connects, so the first change has a before. .NET's `NetworkChange` opens such a socket bound to the
address and route groups through System.Native (`SystemNative_CreateNetworkChangeListenerSocket`) and reads it as a
`Socket` (`ReadEventsAsync`: a zero-byte receive for readiness through the socket engine's `epoll`, then `recvmsg`).
System.Native compiles that listener where `<linux/rtnetlink.h>` exists, so the sysroot carries it and what it includes
from the pinned sanitized kernel headers (`Sysroot.KERNEL_HEADERS`, followed through their `#include` lines: `linux/`,
`asm/` of the ISA and `asm-generic/`, twenty files), as a Linux musl system has them installed; nothing else of the set,
since a program on WitOS has no Linux kernel. A link's state is not reported: the virtio adapter's `STATUS` is read once.

## 3. .NET

`System.Net.NetworkInformation` built for witos was the platform-neutral assembly, whose types throw
`PlatformNotSupportedException` (the project's target frameworks name Windows, Linux, Android, Apple's, FreeBSD, illumos,
Solaris and Haiku). The patch `src.libraries.System.Net.NetworkInformation.src.System.Net.NetworkInformation.csproj.patch`
gives witos the unix flavor, as W2.2 gave System.Net.Http and System.Net.Security theirs, and Linux's files for it: Linux's
`NetworkInterfacePal` asks System.Native for the interfaces (`SystemNative_GetNetworkInterfaces`: `getifaddrs`, the
`AF_PACKET` entries for the hardware addresses, `SIOCGIFMTU` and `if_nametoindex`), reads `/etc/resolv.conf` for the DNS
servers and the routes from `/proc/net/route` only where that file exists — it does not, so a gateway list is empty —
and `NetworkChange` is the unix file over the netlink listener. The statistics (`GetIPStatistics`, `GetIPv4Statistics`,
`IPGlobalProperties`' TCP, UDP, ICMP and IP statistics and connection tables), which Linux reads from `/proc/net`, are not
kept: those calls fail as Linux's do without `/proc` (`FileNotFoundException`), a recorded difference.

## 5. Differences from Linux

- No statistics: `/proc/net` is not emulated (Compatibility-Differences: Network interfaces).
- Gateways: `IPInterfaceProperties.GatewayAddresses` is empty, since Linux's PAL reads `/proc/net/route`; the libc's
  `RTM_GETROUTE` dump names the default route for a program that asks netlink.
- Events: an address or a route change comes from the service's lease alone; a link's loss is not reported.
- A datagram `AF_UNIX` socket of its own serves the interface ioctls alone.
