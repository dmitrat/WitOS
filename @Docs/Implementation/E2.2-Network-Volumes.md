# E2.2 — Network volumes in the guest

Plan step E2.2 (phase E, goal Ц6): a share of a Windows or Samba server mounted in WitOS as a volume of the catalog
(ADR 0032, `ORIGIN_NETWORK`, below `/media`) through the SMB 3 client of E2.1, used by any program through the POSIX
tree, and unmounted again. The command that does it is `witos-volumes`; the libc's `mount(2)` and `umount2(2)` are
what it calls, as Linux's `mount.cifs` calls `mount(2)`.

## 1. The way through

```text
witos-volumes mount //server/share --user U ...        a NativeAOT program of the boot package
  └─ libc mount(2): source, target, "smb3", options     outside the table lock
      └─ namespace service MOUNT                         its session's thread
          └─ SocketStream → network service → TCP 445   the endpoint the device manager gave it
              └─ SmbFileSystem (E2.1) → catalog → /media/<alias>
```

- **The network for the namespace service.** The device manager starts the namespace service before the network
  service, so the service has no network at its start. Once the network service answers ready, the device manager
  moves a duplicate of its clients' endpoint (`SEND`, `DUPLICATE`, `TRANSFER`) to the namespace service in a disk
  message with `WIT_NAMESPACE_DISK_NETWORK`; the service keeps it and logs `the network service's endpoint: shares
  mount below /media`. A board without the service, or a service without an adapter, leaves the loopback alone, and a
  mount answers what the connection does.
- **The stream.** `OutWit.OS.Networking.SocketStream` is a TCP connection of the network service as a `Stream`: a
  session of its own, a stream socket connected as a blocking connect waits (writability or `SO_ERROR`), reads and
  writes that wait on the session's readiness events when the service answers `EAGAIN`, each wait bounded by 60 s of
  the guest's time; a failure is a `SocketStreamException` with the service's errno value.
- **The request.** `WIT_NAMESPACE_MOUNT` (27) carries mount(2)'s four strings in the window, each zero-terminated —
  the source, the target (empty or `/media/<name>`), the type and the options — and `MS_RDONLY` as
  `WIT_NAMESPACE_MOUNT_READ_ONLY`; the reply's window holds the volume's `WitNamespaceVolume`. `NetworkMount.Parse`
  reads it as Linux's cifs reads it: the types `smb3`, `cifs` and `smb`; the source `//server/share` (or with `\`);
  the options of `mount.cifs` (`username`/`user`, `password`/`pass`, `domain`/`dom`/`workgroup`, `ro`, `rw`,
  `ip`/`addr`, `port`, `vers` of a dialect the client speaks), comma-separated with a comma in a value doubled, any
  other option left as Linux leaves it. The service resolves no name: a source that names its server by a name needs
  `ip=`, which the command passes, as `mount.cifs` passes it to the kernel.
- **The volume.** The share mounts through E2.1's client and enters the catalog with the network's origin, its label
  the share's name, its alias the target's name or the share's stem (`-2`… when taken), its identity the GUID of the
  server's GUID and the share's name; a second mount of the same share is the same identity, flagged as a collision.
  The mount line names the dialect, the address and the account, never the password.
- **The unmount.** `WIT_NAMESPACE_UNMOUNT` (28) of a network volume's mount point detaches it from the catalog and
  closes its connection (TREE_DISCONNECT, LOGOFF). While a session holds a file or a directory of it the answer is
  `EBUSY`, unless `WIT_NAMESPACE_UNMOUNT_DETACH` (`MNT_DETACH`) asks it gone anyway — a file left open then fails with
  `EIO`. The mount table counts what each session holds of each mount for it. A disk's volume is never unmounted by a
  request (`EBUSY`): it leaves with its device (E3). At the service's stop the shares log off before the disks' volumes
  unmount.

The errno values follow Linux's mount of a CIFS share: an unknown type `ENODEV`, a malformed request `EINVAL`, a
refused account `EACCES`, a share the server has not `ENOENT`, an alias taken `EBUSY`, no network `ENETDOWN`, and the
connection's own (`ECONNREFUSED`, `ETIMEDOUT`, `EHOSTUNREACH`).

## 2. The libc

- `mount(2)` and `umount2(2)` (`syscall.c`'s `mount_call`) normalize the target and make the namespace's session under
  the table lock, then send the request without it, since a logon is several round trips over the network (S8.1's
  rule for remote transfers). `MS_RDONLY`, `MS_NOSUID`, `MS_NODEV`, `MS_NOEXEC` and `MS_SILENT` are taken (the magic
  `0xC0ED` in the high half dropped); any other flag (a remount, a bind, a move) is `EINVAL`. `MNT_DETACH` detaches,
  `MNT_FORCE` is a plain unmount, `MNT_EXPIRE` is `EAGAIN` as Linux answers its first call; a path below no mount point
  is `EINVAL`.
- `statfs` gives a share `SMB2_SUPER_MAGIC` (0xFE534D42), which .NET's `DriveInfo` takes for a network drive; `/etc/mtab`
  names its type `smb3`, as Linux names a mount of `mount -t smb3`.

## 3. witos-volumes

`src/Apps/Volumes`, published by `runtime-services` beside the services as a NativeAOT program (it calls `mount` and
`umount2` of the libc by a direct P/Invoke) and carried by every package of the services at `/usr/bin/witos-volumes`:

```text
witos-volumes                         the volumes and their space
witos-volumes mount //server/share --user USER [--domain DOMAIN] [--as NAME] [--port PORT]
                                      [--password-file FILE] [--read-only]
witos-volumes unmount NAME|/media/NAME [--detach]
```

It resolves a server's name through .NET's `Dns` (musl's resolver), passes the address as `ip=`, reads the password
from its file or asks for it without echo on a terminal, writes the options as `mount.cifs` does, and words each errno
as what it means for a share. The list reads `/etc/mtab` and each volume's space through `DriveInfo`.

## 4. The gate

`runtime-smb` (`RuntimeSmb`, after `runtime-volumes` in `runtime-witos`): the runner starts the host's `smbd`
without privileges (`Host.SambaPeer`, as E2.1's tests start it) on a free loopback port with a share over a directory
of the scenario holding a text, an account of the host's user with a password of this boot, and QEMU's `guestfwd`
puts it at `10.0.2.100:445` (`BootRequest.NetworkShare`). The package carries the services, the .NET install, the
password in `/etc/witos/share-password` and `tests/Runtime.Witos/Share`, an ordinary program the stock SDK publishes
without a RID. `/bin/init` runs:

1. `witos-volumes mount //10.0.2.100/witos --user <user> --password-file /etc/witos/share-password`;
2. `witos-volumes`, whose list shows the share as `smb3` with its size;
3. the program: the mtab line `smb3 rw`, `DriveInfo` a network drive with its sizes, the host's text read, the
   listing, a copy to `/data`, 300,000 bytes written and read back, directories made and a file moved, a file and a
   directory deleted, `FileNotFoundException` and a non-empty directory's `IOException` — `9 of 9 checks passed`;
4. `witos-volumes unmount witos`;
5. the program again, which finds `/media/witos` gone from the tree and `/etc/mtab`.

The scenario requires the endpoint's line, the mount line (SMB 3.1.1 at `10.0.2.100:445`), the command's answers, the
list's row, the checks, the unmount and each command's exit with 0; after the boot the host requires the written bytes,
the moved note and the deleted file's absence in its directory.

The host tests: `NetworkMountTests` reads mount requests and mounts a Samba share through a session of the namespace
(the network connector a `TcpClient`), uses its files, is refused the unmount while a file is open, unmounts, mounts
again under a name of its own read-only and detaches with a file open, which then fails with `EIO`, and each refusal's
errno (no network, the type, a name without `ip`, a wrong password, no such share, the system's alias, an alias taken,
a refused connection); `VolumesTests` reads the command's arguments and writes its options.

## 6. Limits kept explicit

- No notification: a program learns of a volume that came or went by reading `/etc/mtab` again, which the libc makes
  at each open; no program asks more yet (ADR 0032, Consequences: arrival and departure events come with a consumer).
- The service resolves no name; `witos-volumes` does, and another caller of `mount(2)` passes `ip=`.
- Every process may mount and unmount, as every process runs as root (N2.2).
- A share stays mounted until it is unmounted or the system stops; a server that drops the connection leaves a volume
  whose requests fail with `EIO` until it is unmounted and mounted again (E2.1: no reconnection).
- The password travels in the process's memory, the namespace's window and the service; it is never logged, and the
  service keeps it only inside NTLM's computation.
