# K3.1 — Device descriptors and device memory (ABI v58, boot ABI v5)

Plan step K3.1 brings the first half of the device family of [RFC 0011 v3 §7.7](../RFC-0011-Kernel-Architecture-and-ABI.md)
into the kernel: the board's devices as a read-only descriptor table ([RFC 0007 §13–14](../RFC-0007-Universal-Hardware-Interface.md)),
`DEVICE_ACQUIRE` (80) as the authority over one of them and `DEVICE_MEMORY` (81) as the way to its memory regions,
built on the memory objects of K5.1. The kernel learns no device class, protocol or driver: it publishes what the
platform enumerated and mints capabilities on request. Interrupts (`INTERRUPT_BIND`, `INTERRUPT_ACK`) and DMA
(`DMA_PIN`, `DMA_UNPIN`) follow in K3.2 together with the first driver, virtio-blk in user space.

## What changed

**Boot ABI v5: the firmware tables.** `WitBootInfo` (128 bytes) carries the physical addresses of the ACPI 2.0 RSDP
and of the flattened device tree, found by their GUIDs in the UEFI configuration table, zero when absent. The
common kernel never reads either; the platform enumerates from what it understands. The virt board boots with
`acpi=off` so that the firmware publishes the device tree (EDK2 exposes one or the other).

**The platform enumerates.** `wit_platform_devices` fills `WitDeviceDescriptor` records (`witos/device.h`, 232
bytes each): the bus, the function's address, four opaque identity words (vendor and device, class and revision,
subsystem, header type as the bus reports them), up to seven regions (region 0 the function's ECAM configuration
page, then its BARs with their firmware-assigned bases and probed sizes; port BARs are described with the `PORT`
flag and never mapped) and up to two interrupt lines (INTx as the PIC input on q35, as the GIC INTID from the
device tree's interrupt map on virt). q35 walks the bus through configuration mechanism #1 and takes the ECAM base
from the host bridge's PCIEXBAR; virt walks the ECAM window of the device tree's `pci-host-ecam-generic` bridge,
mapping the pages it reads on demand (the window lies above 4 GiB, so device pages may now be anywhere in the
48-bit physical space). PCI-to-PCI bridges are followed to a bounded depth.

**The table is a memory object.** The kernel keeps the table in one page it owns (`WIT_DEVICE_CAPACITY` 16
descriptors) and hands it to a component as a memory object of kind `TABLE`: read-only by rights (`MAP`, `QUERY`,
`DUPLICATE`, `TRANSFER`) plus `ACQUIRE` (32768) for whoever may take devices. Until K4 the kernel test grants it to
the fixture through the test configuration; the root task's startup descriptor will carry it (RFC 0011 §7.11).
Memory objects gained `Owned`: an anonymous object's pages return to the component's quota with the object, the
table's and a device's pages are never the component's.

**`DEVICE_ACQUIRE(table, index, 0)`** checks the handle's `ACQUIRE` right and that the handle is the table, the
index against the count and the descriptor's owner, then mints a device handle (kind `DEVICE` 12; rights `BIND`
65536, `QUERY`, `DUPLICATE`, `TRANSFER`). A device is held by one component at a time: a second acquisition is
`BUSY` until the holder's last handle, in its table or in flight in a channel, is gone; the component's end frees
every device it held. `HANDLE_DUPLICATE` attenuates; the handle moves through a channel with `TRANSFER`, and a
dropped message gives the device back.

**`DEVICE_MEMORY(device, region, 0)`** needs `BIND`, a region index within the descriptor and a memory region (a
port region is `UNSUPPORTED`, a region beyond 64 pages `TOO_LARGE`); it returns a memory object of kind `DEVICE`
over the region's physical pages, with `MAP`, `WRITE`, `QUERY`, `DUPLICATE` and `TRANSFER` but never `EXECUTE`. A
mapping of it is an alias with the new page flag `WIT_PAGE_DEVICE`: PAT entry 3 (UC, verified when paging starts)
on x64, the device-nGnRnE attribute index on ARM64; `MEMORY_PROTECT` keeps the flag and stays within the rights,
`CODE_PUBLISH` and an executable protection are refused by the rights, commit, decommit and reset are `DENIED` as
on every mapping of an object.

**`QUERY`** now reports `DEVICES` in the feature mask.

## Kernel

- `device.h` (ABI: the table header, descriptors, regions, lines), `devices.h`, `devices.c`: the table page, its
  validation of what the platform published, one owner token per descriptor.
- `user_device.c`: the table grant, the two calls, the device handle's close, duplication, transfer and the
  component's reset; `user_memory_object.c`: adopted objects (`wit_user_memory_object_adopt`) and the uncached
  mapping of a device object; `user_space.c` and the architectures' page entries: `WIT_PAGE_DEVICE`.
- `Kernel.Platform.Q35/devices.c`, `Kernel.Platform.QemuVirt/devices.c`: the enumeration of each board; the virt
  platform parses the flattened device tree itself, the common kernel never does.
- `Boot.Uefi/entry.c`: the configuration table scan for the RSDP and the device tree.

## Fixtures

`tests/User.X64/devices.asm` and `tests/User.A64/devices.asm`, driven by the common `tests/Kernel/user_device_tests.c`
in two modes. `User.DeviceTable`: the table mapped read-only (writable and executable views refused by the rights),
the virtio block function found by its identity (vendor `1AF4`, device `1001`: the fixture's knowledge, not the
kernel's), acquired, its configuration region mapped through `DEVICE_MEMORY` and read back with the same identity
words, a writable view allowed, an executable view, commit and an executable protection refused, the region
outliving the device handle and the view outliving the object's handle. `User.DeviceAuthority`: a table handle
without `ACQUIRE` is `DENIED`, bad indexes and reserved arguments are `INVALID_ARGUMENT`, a second acquisition is
`BUSY`, a port region is `UNSUPPORTED`, a device handle without `BIND` is `DENIED` but keeps the device held, and the
device moves through a channel: held in flight, usable once received, free again when a dropped message carried
it. After every mode the kernel checks that no handle, object, mapping, alias or page survived and that every
descriptor is free again. The kernel self-test prints the table it published.

## Limits kept explicit

- The table has one page and 16 descriptors; a board with more devices is truncated, which the kernel reports as
  the count it published.
- Regions are published as the firmware assigned them; the kernel never programs a BAR, a bridge window or a
  command register. Port I/O is described, never mappable.
- Interrupt lines are described only; binding them to events is K3.2. DMA, and the `PIN` right, are K3.2.
- The authority to acquire is the table handle's `ACQUIRE` right, handed out by the kernel test until the root task
  (K4) receives it in its startup descriptor; there is no second holder, no sharing and no revocation beyond the
  holder's last handle.
- Device memory is mapped uncached only; write-combining and prefetchable attributes are not offered.
