# K8.3a — mechanism fixtures in C

Plan step K8.3 builds the self-test kernels' mechanism fixtures without MSVC and without the frozen line's forms.
Before it, each of the twelve fixtures was written twice, in MASM for x64 and armasm for ARM64, and linked by MSVC's
linker as a PE whose code page the tool cut out.

K8.3a carries nine of them over:

| Fixture | Kernel self-test |
| --- | --- |
| `processors` | `User.ProcessorsAndAffinity` |
| `devices` | `User.DeviceTable`, `User.DeviceAuthority` |
| `interrupts` | `User.InterruptBind`, `User.DmaPin` |
| `virtio` | `User.VirtioBlock` |
| `exceptions` | `User.ExceptionCallbackAndContext`, `User.ExceptionReject` |
| `memory_objects` | the five `User.MemoryObject*` markers |
| `channels` | the five `User.Channel*` markers |
| `threads2` | `User.ThreadFormAndTransport` |
| `processes` | `User.ProcessLifecycle` |

Each is now one C source for both ISAs. `entry`, `threads` and `waits` remain for K8.3b.

## The fixture form

A fixture is `tests/User/Fixtures/<name>.c`.

**Build.** The pinned clang compiles it for the layer-2 triple: freestanding, `-Os`, the ABI-1 transport of
`witos/syscall.h`. lld links it by `tests/User/Fixtures/fixture.ld` at `WIT_USER_CODE`. The tool
(`UserImage.BuildClangFixturesAsync`) refuses any image that is not exactly one executable segment there, starting with
its entry. A fixture has no writable data: its state lives in the component's data page at fixed offsets. The status of
a failed check is at 1304 and the count of checks at 1312, which the kernel self-tests read as before.

**Shared helpers.** `tests/User/Fixtures/fixture.h` holds:
- the counted call (`fixture_expect`) and checks;
- object mappings and channel messages, duplicates and waits;
- the device table's search;
- a device barrier;
- the threads of the one form: `fixture_thread_create` reserves and commits a stack, the thread's exit names it for the
  kernel to release, and `fixture_join` waits, reads the exit code and closes the handle.

The frequent helpers stay calls (`noinline`), so that a fixture stays small.

**Assembly.** A fixture writes assembly only where C cannot say the thing tested:
- the fault sites and landings of the exception fixture, with a marked register the record must show and the
  continuation changes;
- a stack pointer with no room below it;
- a system call made on the alternate stack;
- the entry points of `threads2`, which hand C the registers the kernel set: on x64 the argument in both RCX and RDI,
  and the exact stack pointer;
- the child program of `processes`, which runs from a copy in another process. It is position-independent, and its call
  numbers are constants that `_Static_assert` ties to ABI-1.

The kernel's entry convention for the fault callback is the Microsoft one on x64, which the C callback declares with
`ms_abi`.

**The calls.** The fixtures call the kernel through SYSCALL with the SysV registers on x64 and SVC on ARM64, as layer 2
does. The older MASM fixtures used `INT 0x80` with the Microsoft registers.

**Threads.** The channel fixture's threads now use the one form. They were version 1 threads on the kernel's stacks.

**The 4-byte form of `PROCESSOR_QUERY`.** The processor fixture no longer uses it. It is the frozen line's form, and it
leaves the kernel at K8.4.

## The code window

A fixture compiled from C is larger than its hand-written assembly. The channel fixture took 4,720 bytes on ARM64,
where the old one fit 4,048 with tricks. `wit_user_create` used to map a single code page. It now maps the code window
of a fixed component: the pages from `WIT_USER_CODE` up to the startup block at `WIT_USER_INFO`, three pages at most. It
copies them one by one, since the pages need not be contiguous in physical memory.

## Tests

The fixtures report the same markers as before, and the kernel self-tests are unchanged. On both ISAs:
- the virtio driver reads the boot sector through the bound interrupt;
- the exception fixture takes and continues its two faults and its activation;
- the channel fixture's waits park and wake.

The results:
- `format-check` and the host tests pass;
- `test`: all 27 x64 scenarios pass;
- `test --arch arm64`: all 21 foundation scenarios pass.

## Limits kept explicit

- **Three fixtures still need MSVC.** `entry`, `threads` and `waits` stay in MASM and armasm until K8.3b: preemption
  state, version 1 threads, the raw TLS block, guard pages of the kernel's stacks. The PE fixtures (`image`,
  `bootstrap`, `compiler_tls` and the library fixtures of the host harnesses) stay until K8.4 with the PE loader.
- **The first thread.** A fixture's first thread is still the kernel's version 1 form, with its stack at
  `WIT_USER_STACK_BOTTOM` and the startup block at `WIT_USER_INFO`. The new first-thread form is K8.4's.
