# P1.5 checked console output and processor discovery

User ABI v23 adds a versioned console-write descriptor and an atomic four-byte processor query. Native GetStdHandle, GetConsoleOutputCP, WriteFile and GetCurrentProcessorNumberEx direct/import bindings use the actual source-built adapter objects; imports are readonly and no Windows implementation library is linked into the guest.

The standard output/error handles are the captured startup console capability. They are unavailable before image publication and remain subject to live kernel rights checks on every write, including after close. The serial stream uses UTF-8 bytes; changing codepages, input handles, disk handles and overlapped I/O are not implemented by this bootstrap profile.

The console descriptor carries a caller-owned completion DWORD. The kernel validates that entire destination before clearing it. It then validates the console capability, bounded request size and complete readable source range before emitting any console data. Invalid input never emits a prefix or partial payload; a valid completion DWORD reports zero on failure. Invalid completion ranges receive no partial write. Data is emitted synchronously in internal chunks while mappings are serialized, and the completed count equals the entire requested length. The 65536-byte work quota is explicit: oversize requests fail rather than report successful short output. CoreLib Internal.Console.WriteCore does not retry short writes, so this distinction is required by the reached startup path.

Processor discovery reports the kernel's actual sole-online-CPU profile: group 0, number 0, reserved zero. The kernel checks exact size/reserved arguments and the full writable range before copy-out, with IF disabled. A future unsupported topology is rejected. The native void API fails fast if the kernel cannot produce a complete result, preserving all destination bytes on failure. Native last-error is unchanged on success; errno remains independent.

Tests cover publication prerequisites, UTF-8, direct/import equivalence, a multi-chunk write, exact maximum write, empty output, invalid/closed handles, unsupported flags/modes, invalid source and completion page tails, readonly imports, cross-page successful completion, cross-page processor rejection, invalid processor size/selector, void fail-fast, workers and execution without compiler TLS. Kernel write counters independently reject unnoticed output from failed cases; teardown recovers owned pages and handles.

Validation passed: Release build, 20 boot scenarios, source audit/hosted probe, target/source/reference/readiness and four runtime-config profiles with 231 user groups and 54 expected contained faults each. Full native archive: 111 members; configuration archive: 31 objects. Minimal/broad strict boundaries: 39/45 unresolved symbols. The compact thread/console fixture remains within the existing loader limits (21504 bytes, 60 unwind records). This supplies native console/processor services, not managed Console execution, filesystem support or SMP.
