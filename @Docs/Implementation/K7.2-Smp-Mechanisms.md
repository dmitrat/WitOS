# K7.2 — SMP mechanisms (ABI v64)

Plan step K7.2 is the mechanical half of the SMP groundwork of [RFC 0011 v3 §7.9](../RFC-0011-Kernel-Architecture-and-ABI.md):
the kernel starts every processor the table of K7.1 names, addresses them with inter-processor interrupts and waits
for their acknowledgements, and `PROCESS_WRITE_BARRIER` (94) fences every online processor instead of refusing a
topology with more than one. The scheduler stays on the boot processor: a secondary processor idles with its
interrupts enabled and serves the kernel's requests alone, and no thread runs on it until phase P. `QUERY` reports the
family `SMP` (16) in the feature mask; the version is 64. The call-by-call reference is [ABI-Reference.md](ABI-Reference.md).

## What changed

**Per-processor state.** `cpus.c` keeps one record per processor of the table (state offline, starting, idle or boot;
hardware identity; the counts of acknowledged fence and invalidation requests; the address of the invalidation in
flight). `wit_cpus_initialize` runs after the processor table and the clocks with interrupts disabled: for every
processor but the first it asks the architecture to prepare the processor (`wit_arch_secondary_prepare`) and to start it
(`wit_arch_secondary_start`), then waits up to two seconds of monotonic time for the processor to report itself idle
(`wit_cpus_secondary_ready`) and panics otherwise — an unstarted processor is a defect, not a degraded mode. When all
are up the table of K7.1 marks every processor `ONLINE` and the boot log says `Processors present/online: N/N`.

**Requests.** `wit_cpus_fence_all` sends the fence interrupt to every idle processor in turn and waits up to one
second for each acknowledgement; `wit_cpus_invalidate_all(address)` does the same with the invalidation interrupt
after publishing the address in the target's record. One request is in flight at a time, the sender waits, and a lost
interrupt is a panic. A secondary processor's handler (`wit_cpus_ipi_received`) identifies itself by
`wit_arch_processor_id`, fences, invalidates its own translation of the published address when asked
(`wit_arch_invalidate_local`) and counts the acknowledgement. The kernel has no queue of requests and no other kind.

**ARM64 (virt).** The boot processor records MAIR, TCR, TTBR0, TTBR1, SCTLR and CPACR, gives each processor a kernel stack
of the architecture's size, lets the platform enable the distributor's affinity routing and group 1 forwarding (once,
before the first start; the timer start did it alone until now), enable its own CPU interface and map the processor's
redistributor frames (`WIT_VIRT_GICR_BASE + index * 0x20000`, the SGI frame 0x10000 further, checked against
`GICR_TYPER`'s affinity) and starts the processor through PSCI
`CPU_ON` (`hvc #0`, function 0xC4000003, the kernel's number as the context). The entry of `secondary_entry.asm`
installs the recorded registers (CPACR among them: the vectors save the SIMD registers, and a processor with FP/SIMD
trapped would take the trap inside the vector without end), invalidates its TLB, points VBAR at the shared vector
table, takes its stack and enters `wit_a64_secondary_main`, which checks SCTLR and CPACR against the boot processor's,
wakes its redistributor, enables SGIs 0 and 1 through the platform
(`wit_platform_processor_interrupts_enable`), publishes its features and cache, reports itself ready and waits for
interrupts in WFI. The platform sends SGI 0 for a fence and SGI 1 for an invalidation through ICC_SGI1R_EL1
(`wit_platform_ipi`); the interrupt path recognises an INTID below 16 as an inter-processor interrupt
(`wit_platform_interrupt_claim` returns 3) and completes it (`wit_platform_ipi_complete`). The SPIs of devices keep
their route to the boot processor.

**x64 (q35).** The boot processor maps the local APIC page (`wit_arch_map_device_page`), enables the APIC in xAPIC
mode (MSR 0x1B bit 11, spurious vector 0xFF, the timer and error vectors masked, LINT0 as ExtINT so that the PIC's
tick keeps arriving, LINT1 masked) and refuses x2APIC. It claims the lowest usable page between 64 KiB and 1 MiB from
the page allocator for good (`wit_page_claim`) and copies the trampoline into it: hand-encoded code that leaves real
mode through a private GDT, enables PAE, loads the kernel's root table (which must lie below 4 GiB), sets LME and NXE,
enables paging and jumps to the 64-bit entry of `secondary_entry.asm` with the processor's stack and number; the page
is made executable in the kernel's tables for that last stage. A processor starts with INIT, 10 ms, and two start-up
interrupts naming the page. The entry loads the kernel's GDT and IDT (`wit_x64_tables`) without a task register,
reloads the selectors and enters `wit_x64_secondary_main`, which copies the boot processor's CR0 and CR4, enables its
own APIC with every local vector masked, publishes its features and cache, reports itself ready and halts with
interrupts enabled. The inter-processor interrupts are vectors 0xF0 (fence) and 0xF1 (invalidation), sent through the
interrupt command register to the processor's APIC id and served by `wit_x64_ipi_entry` with the device entry's frame;
the handler acknowledges to the kernel and to the APIC. `wit_platform_timer_start` disables the APIC only while the
boot processor is alone online, as before; with secondary processors it stays on and the PIC's line enters through
LINT0.

**`PROCESS_WRITE_BARRIER`.** The call fences the calling processor and then every other online processor through the
fence request; it reports success only after every acknowledgement. The single-processor refusal is gone. The rest
of the frozen line keeps its single scheduling processor: `CPU_CACHE_SIZE` (208), the context and suspension calls
ask `wit_processors_scheduling()`, which is 1 until phase P, and `ProcessorCount` of `MEMORY_INFO` and `THREAD_INFO`
reports the processors a process's threads run on — one — while `PROCESSOR_QUERY` reports the processors online.

## Kernel

- `witos/cpu.h`, `cpus.c`: the per-processor records, start, requests and acknowledgements; `kernel.c`: the start
  after the processor table; `processors.c`: `wit_processors_report`, `wit_processors_set_features`, the online count
  from `cpus.c`, `wit_processors_scheduling()`; `user_abi.h`: v64, the `SMP` family in the mask.
- `witos/arch.h`: `wit_arch_secondary_prepare`, `wit_arch_secondary_start`, `wit_arch_ipi`,
  `wit_arch_invalidate_local`; `witos/platform.h`: `wit_platform_processor_prepare`,
  `wit_platform_processor_interrupts_enable`, `wit_platform_ipi`, `wit_platform_ipi_complete`.
- `Kernel.Arch.A64/secondary.c`, `secondary_entry.asm`; `Kernel.Platform.QemuVirt/interrupts.c`, `gic.asm`, `virt.h`
  (the redistributor stride and SGI frame); `Kernel.Arch.A64/scheduler.c`: the inter-processor claim.
- `Kernel.Arch.X64/secondary.c`, `secondary_entry.asm`; `entry.asm`: vectors 0xF0 and 0xF1; `exceptions.c`:
  `wit_x64_tables`; `paging.c`: `wit_x64_page_executable`; `Kernel.Platform.Q35/interrupts.c`: the APIC kept with
  secondary processors, the empty per-processor hooks.
- `witos/memory.h`, `memory.c`: `wit_page_claim`, `wit_physical_pages`.
- `user_calls.c`: the barrier; `user_space.c`, `user_reference.c`: `ProcessorCount` as the scheduling count.

## Tests

`tests/Kernel/smp_tests.c` (`Smp.Online`, `Smp.Ipi`; both foundations, any processor count): every present processor
is online in `cpus.c` and in the table, its identity finds its number, two fence requests and one invalidation request
are acknowledged exactly once each by every secondary processor. `tests/Kernel/processor_tests.c` accepts an online
secondary processor with features and cache. `boot-smp2` on both boards requires `Processors present/online: 2/2`
besides every marker of the self-test kernel, so the frozen line's fixtures run with a second processor online and
the barrier of every component fences it.

## Limits kept explicit

- The scheduler stays on the boot processor: a secondary processor runs no thread, takes no system call and no
  user fault, and `THREAD_AFFINITY` still refuses placement elsewhere. Phase P brings the scheduler of N processors.
- One request is in flight at a time and the sender spins for the acknowledgement with a one-second bound; the
  invalidation request carries one page. The paths that change translations do not send it yet, since no translation
  is live on a secondary processor; the mechanism is exercised by the self-test alone.
- A secondary processor must not fault: on x64 it loads no task register, so a double fault there has no stack; a
  kernel exception on a secondary processor is a panic like any kernel exception.
- The trampoline page stays claimed and executable below 1 MiB for the kernel's life; the kernel's root table must
  lie below 4 GiB; xAPIC physical destinations limit APIC ids to 255; x2APIC mode is refused.
- Eight processors at most, with a static kernel stack each; no processor is stopped once started, and PSCI's version
  and the firmware's parking protocol are not queried.
