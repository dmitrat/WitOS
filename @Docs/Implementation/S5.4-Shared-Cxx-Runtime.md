# S5.4 — the shared C++ runtime and the acceptance of phase S

Plan step S5.4 shares the C++ runtime of S4 between the modules of a process and closes the ELF loader of S5 with the
acceptance phase S names: a dynamic program with threads, a C++ exception and a signal on both ISAs
([RFC 0011 v3 §9.1, §9.3](../RFC-0011-Kernel-Architecture-and-ABI.md)). It needs one kernel quota, the reservation
table of the system layer's processes; ABI-1 stays at v68.

## What changed

**The shared runtime (`LlvmRuntimes.BuildSharedAsync`).** The sources and options of the static libraries of S4 are
compiled again position-independent and linked as shared libraries with their sonames, as the runtimes' CMake links
them for Linux. `libunwind.so.1` stands alone, `libc++abi.so.1` links on libunwind, and `libc++.so.1` links on
libc++abi and on libunwind, whose `_Unwind_Resume` its cleanups call. All three sit in the package's `/lib` beside
musl's dynamic linker.

**The start object of a dynamic image (`crtbeginS.o`).** C++ code passes its module's `__dso_handle` to
`__cxa_atexit`, so every module needs its own, hidden. As clang's driver does for Linux, every shared library and
dynamic program now starts with compiler-rt's `crtbegin.c`, pinned by hash. It is compiled as compiler-rt's CMake
compiles its CRT objects for a target with init and fini arrays, position-independent, and without the frame registry,
since every image carries `.eh_frame_hdr`. Static programs keep `static.ld`'s `__dso_handle`.

**The builtins.** libc++'s filesystem clock divides 128-bit integers, and `libc++.so` links whole, so `divti3.c`,
`udivti3.c`, `modti3.c`, `umodti3.c` and `udivmodti4.c` join the compiler-rt pin.

**The reservation table (`WIT_PROCESS_RESERVATION_CAPACITY`).** The root task and the processes it creates get 256
reservations; the frozen line's full profile keeps 32. Every space's arrays are sized by the larger table, which
adds a few KiB to each static process record. S5.3 measured 21 of 32 for a dynamic C program with two small
libraries. Here `std::thread` failed with `EAGAIN` at 32: the stack of a second thread found no free reservation
beside the shared runtime's mappings. The acceptance program ends holding 32, and more while its threads run. The root
task's fixture checks the capacity through `MEMORY_QUERY`.

## The acceptance of phase S

`tests/User/acceptance_main.cpp` (12 checks) and its library `lib/libacceptance.so`
(`tests/User/acceptance_library.cpp`, interface `tests/User/acceptance.h`) run over the shared runtime. The library's
exception type has its key function in the library, so its type information is the library's. The program checks:

- the program catches the library's exception by its own type, by `std::runtime_error` (with a `dynamic_cast` back)
  and by `std::exception`;
- the program's own exception unwinds through a library frame, which runs the destructor of the object it holds;
- two `std::thread`s each throw and catch across the modules and keep their own copy of the library's
  `thread_local` object, and libc++abi destroys both at the threads' exits;
- an `exception_ptr` carries the library's exception from a thread to the main thread;
- strings the library allocates are freed by the program;
- a write to an unmapped page raises SIGSEGV, whose handler leaves with `siglongjmp`.

The C++ scenarios of S4 (`tests/User/cxx_main.cpp` with `tests/User.X64/cxx_exceptions.cpp`) also run as a dynamic
program, `/bin/cxx`, over the shared runtime. They produce the same Itanium trace the static `cxx` scenario and CI's
native Linux build require, and 21 of 21 checks pass. The root task of the `spawn` scenario starts both and requires
exit code 0; the suite requires their last lines. The root task makes 47 checks on both ISAs.

## Limits kept explicit

- The shared runtime is one build of the pinned release; there is no symbol versioning and no ABI promise beyond it.
- Exceptions cross modules through one libc++abi and one libunwind per process; a module with its own static copy of
  the runtime is not supported.
- The frame registry of `crtbegin.c` is off: unwinding finds frames through `dl_iterate_phdr` and `.eh_frame_hdr`
  alone, and an image without `--eh-frame-hdr` cannot be unwound.
- 256 reservations bound a process's mappings and threads, and each mapping still costs one (S5.1, S5.3).
- What phase S has left: the process manager and the console as a capability (S6), the substrate acceptance suite
  (S7).
