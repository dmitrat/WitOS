# K5.2a — The one thread form and the x64 transport (ABI v60)

Plan step K5.2a takes the thread half of K5 ([RFC 0011 v3 §7.3](../RFC-0011-Kernel-Architecture-and-ABI.md)) and the
x64 transport of [§6.1](../RFC-0011-Kernel-Architecture-and-ABI.md): a thread's stack and TLS belong to the caller,
`THREAD_EXIT` returns the stack's reservation to the component once the thread no longer runs on it,
`THREAD_SET_TLS` (33) moves the raw TLS base where the ISA lets the kernel do it, and x64 system calls travel through
`SYSCALL` with the SysV registers. Processes beyond the one slot pair, `PROCESS_CREATE` and mapping into another
process are K5.2b. The frozen Windows-form user space keeps everything it had: version 1 of `THREAD_CREATE` with
the kernel's stacks and TLS pages, and `INT 0x80`, until K8 removes them.

## What changed

**Version 2 of `THREAD_CREATE`.** `WitThreadCreateRequest2` (48 bytes, the size of version 1) carries the entry,
the argument, the stack pointer and the TLS base. The kernel validates the whole request before it publishes
anything: the size and the flags (`SUSPENDED` alone), a 16-byte aligned stack pointer strictly inside a committed
writable reservation of the caller, whose bounds become the thread's `StackBottom` and `StackTop`, a TLS base in
user space or zero, an executable entry, a free thread slot, a free reference record and two free handle slots. It
maps no stack, no raw TLS block, no compiler TLS page, no library TLS: the thread starts with its stack pointer
exactly as given and its argument in both entry conventions (RCX and RDI on x64, X0 on ARM64). The return
validation of every trap accepts an empty stack whose pointer sits at the reservation's top and probes the page a
push would write, so a thread may start at the very end of its stack. The kernel's
stacks and TLS pages, the raw TLS block with the self pointer, handle and argument, the compiler TLS and the
library TLS remain version 1's, which `wit_user_prepare_thread` and the frozen line use.

**`THREAD_EXIT(code, reservation, 0)`.** A nonzero second argument names a reservation of the caller, checked
before the exit as exactly a reservation base (`NOT_RESERVED` returns otherwise; a version 1 thread may not name
one). The kernel records it on the exiting thread and releases it at the reap, on its own stack, after the
thread's handles learned the exit: what musl's `__unmapself` needs. A version 1 thread's kernel stack and TLS are
reaped as before; a version 2 thread's exit frees nothing it does not own.

**`THREAD_SET_TLS(base, 0, 0)`.** On x64 the current thread's raw TLS base (FS) changes from its next return to
user mode, through the dispatcher that already loads FS and GS per thread. On ARM64 the call is `UNSUPPORTED`:
TPIDR_EL0 is the thread's own register, written at EL0 and saved and restored in the frame by the kernel, while
TPIDRRO_EL0 carries the TLS base a version 2 request named.

**`SYSCALL` on x64.** `wit_x64_enable_syscall` sets EFER.SCE, STAR (kernel CS 8 and SS 0x10; the SYSRET base 0x23
that names SS 0x2B and CS 0x33), LSTAR and SFMASK (IF, TF, DF and AC cleared on entry). The entry
(`wit_x64_syscall_entry`) saves the caller's RSP, loads the selected thread's kernel stack, which
`wit_x64_set_kernel_stack` keeps beside TSS.RSP0, pushes SS, RSP, RFLAGS from R11, CS and RIP from RCX, then the
general registers and the FXSAVE image exactly as the interrupt gate's entry does, and calls the dispatcher with
RAX, RDI, RSI and RDX. The frame is the gate's, so `validate_return`, the dispatcher and the IRETQ restore path
serve both transports; the instruction clobbers RCX and R11, which the ABI documents. `INT 0x80` with RCX, RDX
and R8 stays for the frozen line.

## Kernel

- `thread_reference.h`: version 2 and its request. `user_thread.c`: `create_on_caller_stack`,
  `wit_user_thread_set_tls`. `user.c`: the reap frees owned pages or releases the named reservation;
  `wit_user_exit_thread` takes the reservation. `user_calls.c`: `THREAD_EXIT`'s check, `THREAD_SET_TLS`.
  `user_space.c`: `wit_user_space_reservation_bounds`.
- `arch.h`: `wit_arch_frame_create_at`, `wit_arch_user_tls_settable`. `Kernel.Arch.X64/frame.c`: the frame
  builder with RDI, the SysV dispatcher, the MSRs; `exceptions.c`: the kernel stack for `SYSCALL`;
  `user_entry.asm`: the entry. `Kernel.Arch.A64/frame.c`: the frame at an exact stack pointer.

## Fixtures

`tests/User.X64/threads2.asm` (every call through `SYSCALL`) and `tests/User.A64/threads2.asm`, driven by
`tests/Kernel/user_thread2_tests.c` (`User.ThreadFormAndTransport`): the startup argument in both conventions
(x64), `QUERY` over the new transport, `THREAD_SET_TLS` observed through FS (x64) or refused (ARM64), a 64 KiB
reservation committed as a stack, the refusals of version 2 requests (a stack pointer in a fixed mapping, a
foreign version, a flag, a TLS base outside user space, a misaligned stack pointer) and of an exit naming a
non-reservation, then a worker on the fixture's stack with its TLS base: it checks its argument, its exact stack
pointer, writes to its stack, reads its TLS base (FS on x64, TPIDRRO_EL0 on ARM64), changes its TLS (x64) or
writes TPIDR_EL0 and sees it preserved across a yield (ARM64), and exits naming the reservation; the creator
joins it and finds the reservation gone. The kernel checks one creation and one reap, no reservation left and
no page leaked.

The frozen line's native thread fixture checked that a version 2 request was foreign; it now checks version 3, the
one adjustment the frozen code needed.

## Limits kept explicit

- Threads still live in the component's four slots with kernel stacks per slot; N processes, kernel stacks from
  pages and `THREAD_CREATE` into another process are K5.2b.
- The stack pointer must lie in a reservation of the caller: stacks in memory objects mapped from elsewhere wait
  for K5.2b's process model; guard pages and on-demand commitment are the caller's to arrange with the memory
  calls.
- `SYSRET` is not used; both transports return through IRETQ.
- `THREAD_SET_TLS` sets FS alone; the compiler TLS (GS) stays the kernel's for version 1 threads and zero for
  version 2 threads.
