# S6.2 — the current directory and the standard streams

Plan step S6.2 closes S6 ([RFC 0011 v3 §9.3](../RFC-0011-Kernel-Architecture-and-ABI.md)). The current directory
now lives in the libc, as on POSIX, and a process starts in the directory its creator names. The standard streams are
the log capability, one descriptor at a time, and `posix_spawn`'s file actions change what a child starts with. Its
tests found a kernel defect: a call could make the kernel read the boot package through a mapping it does not have.
The fix is part of the step. ABI-1 stays at v68.

## What changed

**The current directory (`src/Substrate/libc/files.c`).** The libc keeps the directory as a package name prefix. A
relative path joins the current directory, or the directory a descriptor names, and is normalized together with it,
so `..` climbs out of it. A directory descriptor's `..` used to fail with `ENOENT`, and `normalize` left a separator
behind a removed name. `chdir` and `fchdir` accept a directory of the package (`ENOTDIR`, `ENOENT` otherwise), and
`getcwd` reports it.

**The start message, version 3 (`witos/start.h`), and the spawn request, version 2 (`witos/manager.h`).** Both now
carry the initial directory (an absolute path of at most 232 bytes, after the structure in the message) and the
standard descriptors the process starts without. The loader resolves the directory through the libc before
`PROCESS_CREATE`, so a missing directory is refused before anything exists.

**The standard streams.** Descriptors 1 and 2 write to the kernel log, and descriptor 0 reads the end of input,
unless the start message or a `close` took them away. A closed standard descriptor is `EBADF` for every call, and it
stays closed. The log capability itself always arrives, since the libc's last-resort diagnostics write to it.

**posix_spawn's file actions (`src/Substrate/libc/process.c`).** A child starts in the caller's directory with the
caller's standard streams. The actions change them in the order a child would apply them: musl keeps the list newest
first, so the libc walks it from the tail.

- `addchdir_np` and `addfchdir_np` move the child's directory.
- `addclose` of a standard descriptor leaves the child without it; a close of any other descriptor does nothing, since
  a child inherits none.
- `adddup2` between standard output and error binds one like the other.

A relative program path names the program from the child's directory, as `exec` after the actions would. A file or a
pipe as a stream (`addopen`, a `dup2` of another descriptor) is `ENOSYS`.

**The kernel's view of a call's buffer (`wit_virtual_view`).** A literal a program writes with `write(1, …)` lies in
its read-only segment, which the loader maps from the package's own pages. `DEBUG_WRITE` copied it through the
identity map, which covers usable memory and the kernel image but not the boot package, and the kernel panicked. Each
architecture now gives a kernel view of a physical page: the identity map for what it maps there, and the storage
window for a page of the package, which is the only kernel mapping of the package. The copies to and from user memory
and their validations go through that view. A device region's page (`WIT_PAGE_DEVICE` in the user's entry) is never a
call's buffer, even where the kernel maps the region for itself (the configuration space ECAM shows on the virt
board): the validation refuses it with `BAD_ADDRESS` before any state changes. ARM64's code publication cleaned the
data cache through the identity address of a package page, which TCG does not check; it uses the same view now.

## Tests

- The `process` scenario of both suites: `/bin/init` makes 65 checks. Beyond S6.1's checks they cover:
  - the initial directory and `chdir`, including relative paths, `..` and a relative `chdir`;
  - the refusals of a file and a missing directory, `fchdir`, and `openat` through `..` of a directory descriptor;
  - a child in the inherited directory, a child moved by `addchdir_np`, and one moved by `addfchdir_np` and started
    by a relative program path;
  - a child with both streams, without standard output, and with its error rebound to the output;
  - the refusals of a descriptor and a file as a stream;
  - `close(0)` of the own input and its `EBADF`, and a child that inherits the closed input.
- The root task fixture (`tests/User/root.c`, both suites) sends the package's magic over a channel straight from a
  mapping of the package and receives it intact: the kernel reads it through the storage window.
- The device fixtures of both ISAs pass a request that lies in the mapped configuration space of the virtio function
  to `MEMORY_OBJECT_MAP` and require `BAD_ADDRESS`.

## Limits kept explicit

- No files or pipes as standard streams, and standard input is the end of input or closed.
- A closed standard descriptor is not reused: `open` returns descriptors from 3.
- `/dev` is no directory for `chdir`.
- The directory a start message names is at most 232 bytes long.
