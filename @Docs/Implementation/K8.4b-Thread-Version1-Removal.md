# K8.4b — version 1 threads, raw and compiler TLS leave

[K8.4a](K8.4a-Policy-Calls-Removal.md) removed the kernel policy of RFC 0011 §8. What was left of the Windows-form
thread model was the version 1 form of `THREAD_CREATE` and everything it carried:

- the kernel's stack and TLS windows;
- the raw TLS block (a self pointer, the thread handle, the argument and the last error);
- compiler TLS (GS on x64, x18 on ARM64, which the kernel reset on every return to user mode);
- the native thread id;
- the `INT 0x80` transport with the Microsoft argument registers.

K8.4b removes all of these. ABI v71.

## ABI

- **Version 1 of `THREAD_CREATE` is retired.** Its request (`WitThreadCreateRequest`, with a stack size and a native-id
  output) is gone, and a version 1 request is now `UNSUPPORTED`. The call takes `WitThreadCreateRequest2` (48 bytes, the
  caller's process) or `WitThreadCreateRequest3` (56 bytes, a process the request names).
- **`WitUserThreadInfo` is version 5, 72 bytes.** `RawTls` becomes `TlsBase`. `CompilerTls`, `CompilerTlsHeader` and
  `NativeId` are gone. The libc reads `ThreadId` and the stack bounds, and the fixtures read `State` and `ExitCode`; all of
  these stay.
- **The raw TLS block's constants** (`WIT_TLS_SELF_OFFSET` and the others) are gone.
- **The x64 transport is `SYSCALL` alone.**
  - Vector 0x80 is no longer a user gate: an `INT 0x80` from user mode is a general-protection fault.
  - A thread's argument arrives in RDI only.
  - The fault callback still receives its token, vector and address in RCX, RDX and R8. The libc and the fixtures
    enter it in that convention, and K8.4b leaves it alone.
- **x18 on ARM64 is the thread's register.** The kernel saves and restores it like any other. A context reads and writes
  it like the other general registers.
- **The user GS base on x64** is always zero.

## Kernel

- **The first thread.** A component's first thread (a fixture's or the root task's) is the only thread the kernel builds
  itself, in `wit_user_prepare_thread`:
  - its stack is the fixed window `WIT_USER_STACK_BOTTOM`–`WIT_USER_STACK_TOP`, mapped page by page, and rolled back
    page by page if a page cannot be had;
  - it has no TLS page and no TLS base.

  `WIT_USER_TLS` and `WIT_USER_THREAD_STRIDE` leave `user_layout.h`. A component therefore owns one page fewer: the
  self-test accounting checks `8 +` stack pages where it checked `9 +`.
- **Every other thread is of the one form.** It may take any slot below the process's `ThreadLimit`.
- **The thread record** loses `NativeId` and `CompilerTls`.
- **`wit_arch_set_user_tls`** takes the TLS base alone:
  - on x64 it writes the FS base and sets the GS base to zero;
  - on ARM64 it writes TPIDRRO_EL0;
  - `wit_a64_prepare_resume` no longer writes x18.
- **x64 entry code.** The `INT 0x80` stub and its handler are gone. Vector 0x80 is an ordinary DPL0 vector, and
  `build_frame` sets RDI alone.

## Tests

- **`threads2`** checked that a thread's argument arrived in both RCX and RDI. It now checks RDI alone, on the first
  thread and on its worker.
- **The kernel's thread self-test** no longer creates version 1 threads. `User.ThreadCreationRollback` now checks four
  things:
  - a version 1 request is refused;
  - the handle and the identity of a version 2 creation are both checked before either is granted, with one handle slot
    left as with none;
  - a refused creation changes no handle, page or count;
  - with the slots back, the creation succeeds on the test's stack reservation and takes no page.
- **`User.NativeThreadIdExhaustion`** leaves both suites, with the native id.
- **A tool fix.** The libc build's stamp did not cover the ABI-1 headers. After `thread_info.h` changed, a stale `libc.a`
  kept sending version 4 queries and the local `libc` scenario failed in `pthread_create`. The stamp now hashes every
  header of `src/Kernel/include` and `src/Sysroot/include`. CI builds fresh, so it never saw the stale library.

Results:

- `format-check` and the host tests pass.
- `test`: all 27 x64 scenarios pass.
- `test --arch arm64`: all 21 scenarios pass.

## Limits kept explicit

- **`-ffixed-x18`.** Layer 2 and the runtime's toolchain patch still reserve x18 on ARM64. The register is free now, but
  freeing it means rebuilding the .NET runtime. That moves to K8.4d with ABI-1 1.0.
- **The first thread's form.** It still runs on the kernel's stack window and starts with `WitUserStartup` at
  `WIT_USER_INFO`. K8.4c gives it its final form.
- **The x64 fault callback** keeps the Microsoft argument registers. Changing them would change every handler in layer 2.
  If it changes at all, it is part of the ABI-1 1.0 review (K8.4d).
