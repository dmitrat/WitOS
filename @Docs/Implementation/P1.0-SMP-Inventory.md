# P1.0 — what one scheduling processor means in the kernel today

Plan step P1 (phase P, RFC 0005, RFC 0011 §7) runs user threads on every online processor. Before its first line of
code, as V0 did for the third ISA, this document records what the kernel assumes about one scheduling processor, with
the places that assume it, and splits P1 into slices with a guest acceptance each on the three ISAs. Made on 2026-10-18
from the tree of V3; the line numbers are that tree's.

## 1. What exists

K7 enumerated the processors (`wit_platform_processors`: the MADT on q35, `/cpus` on both virt boards) and K7.2 started
every one at boot (`src/Kernel/cpus.c`): a secondary processor idles with interrupts enabled on its own stack and serves
two requests alone, a fence and the invalidation of one page, each sent by the boot processor one at a time and
acknowledged within a bounded wait. `wit_processors_online()` counts the started processors; `wit_processors_scheduling()`
is 1 (`processors.c:84`) and `wit_processors_current()` 0 (`:89`). `boot-smp2` passes on the three boards with
`Processors present/online: 2/2`.

## 2. The scheduler's state is global

- **The dispatcher** (`src/Kernel/user.c`): `current_user` (`:8`), the registry `slot_owners[]` (`:9`), `user_idle`
  (`:12`) are globals, and each process keeps its `CurrentThread` (`user.h:141`; `WIT_THREAD_SELF` resolves through it,
  `user_reference.c:150`). `dispatch(timer, rotate)` (`:249-299`) expires every component's waits on one clock read,
  rotates the components (D5.2) and switches the space, the stack and the TLS of the one processor.
- **Idle runs on the waiting thread's kernel stack** (`:289-297`): the processor halts on the stack of the thread that went
  to wait, and a tick there knows it by `wit_arch_frame_is_idle`. With a second processor that thread's frame could be
  resumed on the same stack meanwhile.
- **The architectures' selection is global**: x64 has one TSS and one `wit_x64_syscall_kernel_rsp`, the SYSCALL entry's
  scratch `syscall_user_rsp` and the `host_rsp`/`host_cr3` of `wit_x64_run_user` (`user_entry.S`); ARM64 a static
  `selected_top` (`frame.c:31`) and `host_stack` (`entry.S:8`); RISC-V statics `selected_top` and `user_tls`
  (`frame.c:28-29`), `host_stack` and the reservation scratch (`entry.S:10-13`). The x64 vector of a device line and of an
  IPI is written to one global each (`wit_x64_device_vector`, `wit_x64_ipi_vector`).

## 3. Serialization is "interrupts off on the one processor"

The kernel takes no lock: a call, a fault and an interrupt run with interrupts disabled, and that alone serializes them.
The rules say so (AGENTS.md: mapping is a serialized bootstrap API; memory calls run one at a time on the one processor
that takes calls; event, wait and pressure publication with interrupts disabled), and so do the sources: the commit
rollback bitmap is one static array (`user_space.c:503`), as is a map's (`user_memory_object.c:391`); the channel,
object, binding, device-owner, process-pool, clock, random and console state are globals without a lock; the physical
allocator is one bitmap with a cursor (`memory.c:69-141`).

The calls that require one scheduling processor say so through `wit_processors_scheduling()`: `CODE_PUBLISH`
(`user_space.c:695`; publication is local on x64 and RISC-V, broadcast `ic ialluis` on ARM64), suspension
(`user_suspend.c:7`) and the CPU context profile (`user_thread_context.c:151`); `MEMORY_QUERY` and `THREAD_QUERY` report
it as the processor count. Others assume it without the check: the thread context calls read the target's saved frame,
stale if it ran elsewhere; `PROCESS_WRITE_BARRIER` fences the processors other than the boot one; `PROCESSOR_QUERY`'s
`Current` is 0; `THREAD_AFFINITY` refuses a mask without processor 0. In layer 2 the libc's futex yields and spins
(`futex.c:45`) and `sched_getaffinity` reports one processor (`system.c`).

## 4. The machinery that is there

- **The request fabric** (`cpus.c:121-154`): the address and the kind are one record per target, the acknowledgement a
  counter, the sender the boot processor alone, so that "one in flight" holds because there is one sender; a sender that
  spins with interrupts disabled while its target spins for it would deadlock. `invalidate_all` has no caller but the
  self-test. RISC-V keeps one pending kind per hart (`pending_ipi[hart]`), which a second kind overwrites.
- **Identity**: x64 reads the local APIC id through CPUID, ARM64 MPIDR, and RISC-V knows a secondary by the stack it runs
  on, which stops working once a secondary runs on a thread's kernel stack. No per-processor pointer exists (no GS base,
  TPIDR_EL1 or per-processor `sscratch`); the x64 rule keeps the kernel's GS base zero.
- **Timers** reach the boot processor alone: the PIT through the 8259 and LINT0 on q35 (the local APIC timer is masked on
  the secondaries), CNTV's PPI 27 in the boot processor's redistributor on virt, `stimecmp` or SBI on the boot hart.
- **Device lines** reach the boot processor on q35 and RISC-V; on ARM64 the distributor routes SPIs to any processor
  (IRM=1, `QemuVirt/interrupts.c:154`), and a line taken by a secondary would reach `wit_user_interrupt` with the boot
  processor's state — a latent hazard P1.2 closes.
- **Translation**: one root per process, shared by its threads; `invalidate` after a map, an unmap, a protect and a
  prune acts only where the space is active on the calling processor (`invlpg` and `sfence.vma` local, ARM64's
  `tlbi vaae1is` broadcast); no ASID or PCID.
- **Stacks per slot** stay static: `[WIT_PROCESS_CAPACITY][32]` kernel stacks of 64 KiB with guards in each
  architecture's image (`limits.h:44-55`: 12 processes in the release kernel, 8 in the self-test kernel, by image size).

## 5. Decisions

- **One kernel lock first.** Every entry into the common kernel — a call, a user fault, a tick, a device line, an IPI that
  needs the kernel — takes one lock, and the processor releases it only once it runs on the frame it resumes or halts in
  idle. Every rule of section 3 then holds as written, the common kernel changes little, and the work stays in user
  space, where WitOS keeps it; finer locks come later where a measurement shows contention, never by guess. A processor
  that spins for the lock serves the requests sent to it, so that a shootdown never waits for a processor that waits for
  the lock.
- **A per-processor record** holds the current component and thread, the idle flag, the selected stack top and the
  architectures' scratch, found without a lock or a system register write by user space: x64 by a TSS and a task register
  per processor (STR names the record; the GS base stays zero) and an entry stub per processor for SYSCALL; ARM64 by
  TPIDR_EL1; RISC-V by a per-processor pointer the trap entry reaches through `sscratch` while U-mode runs.
- **Idle on the processor's own stack**, never on a waiting thread's.
- **A tick per processor**: the local APIC timer calibrated against the HPET on q35, PPI 27 in each redistributor on
  virt, `stimecmp` (or SBI) armed on each hart, each processor's tick charging the component it runs.
- **Device lines stay on the boot processor** in P1, ARM64's routing pinned to it; spreading them is a later question.
- **Shootdown by request** to every processor on which the space is active, after the local invalidation, for an unmap,
  a protect, a decommit and a prune; `CODE_PUBLISH` publishes on every processor; no ASIDs, so a switch flushes as today.
- **Requests from any processor to any**: a pending set per processor instead of one slot, the sender holding the kernel
  lock, a RESCHEDULE kind for a processor that idles while a thread became ready and a STOP kind for the root's end.
- **Suspension, the thread context and a process's end** first take the target off its processor (a RESCHEDULE and a
  wait for it to leave), then act on the saved frame as today.
- **Affinity** is RFC 0005 §38's allowed set: `THREAD_AFFINITY` keeps its record form and the scheduler honours it;
  placement and exclusive allocation stay RFC 0005's later model.

## 6. The slices

| Slice | What it changes | Guest acceptance on x64, ARM64 and riscv64 |
| --- | --- | --- |
| **P1.1** Per-processor state | the per-processor record and its identity on each ISA, the current component and thread there instead of globals and `CurrentThread`, idle on the processor's own stack, an entry stub per vector where a global held the vector; `wit_processors_current()` the caller's index; scheduling stays 1 | every suite unchanged; `Smp.Identity`: each processor's index from its record equals its index in the table |
| **P1.2** The kernel lock and the request fabric | the lock at every entry, requests from any processor to any with a pending set, RESCHEDULE and STOP, serving requests while spinning, ARM64's SPIs pinned to the boot processor | `Smp.Ipi` from a secondary to the boot processor and from two senders at once; a contention self-test whose counter comes out exact; `boot-smp2` |
| **P1.3** Threads on every processor | a tick per processor, RESCHEDULE to an idle processor, shootdown and `CODE_PUBLISH` on every processor, suspension, contexts and ends that take the target off its processor, the root's end that stops the others; `wit_processors_scheduling()` = online; the libc's `sched_getaffinity` reports them | the users suite under `boot-smp2`; a fixture whose two spinning threads see `Current` 0 and 1; a fixture that protects a page to no access while a thread on the other processor faults on it (`wit_test_faulted`); the layer-2 scenarios with two processors |
| **P1.4** Affinity and balance | any mask with an online processor, the dispatcher filtering by it, a running thread moved by RESCHEDULE when its mask changes, idle processors taking ready threads, D5.2's rotation per processor; `THREAD_QUERY` version 6 with the last processor | mask {1} keeps `Current` 1 across yields and {0} keeps 0; the refusals; `boot-smp4` |
| **P1.5** The process record and the stacks per slot | kernel stacks allocated per thread with guards in a kernel window instead of static arrays per slot, records allocated, the static scratch arrays gone; the registry beyond 12 | the image's size measured; `boot-128` loads; a scenario with more than 12 processes; `process` and `spawn` on two processors |

P2 (server GC, the thread pool, `Environment.ProcessorCount` > 1, N1 and N2 under load on several processors) follows
P1; runtime scenarios keep one processor until P1.3 makes two possible.

## 7. Size

The common dispatcher and objects are some 3,500 lines (`user*.c`), the SMP code 280 (`cpus.c`, `processors.c`), each
architecture's scheduler, frame, entry, page table and secondary code about 1,400–1,500, the boards' interrupt code 600.
