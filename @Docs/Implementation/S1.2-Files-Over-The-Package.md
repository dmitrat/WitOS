# S1.2 — files over the read-only boot package

Plan step S1.2 gives the libc its first files ([RFC 0011 v3 §9.3](../RFC-0011-Kernel-Architecture-and-ABI.md): "over the
boot package memory object first, then the namespace service over channels"). The boot package is the root task's
initial capability — a memory object of kind `PACKAGE` the kernel never parses for it — in the format of
`witos/package.h`; the library reads it as the namespace: `/` is the package's root, an entry is a file, a prefix of an
entry up to a `/` is a directory, `/dev/null` is the empty device. Nothing is writable, there are no links, and the
current directory is `/` until the process manager (S6) hands a process its own. The first libc program now reads a
text file with stdio, stats files and directories, lists a directory and sees every write refused.

## What changed

**`src/Substrate/libc/files.c`.** The library maps the package's header and entry table once, read-only, through
`MEMORY_OBJECT_MAP` (at most 64 pages, which holds the table of 1024 entries) and validates them as the kernel's
loader does: the magic `WITPAK01`, version 1, the header and entry sizes, the total size against `PackageBytes`, the
count, every name within the window, nonempty, without `/` at either end or doubled, and sorted; a package that fails
is an unreadable volume (`EIO`). A read maps the window of the bytes it needs (page-aligned, at most 64 pages),
copies them and releases the window, so a file of any size is readable. Descriptors 3–63 are files, directories or
the empty device; 0–2 stay the kernel log.

**The calls.** `openat` (and `open`) resolve a path against the root or an open directory descriptor: `.` and `..`
are folded, `..` above the root is `ENOENT`, a name is a file, a prefix is a directory, `O_DIRECTORY` on a file is
`ENOTDIR`, and any writing intent (`O_WRONLY`, `O_RDWR`, `O_CREAT`, `O_TRUNC`, `O_APPEND`) is `EROFS`; `close`;
`read`, `readv` and `pread64` (a directory is `EISDIR`, the empty device reads nothing); `write` to the empty device
accepts the bytes and to a file is `EBADF`; `lseek` with the three origins; `fstat` and `fstatat` (`newfstatat`,
`stat`) fill the kernel's `struct kstat` of the architecture (`arch/<arch>/kstat.h`): a file is `S_IFREG | 0444`
with its size and the entry index as inode, a directory `S_IFDIR | 0555`, the empty device a character device; `statx`
is `ENOSYS` so musl falls back; `faccessat` (`access`) refuses `W_OK` with `EROFS` and `X_OK` on a file with
`EACCES`; `getdents64` lists a directory as Linux does — `.` and `..`, then the files and subdirectories of the prefix
in table order, each once, as `linux_dirent64` records with the next cursor in `d_off`; `getcwd` is `/`; `fcntl`
answers `F_GETFL`, `F_GETFD` and `F_SETFD`; `readlinkat` is `EINVAL` (since R1.2b, `readlink` and `readlinkat` are
`EINVAL` for a path that exists and `ENOENT` for one that does not, as Linux answers); `ioctl` on a file is `ENOTTY`;
`mmap` of a file stays `ENODEV` (R4). The dispatch of `syscall.c` routes these numbers to `files.c` and keeps the log for 0–2.

**The package of the scenario.** `BootPackage.BuildAsync` adds, for the `libc` scenario alone, `test/hello.txt`
(two lines), `test/dir/a.txt` and `test/dir/b.txt`; the other scenarios' packages are unchanged.

## Tests

`tests/User/libc_hello.c` grows to 55 checks: `fopen`/`fgets`/`feof`/`fseek`/`fread`/`ftell`/`fclose` on the text
file; `stat` of a file, of a directory with and without a trailing slash, of a missing name; `open` for writing and
creation refused with `EROFS`; `O_DIRECTORY` on a file; `read` of a directory; `access` read and write; `opendir`/
`readdir`/`closedir` listing `.`, `..`, `a.txt`, `b.txt` in order; `pread` leaving the position; `getcwd`; `/dev/null`.
Both suites' `libc` scenario requires the summary line as before.

## Limits kept explicit

- Read-only, from the boot package alone: no creation, no writing, no links, no `mmap` of files, no `chdir`
  (`ENOSYS`), no file times; a process's own namespace and current directory come with S6 and the namespace service
  with D5.
- Each read maps and releases a window; nothing is cached beyond the table.
- The package's entries are files only; directories exist as prefixes, so an empty directory cannot exist.
