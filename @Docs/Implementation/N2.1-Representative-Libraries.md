# N2.1 — Representative NuGet libraries

N2.1 is the first step of N2. Implementation Strategy §59 lists six representative libraries: NUnit, xUnit, Math.NET,
MessagePack, MemoryPack and Roslyn. This step runs all six on WitOS, unchanged, from nuget.org.

- **NUnit and xUnit** run as what they are, the test frameworks of two ordinary test applications.
- **The other four** are what those applications test.

RFC 0015 §9's gate N2 asks for the libraries' own test suites in the guest. Building and running six upstream test
suites (Roslyn's among them) is a larger piece of work, which N2.2 is for. N2.1 establishes that the libraries load,
run and pass representative tests under their frameworks on both ISAs.

## The applications (`tests/RepresentativeLibraries`)

Both are ordinary net10.0 applications with packages from nuget.org and nothing for WitOS.

**`NUnitApp`** runs NUnit 5.0.0 through NUnitLite 5.0.0. The runner writes no result file (`--noresult`), since a
test's working directory may be read-only. It exits with the number of failed tests. Its tests:
- **MessagePack 3.1.11:**
  - a contract type through the standard resolver;
  - a dictionary through the contractless resolver, whose formatters it emits at run time;
  - LZ4 block compression.
- **MathNet.Numerics 5.0.0**, on its managed provider:
  - a linear system;
  - a QR decomposition and determinant;
  - an FFT's peak;
  - a fitted line, a mean and the gamma function.

**`XUnitApp`** is an xUnit v3 4.0.2 application, which runs its own tests in process. Its tests:
- **MemoryPack 1.21.4**, through formatters its source generator made at build time:
  - a round trip;
  - a union of two types behind an interface;
  - version tolerance.
- **Microsoft.CodeAnalysis.CSharp 5.9.0:**
  - C# parsed and compiled in memory against the running framework's assemblies, which come from the
    `TRUSTED_PLATFORM_ASSEMBLIES` the host passed;
  - the image emitted, loaded into a collectible `AssemblyLoadContext` and invoked;
  - a semantic model's symbol;
  - a compilation error's diagnostic.

## Where they run

- **Windows and Linux.** Both projects are part of `WitOS.slnx`, and `RepresentativeLibrariesTests` runs them through
  `dotnet` on the hosts that run the host tests.
- **WitOS.** The `runtime-libraries` scenario (`RuntimeLibraries`) runs both through `dotnet`, beside the device
  services, from the package N1 built its scenario from. That package is now shared (`RuntimeApps`):
  - the device services and the .NET install of R5;
  - each application published by the stock SDK without a RID under `/app/<name>`;
  - the commands in `/etc/apps`;
  - `tests/User/apps_init.c` as `/bin/init`. It replaces N1's `compatibility_init.c` and runs each command with
    `TMPDIR` on `/data`.

  The scenario requires each runner's summary without failures and each application's exit with 0. `runtime-witos`
  runs it after N1, and the `runtime-libraries` command runs it alone.

## Results

| System | NUnit (MessagePack, Math.NET) | xUnit (MemoryPack, Roslyn) |
| --- | --- | --- |
| Windows x64 | 7 of 7 | 6 of 6 |
| Linux x64 | 7 of 7 | 6 of 6 |
| WitOS x64 | 7 of 7 | 6 of 6, in 241 s |
| WitOS ARM64 | 7 of 7 | 6 of 6, in 295 s |

Roslyn's tests take minutes under TCG: every method of the compiler is JIT-compiled the first time it runs, and no
ReadyToRun code exists for `witos` (`Compatibility-Differences.md`: Code). The scenario allows an hour.

## Limits kept explicit

- **Representative tests, not the libraries' own suites.** That is N2.2.
- **xUnit colours its output.** WitOS's console answers `TIOCGWINSZ` so that stdio line-buffers (R4.1), so xUnit
  takes it for a terminal and writes ANSI colour codes into the kernel log. The required lines match through them.
- **Packages come from nuget.org at publish.** The versions are pinned in the projects. The scenario needs the
  network on the host that publishes, as any restore does.
