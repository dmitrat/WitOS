# K3.2 — Interrupts and DMA (ABI v59)

Plan step K3.2 completes the device family of [RFC 0011 v3 §7.7](../RFC-0011-Kernel-Architecture-and-ABI.md) begun
in [K3.1](K3.1-Device-Descriptors.md): `INTERRUPT_BIND` (82) and `INTERRUPT_ACK` (83) deliver a device's line to an
event of the component that holds it, `DMA_PIN` (84) and `DMA_UNPIN` (85) give that component the physical ranges
of memory it owns for the device. With them the first driver runs in user space on both boards: the virtio-blk
fixture reads a sector of the boot disk over the modern virtio PCI transport with nothing but ABI-1. The kernel
still knows no device class, protocol or driver.

## What changed

**A binding is a line, a device and an event.** `INTERRUPT_BIND(device handle with BIND, line index, event handle
with SIGNAL)` validates the device holder, the line (a `LEVEL` line the platform accepts), the event and that
nobody bound the line yet (`BUSY`), then records the binding (kernel-wide, `WIT_INTERRUPT_CAPACITY` 8), takes a
reference to the device (it stays acquired while bound) and to the event (it lives while bound, whatever handles
the component closes), unmasks the line and returns an interrupt handle (kind `INTERRUPT` 13; rights `ACK` 131072,
`QUERY`, `DUPLICATE`, `TRANSFER`). The binding ends with the handle's last reference, in the component's table or
in flight in a channel, or with the component: the line is masked and both references dropped.

**Delivery is mask, set, dispatch.** The architecture takes the interrupt, masks and completes the line through the
platform, and hands the line to the kernel: the bound event of the running component is set and the ready threads
are dispatched as after a timer tick, so a thread parked in `OBJECT_WAIT` on the event runs; the component's
`InterruptsDelivered` counts it. A line nobody bound, or one bound by another component, stays masked. The line
stays masked until `INTERRUPT_ACK(interrupt handle with ACK, 0, 0)`; a driver clears the device's cause first.
On x64 the PIC inputs 1 to 15 (vectors 0x21–0x2F) enter the kernel through `wit_x64_device_entry`, a copy of the
timer entry that notes the vector in `wit_x64_device_vector` (one processor, interrupts disabled); the platform
keeps the mask registers of both PICs, opens the cascade for slave lines and acknowledges both chips. On virt the
platform's claim returns a shared peripheral interrupt as a device line; the distributor is programmed for it as
group 1, priority 0x80, routed to any processor, enabled and disabled through `GICD_ISENABLER` and
`GICD_ICENABLER`.

**A pin holds memory still for a device.** `DMA_PIN(WitDmaPinRequest, 56, 0)` (`witos/dma.h`) needs the device
handle with `BIND` and an anonymous memory object the caller holds with `MAP`, a page-aligned window of it and a
buffer of `WitDmaRange` entries. Objects are eagerly backed and never move, so the pin is a reference that keeps
the object alive (`WIT_PIN_CAPACITY` 8 per component) plus the physical ranges of the window, merged where pages
are contiguous and written whole with a zero entry after the last; a window that needs more ranges than the buffer
takes is `TOO_LARGE` and pins nothing; a device region or the table is `INVALID_ARGUMENT`. The pin handle (kind
`PIN` 14; `QUERY`, `DUPLICATE`, `TRANSFER`) ends the pin with its last reference; `DMA_UNPIN(pin handle, 0, 0)`
closes it. There is no IOMMU and no `PIN` right: the ranges are physical and the device holder is the trust
boundary (RFC 0004 §57), which is why the device handle is part of the request.

## Kernel

- `user_interrupt.c`: the bindings, the two calls, delivery (`wit_user_interrupt_raised`), the handle's lifecycle
  and the component's reset. `user.c`: `wit_user_interrupt`, the mirror of the timer tick for a device line.
- `user_dma.c`: the pins, the two calls and the handle's lifecycle; `user_memory_object.c`: references beyond
  handles and the pages of an object; `user_device.c`: the device index behind a handle and references beyond
  handles; `events.c`: references by object number; `user_wait.c`: a signal by object number.
- `platform.h`: `wit_platform_interrupt_claim` reports a device line; `wit_platform_line_valid`, `_unmask`,
  `_mask`, `_complete`. `Kernel.Platform.Q35/interrupts.c`: the PIC mask registers and EOIs;
  `Kernel.Platform.QemuVirt/interrupts.c`: the distributor's SPI registers.
- `Kernel.Arch.X64/entry.asm`, `context.asm`, `scheduler.c`: the device vectors and their entry;
  `Kernel.Arch.A64/scheduler.c`: the claimed device line.

## Fixtures

`tests/User.X64/interrupts.asm` and `tests/User.A64/interrupts.asm` (modes `User.InterruptBind`: rights, one
binding per line, acknowledgement, the binding holding the event and the device until its last handle;
`User.DmaPin`: the ranges of a two-page object, refusals of a window beyond the object, of no capacity, of a
foreign version or size, of a device region, of a device handle without `BIND` and an object handle without `MAP`,
the pin ending with its handle while a second pin keeps the object) and `tests/User.X64/virtio.asm`,
`tests/User.A64/virtio.asm` (`User.VirtioBlock`): the driver. It maps the configuration page, turns on memory
decoding and bus mastering, walks the vendor capabilities to the common, notify, ISR and device configuration of
the modern BAR, finds that BAR among the descriptor's regions by its firmware-assigned base and maps it, creates
and pins five pages (descriptors, available ring, used ring, request and status, data), resets the device,
negotiates `VIRTIO_F_VERSION_1` alone, sets queue 0 of eight entries to the pinned pages, binds the INTx line to an
auto-reset event, queues one read of sector 0 through three descriptors, notifies the queue, waits on the event,
reads the ISR status, checks the used ring, the request status and the sector (the FAT boot sector's `AA55h` and
`FAT1`), acknowledges the line, resets the device and gives everything back. The common
`tests/Kernel/user_interrupt_tests.c` drives both images, raises the tick budget for the driver because the host's
block I/O takes wall-clock time, requires at least one delivered interrupt and checks after each mode that no
binding, pin, device, object, mapping or page survived.

## Limits kept explicit

- One binding per line: two devices sharing an INTx line cannot both be driven; sharing (several bindings per
  line, each acknowledging) is not implemented.
- Level-triggered lines only; message-signalled interrupts (MSI, MSI-X) are not offered, and the fixture leaves the
  device's MSI-X capability unused.
- The driver is a test fixture, not the device manager of phase D: it has no error handling beyond failing the
  scenario and drives one request.
- No IOMMU and no `PIN` right: the ranges are physical and the device holder is trusted; a device programmed with
  another address is not stopped. With an IOMMU the same call returns device addresses.
- The virt firmware's INTx routing comes from the device tree's interrupt map; the ACPI `_PRT` is not parsed.
