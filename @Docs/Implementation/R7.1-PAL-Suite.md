# R7.1 — CoreCLR's PAL suite in the guest

R7 is the gate of RFC 0015 §9 that runs upstream's own tests in QEMU. R7.1 is its first slice: the PAL suite
(`src/coreclr/pal/tests/palsuite`), which tests the layer CoreCLR is built on, the PAL, over the system layer.

```
[PAL] CoreCLR's PAL suite on x86_64: all 246 tests passed
[PAL] CoreCLR's PAL suite on aarch64: all 246 tests passed
```

## The build and the runner

Upstream's `clr.paltests` subset builds for `witos`. It gives one dynamic program, `paltests`, that holds every test,
plus `pal_sxs`, a program with two libraries that each link their own PAL. `runtime-witos` builds the subset with
CoreCLR's native part. One patch of the suite's own build was needed, for `pal_sxs` (see below).

The `runtime-palsuite` scenario runs the suite the way `runpaltests.sh` does:

- The selection is upstream's `paltestlist.txt` (305 tests) less the tests `build/runtime/palsuite.json` leaves out.
  Each test it leaves out has a reason, and the tool refuses an exclusion with no reason or a name the list does not
  have.
- `tests/User/palsuite_runner.c`, the scenario's `/bin/init`, starts each test in a process of its own with
  `posix_spawn`. A test runs as `paltests <name>`, or as the test's own program when its build made one, and passes
  when it exits with zero.
- The runner prints a line per test and a summary. The scenario requires `all N tests passed` and the root task's
  report of status 0.

`runtime-witos` boots the scenario on each ISA after CoreCLR's load check. The whole suite takes a few minutes of the
guest's time.

## Results

The first run passed 243 of 305 tests on x64. The fixes and the exclusions below brought it to all 246 of the
selection, on both ISAs.

| Found | Cause | Change |
| --- | --- | --- |
| `SetThreadPriority` failed with `ERROR_INTERNAL_ERROR` (`ThreadPriority/test1`, `DuplicateHandle/test7`). | The PAL reads the thread's policy with `pthread_getschedparam` and the policy's range with `sched_get_priority_min` and `max`. The libc answered `ENOSYS` to those calls. | The libc answers as Linux does for a normal thread: the kernel runs every thread round-robin at one priority, which is `SCHED_OTHER` at priority 0. The real-time policies' ranges are `EINVAL`. Setting `SCHED_OTHER` at 0 is accepted, since it changes nothing, and any other setting is `ENOSYS`. `process_init.c` checks it. |
| `runtime-witos` refused `tryrun.cmake` after that fix. | The configure's `HAVE_SCHED_GET_PRIORITY` probe now succeeds in the guest, while `tryrun.cmake` still answered that it failed. | The witos answer follows the measurement: `HAVE_SCHED_GET_PRIORITY_EXITCODE` is 0. CoreCLR's PAL then maps a priority through the range of one value and asks the libc for `SCHED_OTHER` at 0. |
| `pal_sxs` could not find its libraries (exit 127). | The program's `RUNPATH` is `$ORIGIN`. For a main program that the system mapped, musl's dynamic linker reads `/proc/self/exe`, and WitOS has no `/proc`. | A second WitOS hook in `patches/musl/dynlink.c.patch` takes the program's `AT_EXECFN` as its origin. That is the path its creator started it by, which musl already uses as the program's name. |
| The runner ran `paltests pal_sxs`. | The package keeps no execute bits, so `access(X_OK)` refuses every file. | The runner checks that the file exists, as `runpaltests.sh` does with `-f`. |
| `pal_sxs` ended with an uncaught `PAL_SEHException` (SIGABRT). | The test's second library exports only its two entry points through a version script on Linux, FreeBSD and NetBSD, and its CMake names those platforms. On `witos` the library exported every PAL function, so its calls bound to the first library's PAL. A fault in its `PAL_TRY` was then thrown by the other PAL, as a type that its catch did not match, since each library's type information is hidden. Instrumented, the throw came from the first library's `ThrowExceptionHelper`. | `patches/runtime/src.coreclr.pal.tests.palsuite.exception_handling.pal_sxs.test1.CMakeLists.txt.patch` adds `CLR_CMAKE_TARGET_WITOS` beside the other platforms. The patch set grows to 26 files, CoreCLR 10 of FreeBSD's 31. |

### Left out, with the reason

| Tests | Reason |
| --- | --- |
| 41 tests of `file_io`, `_wfopen`, `CreateFileMappingW`, `MapViewOfFile`, `UnmapViewOfFile` and `CloseHandle/test1` | Each test writes a file in its working directory. The boot package is the whole file system and stays read-only until the namespace service (D5) and storage (D6). `runpaltests.sh` gives every test an empty writable directory, and WitOS has no place for one yet. |
| `VirtualAlloc` tests 3, 4, 5, 15, 16 and 17, `VirtualProtect` tests 2, 3 and 4 | Each asks for executable anonymous memory: `PAGE_EXECUTE`, `PAGE_EXECUTE_READ` or `PAGE_EXECUTE_READWRITE`. WitOS never makes plain memory executable. Code comes from the package or from the double mapping of a shared memory file (R3.2b), which is how CoreCLR's JIT gets it. |
| `CreateProcessW` tests 1 and 2, `NamedMutex/test1` | Each starts a process. The PAL's `CreateProcess` forks, and WitOS never emulates `fork` (RFC 0015 §8). The named mutexes are also files under `/tmp`. |
| `test2` of `InterlockedIncrement`, `InterlockedDecrement`, their 64-bit forms and `InterlockedCompareExchange64` | Each runs 64 threads at once. A system layer process runs 32 (`WIT_PROCESS_THREAD_CAPACITY`) while every thread has a static kernel stack. |
| `ProbeMemory_neg1` | `PAL_ProbeMemory` writes the probed byte into a pipe and expects `EFAULT` for an inaccessible address. The libc's pipes live within the process and copy in user space, so the copy faults (SIGSEGV) where Linux's kernel returns `EFAULT`. CoreCLR calls `PAL_ProbeMemory` only from debugger helpers. |

The thread quota, the read-only file system, the single priority and executable memory are recorded in
[Compatibility-Differences.md](Compatibility-Differences.md). The pipe's copy is not, because no managed API reaches
it.

## Since R7.2a

R7.2a made `/dev/shm` the directory in which a process creates files, and the runner now starts each test there. 34 of
the 41 tests left out for writing files pass, and the exclusions are 25. The 7 left are listed in
[R7.2a-Writable-Shared-Memory.md](R7.2a-Writable-Shared-Memory.md).
