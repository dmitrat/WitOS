# E4.5 — Working on VMware

Plan step E4.5 (phase E, goal Ц6). On 2026-11-03 the author asked for real work on VMware after E4.4. The pre-check
used the PC's one disk with E4.4 in the H5 machine, headless (`vmrun -T ws … nogui`, the screen through VMware's VNC
server on 127.0.0.1). At the session's pwsh prompt it wrote a console project, built it with the layer's SDK, ran it,
then ran it again from Arlecchino.Commander's command line. Two things stood in the way, and this step removes both.

## 1. What the work found

| Run | Machine | Result |
| --- | --- | --- |
| `dotnet --version` | 1 GiB, 2 processors | `10.0.300` in 2 s, code 0 |
| `dotnet build` of a console project | 1 GiB | failed after 19 s: Roslyn's `Csc` task reported "Out of memory" |
| the same build | 2 GiB | succeeded in 22 s, then in 15 s on the machine of §3 |
| the program it built | 2 GiB | printed its line and returned 7 |
| `mkdir`, `ls`, `mv`, `clear` at the prompt | either | "The term 'mkdir' is not recognized as a name of a cmdlet …" |

- **Memory.** One GiB leaves 805 MiB usable, and a build runs pwsh, MSBuild and the compiler at once. The machine needs
  2 GiB (1829 MiB usable), as the QEMU gates give their SDK scenario 1024 MiB with one processor.
- **The shell's commands.** pwsh on Unix leaves `ls`, `cp`, `mv`, `rm`, `rmdir`, `cat`, `sort`, `sleep`, `tee` and
  `clear` to the system's coreutils and defines no `mkdir`. WitOS has no coreutils and no `/bin/sh` (ADR 0027). So the
  commands a person types first were missing, at the prompt and on Commander's command line alike.
- **A log line, not a failure.** Each build logs `[LIBC] mprotect refused (plain memory never executes): …, protection
  0x5` once, and builds anyway: one of the build's processes asks for executable plain memory and then takes another
  way.

## 2. The shell's commands

The session's profile (`build/console/profile.ps1`, `$PSHOME/profile.ps1`) names the cmdlets as Windows' PowerShell
does: `ls` Get-ChildItem, `cp` Copy-Item, `mv` Move-Item, `rm` and `rmdir` Remove-Item, `cat` Get-Content, `sort`
Sort-Object, `sleep` Start-Sleep, `tee` Tee-Object, `clear` Clear-Host, and the function `mkdir`, which is New-Item
of a directory. The names are set before the profile's early return, so a session with redirected streams and every
command Commander runs through `SHELL` get them too. `ps` and `kill` stay out, since another process's list and its
termination are `PlatformNotSupportedException` on WitOS.

`runtime-powershell` types, at the interactive prompt:

```
mkdir /data/unix/inner | Out-Null; Set-Content /data/unix/inner/t.txt unix; cp … c.txt; mv … m.txt;
'aliases=' + (cat /data/unix/m.txt) + ':' + ((ls /data/unix -Name | sort) -join ','); rm -r /data/unix
```

It requires `aliases=unix:inner,m.txt`.

## 3. The machine

`shell --pc --prepare <directory>` writes `WitOS-pc-x64.vmx` beside the image and its descriptor on x64
(`RuntimeDataDisk.WriteVmxAsync`). It is the machine H5's sessions measured:

- EFI firmware without Secure Boot, with its serial console;
- the HPET the kernel's clock takes (H1.1);
- the disk on SATA;
- the e1000e adapter on NAT (H4);
- the first serial port to `serial.log` beside the machine, which is the kernel's log;
- no virtual USB keyboard, whose presence costs the first second of a boot's keys (H5 §2.2);
- 2 GiB and two processors.

It has no remote display, since VMware's VNC server has no password. A person opens the machine in VMware Workstation.
`RuntimeDataDiskTests` checks the text.

A machine of exactly that text, with VNC added for the headless check, booted to the prompt with 1829 MiB and 2 of 2
processors. At the prompt:

- the project built in 15 s;
- `dotnet bin/Debug/net10.0/hello3.dll` printed "Hello from WitOS 0.1 ABI-1, built on this machine" and returned 7;
- Commander ran the same command from `/data/hello3` with the terminal given to the program;
- the session's `exit` powered the machine off with `/bin/init`'s status 0.

## 4. Limits kept explicit

- **A command's code in Commander is pwsh's.** Commander runs a command through `SHELL`, which is pwsh, and
  `pwsh -Command` exits with 1 when the last native program exits with anything but 0. A program that returns 7
  shows `[exit 1]`; one that returns 0 shows `[exit 0]` (E4.3). A shell that passes the code on, as bash does, is not
  in the system.
- **The panels' free space** is that of `/`, the boot package (E4.2 §5).
- **Files from Windows** reach the machine through an SMB share (E2) or a USB drive (E3). The share needs a share on
  the Windows host, and a firewall rule for VMware's NAT network, which is the author's to decide. That is E5's session.
