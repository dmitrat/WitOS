# K8.4d — ABI-1 1.0

[K8.4a](K8.4a-Policy-Calls-Removal.md)–[K8.4c](K8.4c-Flat-Fixtures.md) removed the kernel policy, the version 1 thread
form and the raw component path. K8.4d settles what remained of the frozen line's conventions and declares
**ABI-1 1.0** (RFC 0011 §10.1). This finishes step K8 and phase K.

## The version

- **The encoding.** The version is `(major << 16) | minor`: `WIT_ABI_VERSION_MAJOR` is 1 and `WIT_ABI_VERSION_MINOR` is
  0. `WIT_ABI_VERSION` is that expression, and `WIT_ABI_MAJOR(version)` takes the major back out. `QUERY` reports the
  version in the low half of its result and the startup descriptor carries it.
- **Continuity.** The draft counters of phase K ran from 1 to 72 with major 0, so the 1.0 value (0x10000) is larger
  than any of them.
- **What may change after 1.0.** Changes are additive: a call, an operation of a composite call, an appended field under
  a new structure version, a feature bit. Each raises the minor. Removing anything, or changing what it means, needs a
  new major and an ADR. Call numbers, status values and rights bits are still never reused (since K1). `user_abi.h`
  states the rule.
- **The banner** reads `WitOS user ABI 1.0, boot ABI v6`. The kernel prints the major and the minor. `KernelAbi` reads
  them, and the host tests check the banner, README, PLAN and the ABI reference against them.
- **The libc refuses another major** (RFC 0011 §10.1, item 5). Before anything else runs, `crt1` checks the startup
  descriptor's version and its ABI major. On a mismatch it writes one line to the kernel log and exits with 127. The
  root task fixture checks the major too.

## What 1.0 fixes

- **The x64 fault callback uses the SysV argument registers.** The token, the vector and the address arrive in RDI, RSI
  and RDX, the registers a thread's entry uses, instead of the Microsoft RCX, RDX and R8. The libc's
  `__wit_signal_entry` no longer moves registers, and the fixtures' callbacks lose `ms_abi`. ARM64 is unchanged
  (x0–x2).
- **`PROCESSOR_QUERY` has the record form alone.** The frozen line's 4-byte form (the current processor as
  `{group, number, reserved}`) is gone, so a 4-byte buffer is now `INVALID_ARGUMENT`.
- **`limits.h` has mechanisms only, in two profiles:**
  - the fixture's (`WIT_USER_*`, 16 handles, 4 events, 8 objects);
  - the system layer process's (`WIT_PROCESS_*`).

  The frozen line's "runtime profile" constants are renamed: `WIT_RUNTIME_PAGE_CAPACITY` → `WIT_PROCESS_PAGE_CAPACITY`,
  `WIT_RUNTIME_TICK_BUDGET` → `WIT_PROCESS_TICK_BUDGET`, `WIT_RUNTIME_USER_LIMIT` → `WIT_PROCESS_USER_LIMIT`.
  `WIT_RUNTIME_RESERVATION_CAPACITY` (32) is gone: the system profile now takes the system reservation table (256)
  directly, and its callers no longer override it.
- **The self-test kernel has 16 threads per process** (`WIT_PROCESS_THREAD_CAPACITY`), as the release kernel does. The
  limit of four is gone, along with the frozen scenario that needed it.

## Tests

The fixtures and the root task's mechanism checks register their callbacks in the SysV convention. The suites keep
their markers.

- `format-check` and the host tests pass.
- `test`: all 27 x64 scenarios pass.
- `test --arch arm64`: all 21 scenarios pass.

## Limits kept explicit

- **`-ffixed-x18`.** Layer 2 and the runtime's toolchain patch still reserve x18, although the kernel no longer uses it
  (K8.4b). Removing the option means rebuilding the runtime, so it moves to step R3.
- **The fault callback's frame.** On x64 the callback is entered with no return address and a 16-byte aligned stack, as
  before. 1.0 freezes the registers the arguments arrive in, not that layout.
