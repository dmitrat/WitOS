# D4.2 — The managed ext4 provider reads

D4.2 is the second step of D4. It adds a managed provider of the ext4 on-disk format, the storage document's first
general-purpose filesystem (§17–19). The provider serves the format, not Linux's VFS (§19), and reads ext4, ext3 and
ext2. It mounts read-only: writing through the journal is D4.3.

Its references are volumes the host's e2fsprogs makes from a known tree (§73: compatibility is the format's actual
semantics):

- on the host, six variants of `mkfs`;
- in the guest, the data disk's ext4 partition, which the device manager reads through the virtio driver's block
  channel.

## The contract grows by what ext4 records

- **`FileSystemEntry.Kind`** replaces the flag of D4.1. An entry is a file, a directory, a symbolic link, or `Other`
  (a device node, a pipe or a socket, which the provider serves no data of). `IsDirectory` stays.
- **`FileSystemUnixMetadata`** carries what a POSIX-shaped format records: permission bits, owner, group, link count
  and the entry's number in the volume. It is recorded data, not authority (§56). The namespace service of D5 reports
  it in stat. FAT reports none.
- **`IFileSystem.ReadLinkAsync`** returns a link's target as recorded. A lookup never follows a link; where links
  resolve across volumes is D5's question. A path that is no link fails with the new `FileSystemError.NotALink`. FAT
  answers `NotALink` for anything that exists.

## The provider (`OutWit.OS.FileSystems.Ext4`)

Nothing of the volume is trusted before it is checked (§72).

- **`Ext4Superblock`** is checked whole before anything else of the volume is read:
  - the magic;
  - the CRC-32C checksum when `metadata_csum` is on;
  - the geometry: block size, groups, inode size, descriptor size, the volume within its resource;
  - the incompatible features the reader serves: `filetype`, `extents`, `64bit`, `flex_bg`, `ea_inode`, `csum_seed`,
    `largedir`.

  Everything else is refused as `Unsupported`, with a reason: `meta_bg`, `inline_data`, `encrypt`, `casefold`, an
  external journal, and a journal that needs recovery.
- **`Ext4GroupTable`** reads the group descriptors (32 or 64 bytes) at the mount. Each must pass its checksum: CRC-32C
  with `metadata_csum`, the older CRC-16 with `gdt_csum`. Each must place its inode table within the volume.
- **`Ext4Inode`** reads a record and checks its checksum over the whole record. The checksum is seeded by the volume,
  the number and the generation, and has a high half only where the record's extra size covers it.
  - The type and permission bits, the owner with its high halves, the size, the links and the flags.
  - The four times, with their epoch bits and nanoseconds; the creation time only where the record holds it.
- **`Ext4DataMap`** gives where an inode's data lie, as runs of logical blocks on physical blocks.
  - **Extents.** The extent tree up to depth 5, each child at one depth less than its parent, so no cycle can form.
    Each block is checked by its tail's checksum. An uninitialized extent reads as zeros.
  - **Block maps.** The block map of ext2 and ext3: direct blocks, then indirect, double and triple indirect.
  - **Holes.** A logical block no run covers is a hole.
  - **Checks.** Every run must lie within the volume, in order.
- **`Ext4Directory`** reads a directory linearly, so an htree needs no hashing: its root block holds "." and "..",
  and its index nodes hold one empty entry over the block, which the reader skips.
  - With `metadata_csum`, every leaf ends with a tail whose CRC-32C covers the block.
  - Every entry's length is checked against its block before its name is read.
  - A record length of 65,535 or 0 stands for a whole 64 KiB block.
- **`Ext4FileHandle`** reads through the map. Each run of contiguous blocks is one read of the resource; holes come
  back as zeros.
- **`Ext4Disk`** reads byte ranges of the resource. It goes through the aligned range when the resource asks for more
  alignment than an ext block has, and splits a read at the resource's transfer limit.
- **Concurrency.** Everything the volume holds is read at the mount and never changes, so reads run at once without a
  lock.
- **`Ext4FileSystem`** maps the contract onto the reader:
  - `MountAsync` mounts read-only;
  - `DetectAsync` checks only the magic (§58);
  - a lookup takes "." and "..", refuses to climb above the root, and fails through a non-directory with
    `NotADirectory`;
  - `ReadLinkAsync` serves a fast link from `i_block` and a slow one from its block;
  - `CheckAsync` walks the tree from the root and reads every directory, inode, map and link, and reports a directory
    inode reached twice;
  - every change is `ReadOnly`.
- **The checksums** are the kernel's: a raw CRC-32C update (Castagnoli, reflected `0x82F63B78`) with no inversion,
  and CRC-16/ARC for `gdt_csum` (`Ext4Checksums`).

## Tests

- **The reference volumes.** `tests/OutWit.OS.Tests` makes them with `mkfs -d` from one tree, then runs `e2fsck -fD`,
  which indexes the large directory as an htree. The tree holds:
  - a text file, an empty file and nested directories;
  - a sparse file of ten chunks between holes, which needs an extent index in ext4 and an indirect block in ext2 and
    ext3;
  - a directory of 3000 entries, an htree with index nodes below its root at 1 KiB blocks;
  - a fast link and a slow link;
  - two modes.
- **The variants.** Each test runs on six variants:
  - ext4 with 4 KiB blocks and 256-byte inodes;
  - ext4 with 1 KiB blocks;
  - ext4 without `metadata_csum`, so `gdt_csum` is in use;
  - ext4 with 128-byte inodes, which have no extra fields;
  - ext3;
  - ext2.
- **What they check.**
  - Every entry, kind, byte, link target and mode equals the tree's.
  - The tests also check that the structures they claim to exercise are there: the htree flag, the extent index or
    indirect block, and the index levels.
  - The volume's check is clean and counts the tree's files and directories.
  - Every failure carries its error.
- **Damage and backends.**
  - A changed superblock, inode or directory block fails its checksum.
  - A journal that needs recovery is refused with its reason.
  - A resource without a volume is refused.
  - The substitution test of §71: one volume read over a partition and over the block protocol.
  - The checksums match the published check values.
- **Totals.** 161 tests pass on Linux. On Windows, which has no e2fsprogs, the 23 tests that need an image are
  skipped. CI's `linux-host` job runs them all.
- **`tests/WitOS.Dev.Tests`.** The data disk's ext4 partition holds the tree, read by the provider.

## The scenario

- **The data disk** grows to 32 MiB with a third partition, "WitOS ext4" (21 MiB).
  - `RuntimeExt4Volume` makes it with the host's `mkfs.ext4 -d` and `e2fsck -fD` from a tree: a text file of mode 644,
    a directory with a file, a sparse file of six chunks between holes, an htree directory of 400 entries and a link.
  - A host without e2fsprogs cannot make it. `runtime-devices` needs a Linux host anyway.
- **The device manager's `Ext4Probe`** mounts the partition read-only through the block channel and reads it back:
  - its root and `/hello.txt` with its mode;
  - `/big.bin`, every chunk and hole;
  - `/many` and `/link`;
  - a check.
- **The host check.** After the boot, the tool requires the partition byte for byte as it was made: the read-only mount
  wrote nothing.

## Results

`runtime-services` passes on both ISAs with the same lines, and the tool's check after each boot finds the ext4
partition unchanged.

- **The volume.** "WITOS EXT4", 22,020,096 bytes in blocks of 4096, read-only. `/` holds `big.bin`, `docs`,
  `hello.txt`, `link`, `lost+found` and `many`.
- **The files.**
  - `/hello.txt` has mode 644 and reads as the host wrote it.
  - `/big.bin` reads as 347,680 bytes, six chunks between holes, as the host wrote them.
  - `/many` holds 400 entries.
  - `/link` points to `hello.txt`.
- **The check** is clean: 403 files, 4 directories.

## Limits kept explicit

- **Read-only.** Writing, with the journal and its ordering (§45–49), is D4.3. A journal that needs recovery is refused
  until D4.3 replays it.
- **Refused features.** `meta_bg`, `inline_data`, `encrypt`, `casefold` and external journals are refused.
  `bigalloc` volumes are read as their extents name blocks.
- **No extended attributes, ACLs or quotas** are read.
- **Linear directory reads.** A lookup reads a directory linearly rather than through its htree hash, which is correct
  but slower for very large directories.
- **A file's map is read whole** at the open.
- **No block cache.** A caller that wants one puts `CachedBlockStorage` below.
