# H3.2 — PC storage: an NVMe driver

H3.1 served the PC's SATA disks. H3.2 serves its NVMe disks, which VMware gives a machine as an NVMe controller (15ad:07f0)
and which the Raspberry Pi 5 reaches through its PCIe connector. The driver serves the controller's first active namespace
over the block protocol (`witos/block.h`), through the block server H3.1 made shared.

## 1. The pieces

| Where | What |
| --- | --- |
| `OutWit.OS.Hardware.Nvme` (the entries, the PRPs and Identify host-tested) | `NvmeCommands`: a submission queue entry, a completion queue entry with its phase tag and status, and the PRP entries of a transfer's physical segments. `NvmeControllerIdentity` and `NvmeNamespaceIdentity`: what Identify answers. `NvmeController`: the controller. `NvmeNamespace`: the first active namespace as an `IBlockDevice`. |
| `IBlockDevice.MaxTransferBytes` | The largest request whatever its segments, which the block server's transfer limit respects: an NVMe controller's MDTS, the 65536 sectors of an ATA command, no limit for virtio-blk. |
| `/system/Drivers/Nvme` (`src/Services/Drivers/Nvme`) | The driver: it takes the device, enables the controller, logs it and its namespace, reads the namespace's block 0 and serves it over the block protocol. Its stop is the controller's normal shutdown. |
| The device manager | `DriverTable` maps a non-volatile memory controller (PCI class 01/08) with NVM Express's I/O programming interface (0x02), whatever its vendor, to the driver, which `DriverTable.ServesBlocks` names among the block drivers. |
| WitOS.Dev | `DiskController.Nvme`: QEMU's `nvme` with the data disk as its namespace 1, where the virtio device would be. `runtime-devices` boots its data disk a seventh time, on NVMe (§4). |

## 2. The controller

- **Enable** (§7.6.1). The driver requires a least memory page (CAP.MPSMIN) of 4 KiB, which it gives the controller, and
  queues of at least 16 entries. It then:
  1. clears CC.EN and waits for CSTS.RDY to clear, within the timeout CAP.TO names;
  2. gives the admin queues — 16 entries each, a page each — through AQA, ASQ and ACQ;
  3. sets CC with the NVM command set, 4 KiB pages, 64-byte submission and 16-byte completion entries, and EN;
  4. waits for CSTS.RDY, failing on CSTS.CFS.
- **Identify.** Identify Controller gives the model, serial number and firmware, MDTS and the volatile write cache.
  The active namespace list gives the first namespace, and Identify Namespace its size and the logical block of its LBA
  format in use. A namespace whose format carries metadata is refused.
- **The I/O queue pair.** Create I/O Completion Queue 1 on interrupt vector 0, then Create I/O Submission Queue 1 onto it,
  16 entries each, physically contiguous in pages of the arena.
- **A command**, one at a time on its queue:
  1. the entry is written at the submission queue's tail;
  2. the tail's doorbell is rung, at `0x1000 + 2 × queue × stride`;
  3. the driver waits for a completion entry whose phase tag is the current lap's;
  4. it consumes that entry and rings the completion head's doorbell, which ends QEMU's INTx assertion, and unmasks the
     line.

  A completion of another identifier is a command's that ended before and is passed over. A failed status is reported
  with its type and code, a fatal controller status as it comes, and no completion in Linux's NVMe times as a timeout:
  30 s for an I/O command, 60 s for an admin command (10 s until a gate's AHCI flush timed out in CI: under QEMU's
  instruction clock without sleep an idle guest's time runs ahead of the host's fdatasync, so the gates' writable disks
  now end a flush at QEMU's device, `cache.no-flush=on`, while the guest's flush is served as before).
- **The interrupt.** MSI-X entry 0 where the kernel serves messages and the function has the capability, the INTx line
  otherwise, with INTMC's vector 0 unmasked. A command's wait also looks at the queue every 10 ms.
- **The end** (§7.6.2): a normal shutdown, CC.SHN of 01, awaited until CSTS.SHST reports it complete, which writes the
  controller's cache to its medium. Then the disable ends its DMA before the arena goes.

## 3. The namespace

- **Read and Write** of whole logical blocks, at most 65536 and at most MDTS pages (MDTS 0 names no limit). Dwords 10–11
  carry the starting block and dword 12 the blocks less one.
- **The data** are PRP entries (§4.3). PRP 1 is the first byte, anywhere in its page; PRP 2 is the second page, or, where
  the transfer reaches more than two pages, the address of a list in a page of the driver's own holding every page after
  the first. The block server's segments are a pinned window's physical runs. Every one but the first starts at a page
  and every one but the last ends at one, so they always make PRPs; `BuildPrps` refuses any other.
- **Flush** where the controller reports a volatile write cache; a durable write is the write and then the flush.
- **Read-only** where Identify Namespace reports the namespace write protected.

## 4. Measured

**QEMU's controller** (1b36:0010): NVMe 1.4, "QEMU NVMe Ctrl", 256 namespaces addressable (NN), queues of up to 2048
entries, MDTS 7 — 512 KiB at 4 KiB pages, more than the block protocol's 256 KiB window — a volatile write cache, a
doorbell stride of 4 bytes, physically contiguous queues required. The INTx line stays asserted while a completion queue
holds an entry the host has not consumed (`nvme_irq_check`).

**The gate.** `runtime-devices` boots its data disk a seventh time as QEMU's `nvme` namespace 1:

- on x64 through MSI-X entry 0;
- on ARM64 and riscv64 through the INTx line, the controller put where the virtio data disk would be.

The probes, the namespace service and `/bin/init` find on it what the six boots before left, and the host requires the
boot count and a clean volume.

| ISA | `runtime-devices`, seventh boot on NVMe |
| --- | --- |
| x64 (container), MSI-X | passed: the controller at 00:04.0, MSI-X message 0x31, 8 pages of DMA memory, the normal shutdown at the stop |
| ARM64 (container), INTx | passed: the controller at 00:03.0, the virtio data disk's slot and line |
| riscv64 (container), INTx | passed: the controller at 00:03.0 |

Every earlier boot of the scenario passed again on the three ISAs with the NVMe driver in the package, the sixth on AHCI
among them. Identify Controller read firmware 11.1.0, QEMU's version, and the namespace took transfers of up to 524288
bytes, so the block server's limit stayed the window's 262144.

## 5. What is not yet

- **Several namespaces and several queues.** The driver serves the first active namespace, one command at a time on one
  I/O queue pair; queue depth and a queue per processor wait for a need.
- **Metadata, protection information and SGLs**: a namespace formatted with metadata is refused; data travel as PRPs.
- **VMware's controller** (15ad:07f0, MSI-X) is the H5 session's to measure.
