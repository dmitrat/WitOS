# P1.8.f: full-runtime worker lifecycle

The guest NativeAOT executable now has a private acceptance helper invoked from ordinary managed Main, while the complete upstream runtime and collector are live. The helper is linked as a separate test object against the same source-built runtime definitions and headers as the PAL; it is not part of the runtime archive or an application SDK. Standard CoreLib remains unchanged.

The driver passes the helper address through one private hexadecimal argv value. Main supplies an UnmanagedCallersOnly allocation callback through an ordinary unmanaged function pointer. Hosted execution without this argument retains the original allocation/GC reference workload; it does not claim guest worker evidence.

## Acceptance workload

Each guest execution creates nine workers: five joinable and four detached. One joinable worker is held alongside the first regular worker so that main, finalizer and both workers fill the four-thread quota. Both joinable and detached additional creation must fail with NO_MEMORY; failed joinable creation must publish no handle. Subsequent workers demonstrate recovery and reuse without increasing the quota.

For each worker the fixture checks:

- Fresh runtime TLS, actual ThreadStore::AttachCurrentThread and exactly one list entry under the real ThreadStore lock.
- Repeated attach retains the same runtime context capability and exactly one list entry.
- Duplicate runtime-exit/platform-cleanup registration returns BUSY and preserves the original callbacks.
- A normal compiler-generated C++ TLS destructor runs before the platform cleanup observer.
- The managed callback allocates a real object and returns through the genuine reverse-P/Invoke transition.
- The worker has a nonempty GC allocation context before entering native thread exit.
- Actual RuntimeThreadShutdown removes the record from ThreadStore, marks it detached and closes its runtime thread capability.
- Real GC FixAllocContext transforms the remaining allocation tail into an object with the collector's free-object method table; the upstream dead-thread accounting delta matches that tail.
- An independent generation-bearing thread reference reports EXITED/42 after the exit syscall. Join consumes its separate join capability; detached workers require no join. Every observer/event handle is closed.

Main then performs GC.Collect, requires GC.CollectionCount(0) to increase and verifies static/local roots, the array sentinels and the object produced by the final worker. Both image bases retain the existing full component teardown checks.

## Shutdown allocation detail

The first exact-size check detected 128 additional allocated bytes between returning from the worker callback and the allocation-context fix during shutdown. Runtime shutdown is allowed to execute managed callbacks. The test therefore checks the actual final tail, within the original allocation context, and the exact accounting delta and free-object header at that final address. It does not assume that the pre-shutdown tail is unchanged.

Pinned FixAllocContext(false) makes a free object; it does not promise to zero alloc_ptr/alloc_limit. No runtime method or collector implementation was replaced to satisfy the test.

## Evidence and limits

The final workload, including the C++ TLS destructor assertion and creation rollback, passed all four RAM/CPU profiles at both image bases: 72 completed worker lifecycles. Release build, hosted probe and all 20 ordinary boot scenarios pass. All four existing native runtime profiles also pass, including their expected contained faults. P1.8.f is complete; the subsequent [runtime rendezvous](P1-Runtime-Rendezvous.md) also closes P1.8.g/h. This document retains the nine-worker checkpoint.

The linker map binds RuntimeThreadShutdown to startup.witos.cpp.obj, DetachCurrentThread to threadstore.witos.cpp.obj and FixAllocContext to the complete gcwks.witos.cpp.obj.
