Actual current/foreign protected-frame walks, GS handler invocation/corruption and malformed-image rejection pass. Full source/archive/guest object identity is recorded in the implementation evidence.

The native scope outlives uses of original saved-register/return-address locations. Foreign calls require a real reference and suspended target; RSP alone is not authority. This is a lifetime contract, not proof of managed root enumeration or a complete GC rendezvous.

## P1.8.e: exception boundary

Remaining minimal symbols are PalInitComAndFlsSlot, PalAttachThread and PalHijack. Completed linking of C-specific code does not imply complete exception semantics. Keep their actual runtime dependencies.

Pinned startup.cpp registers RhpVectoredExceptionHandler after RuntimeInstance::Initialize. The WitOS overlay now checks registration failure and stops initialization; the Windows reference remains unchanged. EHHelpers.cpp's real handler ignores breakpoint/single-step events, consults the actual RuntimeInstance/code manager and ThreadStore, and uses an actual EXCEPTION_RECORD/CONTEXT to translate supported faults. Its continuation can change IP/SP or suspend an attached runtime thread.

Kernel hardware upcalls and validated continuation now execute in the guest; see [P1-Exception-Upcalls](P1-Exception-Upcalls.md). Next implement the real native vectored registry and EXCEPTION_RECORD/CONTEXT conversion, correct search/unwind dispositions, software RaiseException and language-specific scope-table handling. Keep kernel register/frame ownership independent of Windows SDK structures, which belong in the adapter. Preserve the captured fault cause, contained unsupported/nested failures, whole-buffer validation and safe IRET selectors/flags/stack bounds. Do not label a manually invoked GS-cookie consumer as automatic SEH dispatch or managed exceptions.

RaiseException is used both by the Windows hijack fallback and EHHelpers debugger notification; a return-success stub cannot satisfy either contract. Native fail-fast must remain nonreturning and preserve its original failure through diagnostics. __C_specific_handler requires actual scope/filter/finally semantics and payload validation, not merely returning ContinueSearch.

## P1.8.f/g: attachment and rendezvous

PalInitComAndFlsSlot must adapt real initialization/notification ordering. PalAttachThread must connect the actual Thread pointer to checked runtime exit notification. RuntimeThreadShutdown -> ThreadStore::DetachCurrentThread must retain managed exit callback and GC allocation-context cleanup. Native notification probes are not managed attachment or detach.

Pinned PalHijack's fallback has a real target handle and brackets HijackCallback with suspend/resume. It explicitly rejects CONTEXT_SERVICE_ACTIVE or CONTEXT_EXCEPTION_ACTIVE. Existing normal alertable APC delivery does not supply asynchronous GC rendezvous. Integrate scopes with actual Thread/StackFrameIterator and enclosing root/hijack use, preserving preemptive/cooperative transitions and keeping GC cleanup real.

CoffNativeCodeManager copies nonvolatile-context pointers into REGDISPLAY; Thread::HijackReturnAddressWorker uses a returned stack address after the unwind call. A copied stack or a foreign lease released inside one RtlVirtualUnwind call would break that contract. The implemented native scope provides the necessary primitive; full-runtime call-site integration and collector execution remain P1.8.f/g and P3.

Full P1 still requires the actual executable startup thunk and strict complete link (P1.9/P1.10), followed by integration acceptance. None of these prerequisites proves managed startup by itself.
