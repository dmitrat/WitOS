# K8.4c — one component form: flat images and the startup descriptor

Until K8.4c the kernel built a component in two ways:

- **The root task** came from a validated flat image (K4) and started with the startup descriptor of RFC 0011 §7.11
  (`WitRootStartup`).
- **A self-test kernel's mechanism fixtures** were raw code copied to `WIT_USER_CODE` (`wit_user_create`) and started
  with the Windows-form line's `WitUserStartup` (version, size, console handle, image information).

K8.4c removes the second way. The fixtures become flat images, and every component the kernel builds starts with the
startup descriptor. ABI v72.

## Kernel

- **`wit_user_create` is gone**, and with it the code window and the special case of three code pages (K8.3a).
- **`wit_user_create_flat` takes a profile.**
  - *System (the root task).* The system layer's quotas, as before.
  - *Fixture.* The default quotas the fixtures' tests exhaust: 16 handles, 4 events, 4 threads, 128 pages,
    8 reservations, 8 objects and a budget of 10 ticks. Every segment must also lie inside the fixed window of that
    profile (`WIT_USER_LIMIT`), checked before a page is mapped.
- **`WitUserStartup` and `WIT_ABI_STARTUP_SIZE` leave `user_abi.h`**, and `WIT_USER_CODE` leaves `user_layout.h`.
- **`root.h` describes the startup descriptor** of any component the kernel builds.

The kernel now builds components only from flat images. Every other process is the system layer's, made with
`PROCESS_CREATE`.

## Tests and tool

- **A fixture is linked at the image window** (`fixture.ld`): one executable segment that starts with the entry. The
  tool converts it with `FlatImage` and embeds it, as it does the root task. `UserImage` no longer reads ABI constants,
  and `FlatImage` loses its unused PE path.
- **`wit_test_create_fixture`** (`tests/Kernel/user_fixture.c`, self-test layer) creates a fixture:
  - it validates the image with `wit_flat_validate`;
  - it creates the component with the fixture profile;
  - it writes the startup descriptor: version, size, the ABI version and features, the arenas, and the kernel log with
    `WRITE` as the only handle.

  Every kernel test that created a fixture now calls it.
- **The tests' configuration** (`WitUserTestConfig`, `tests/User/protocol.h`) now follows the 128-byte descriptor. A
  fixture finds the log at `Startup.Handles[WIT_ROOT_HANDLE_LOG]`.
- **The entry fixture checks the descriptor**: its version, its size, the ABI version and a single handle.
  `threads2` checks the ABI version in it.
- **Fault tables and tests now name `WIT_USER_IMAGE_BASE`** where they named `WIT_USER_CODE`.
- **The fault containment check** accepts a PC anywhere in the component's fixed window
  (`WIT_USER_BASE`–`WIT_USER_LIMIT`). The NX test faults on the data page, below the image window.
- **The image window shares the code window's page table**, so the self-test accounting is unchanged.

Results:

- `format-check` and the host tests pass.
- `test`: all 27 x64 scenarios pass.
- `test --arch arm64`: all 21 scenarios pass.

## Limits kept explicit

- **The first thread's stack** stays the fixed window `WIT_USER_STACK_BOTTOM`–`WIT_USER_STACK_TOP`. RFC 0011 §7.11
  fixes the descriptor in the argument register, not where the stack lies. The release kernel's root task and the
  fixtures share this boot form.
- **The flat format** is a boot format, for the root task and the fixtures alone. Applications are ELF programs that the
  system layer loads.
