# R7.3 — Slices of the .NET libraries' tests in the guest

R7.3 is the last slice of R7. It runs upstream's library tests in the guest, as upstream's CI runs them: xunit's console
runner through `dotnet`, on the shared framework of R5. Both ISAs pass.

```
System.Collections.Concurrent.Tests  Total: 2460, Errors: 0, Failed: 0, Skipped: 1
System.Runtime.Numerics.Tests        Total: 2627, Errors: 0, Failed: 0, Skipped: 0
[LIBRARY-TESTS] The libraries' tests on x86_64: all 2 projects passed
[LIBRARY-TESTS] The libraries' tests on aarch64: all 2 projects passed
```

That is 5086 tests, with 2 left out with a reason and 1 that xunit skips by its own condition.

## Building and running

- **Build.** `runtime-witos` runs `libs.pretest` for witos, which builds the testhost and the tests' shared
  dependencies. It then builds each project of `build/runtime/library-tests.json` with the tree's SDK as an archived
  test build (`/p:TargetOS=witos /p:ArchiveTests=true`), which bundles xunit's console runner and writes `RunTests.sh`.
  As in R7.2b, the restore takes the tree's identifier graph.
- **Package.** The `runtime-library-tests` scenario lays out the .NET install of R5 and each project's output under
  `/tests/<project>`.
- **Run.** `tests/User/library_tests_runner.c` runs each project in a process of its own, as `RunTests.sh` runs it:
  - the command is `dotnet exec --runtimeconfig <project>.runtimeconfig.json --depsfile <project>.deps.json
    xunit.console.dll <project>.dll`;
  - it leaves out the categories upstream's CI leaves out (`IgnoreForCI`, `OuterLoop`, `failing`), and the excluded
    methods through `-nomethod`;
  - each project runs in its own directory, with `TMPDIR` naming `/dev/shm`, so that .NET's temporary files and the
    results XML have a writable directory (R7.2a);
  - a project passes when the console runner exits with zero.
- **Report.** `runtime-witos` reads each project's xunit summary and its `[FAIL]` lines from the log and writes
  `artifacts/runtime-witos/library-tests-<arch>.json`. A failed test or a missing summary fails the run.

## Found and changed

| Found | Cause | Change |
| --- | --- | --- |
| "Failed to create RW mapping for RX memory", then `OutOfMemoryException` on the smallest allocations. | `System.Linq.Tests` JIT-compiles about 30 MiB of code into 120 shared memory chunks, each shown twice. That filled 976 of a process's 1024 reservations and 957 of the libc's 1024 mappings, while the process owned only 63 MiB. | A system layer process has 4096 reservations (24 bytes each, 96 KiB a space), the libc 4096 mappings, a process 512 live memory objects, and the kernel's object table 1024. |
| The .NET install of R5 failed with "Duplicate package name". | `libs.pretest` copies the runtime and the hosts into the runtime pack's `native` directory, from which the install took every library. | The install takes the libraries' native libraries alone (`libSystem.*.so`) from there. |
| A project that also targets .NET Framework had two run scripts. | `System.Threading.Channels.Tests` builds for `net481` too. | The package takes the .NET target framework's output. |

The runner prints the free memory before each project. It stayed at 393 MiB between projects, so a process's exit
returns everything.

## Left out, with the reason

| Test | Reason |
| --- | --- |
| `ToStringTest.RunRegionSpecificStandardFormatToStringTests` | It formats in the en-US culture. Globalization is invariant, since the system layer has no ICU (RFC 0015 §8). |
| `op_rightshiftTest.LargeNegativeBigIntegerShiftTest` | It builds a `BigInteger` of 2^31 bits twice, 256 MB each, past a process's page quota (256 MiB). |

## Measured once, outside the selection

Two more projects ran once on x64. They stay out of the selection because of the time they take, and because of one
open question.

- **`System.Linq.Tests`.** 52186 tests in 31 minutes of guest time: 52174 passed, 8 skipped, and 4 failed. The four are
  `CultureOrder`, `CultureOrderElementAt`, `CultureOrderBy` and `CultureOrderByElementAt`, which ask for the da-DK
  culture that invariant mode lacks.
- **`System.Threading.Channels.Tests`.** 1594 tests: 1592 passed and 2 skipped (stress mode). One earlier run ended
  with the runtime's "Out of memory." right after the first tests, and the next two runs passed. A thread the thread
  pool fails to create beyond a process's 32 is one candidate cause. It is not shown yet.

## With R7.3, R7 is done

The PAL suite (R7.1), slices of `src/tests` (R7.2) and slices of the libraries' tests (R7.3) pass in QEMU on both ISAs.
`runtime-witos` and CI's `linux-host` job run all of them.
