# P1.4 — affinity and balance

Plan step P1.4 (phase P, `P1.0-SMP-Inventory.md` section 6): the dispatcher honours a thread's affinity, idle
processors take the ready threads they may run, `THREAD_QUERY` reports the processor a thread runs on, and the kernel
boots with four processors on the three ISAs. ABI-1 becomes 1.4. Made on 2026-10-18.

## 1. Affinity (RFC 0005 section 38's allowed set)

- **The mask**: `THREAD_AFFINITY` accepts any mask within the table that holds an online processor
  (`wit_processors_affinity_status`); a zero mask or one beyond the table is `INVALID_ARGUMENT`, one of present but
  offline processors alone `UNSUPPORTED`. A new thread's mask is every processor of the table (`wit_processors_all`),
  as Linux gives a thread every CPU; until P1.4 it was the boot processor's bit, which nothing honoured.
- **The dispatcher**: `pick` skips a ready thread whose mask leaves the processor out and counts it as something an
  idle processor waits for. A running thread whose new mask leaves its processor out is kicked off it with a
  RESCHEDULE (`wit_user_thread_kick`), and the caller that left out its own processor becomes ready at its call's end,
  as a suspended caller does.
- **Balance**: a processor that leaves the kernel, or goes idle itself, kicks one idle processor that a ready thread
  may run on (`kick_idle`, `thread_ready_for`); a pinned thread therefore moves at once rather than at the other
  processor's next tick. Each processor rotates over the components from its own (D5.2's rotation per processor, since
  P1.1 keeps the dispatcher's state per processor).
- **The libc**: `sched_getaffinity` and `sched_setaffinity` are `THREAD_AFFINITY` of the thread a tid names (the
  caller's for 0, `__wit_thread_handle`): the mask of the online processors it holds, the processors beyond them ignored
  and an empty rest `EINVAL`, as Linux answers. CoreCLR's PAL gives each new thread the process's mask, which is every
  processor.

## 2. THREAD_QUERY version 6 (ABI-1 1.4)

`WitUserThreadInfo` appends `Processor`, the processor that runs the thread or ran it last, and `Reserved`: 80 bytes
under version 6. Version 5, 72 bytes without them, is still served, so that programs built against the 1.3 headers keep
working; the call returns the size of the record the caller's version names. The minor version rises with it
(`WIT_ABI_VERSION_MINOR` 4), as RFC 0011 section 10.1 requires of an appended field under a new structure version.

## 3. Four processors

`boot-smp4` boots the self-test kernel with four processors on the three ISAs; the SMP and user suites run with
threads on all of them. On riscv64 it found a limit of the board's device-tree walk: the walk kept four interrupt
controllers, and every hart's own controller comes before the PLIC in the tree, so with four harts the PLIC was not kept,
the PCI interrupt map found no controller, and the virtio block function had no line (the interrupt fixture's check 20).
The table now holds one controller a processor and four more (`CONTROLLER_CAPACITY`).

## 4. The acceptance

- `User.SmpAffinity` (`tests/User/Fixtures/smp.c`, affinity mode): the default mask is every processor; a zero mask and
  one beyond the table are refused; pinned to processor 0, then to processor 1 where one is online, the thread stays
  there across 64 yields as `PROCESSOR_QUERY` reports, and `THREAD_QUERY` version 6 names the same processor; version 5
  is still answered.
- The processor fixture expects every processor as the default mask; `process_init.c` pins its thread to the first
  processor with `sched_setaffinity`, reads that back and sets it free, where two processors run (`process-smp2`).
- `boot-smp4` on the three ISAs.

## 5. What ran

In the Linux host's image, with the final code:

- `test --arch x64`: PASS, all 34 scenarios (`boot-smp4` new): `User.SmpAffinity` on one, two and four processors,
  `process-smp2` with the libc's pinning.
- `test --arch arm64`: PASS, all 28; `test --arch riscv64`: PASS, all 28.
- `release` on the three ISAs: `release-128`, `release-512` and `release-display-256` pass.
- `runtime-terminal --arch x64`: PASS, 20 checks; `runtime-portable-app --arch x64`: PASS, 12 of 12 checks — CoreCLR's
  PAL reads and sets the affinity through the libc at its start.

The first x64 run failed `process`: the libc returned the handle of `WIT_THREAD_SELF` as a `long`, which is negative,
and took it for an error.
