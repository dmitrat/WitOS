# T2.1b — layer 2 on the release kernel

Plan step T2.1b moves the layer-2 scenarios to the release kernel, so that both hosts run them. Until now `libc`,
`libc-test`, `cxx`, `spawn` and `process` booted a self-test kernel. Every self-test kernel embeds the frozen line's
fixtures, which MSVC builds, so a Linux host (T2.1a) could not build them. None of these scenarios needs a self-test:
its subject is the root task and the programs it starts, and the release kernel starts the root task after `Hello` and
panics on a nonzero exit, as the self-test kernel does. They now boot the release kernel on Windows and on Linux alike.

## What changed

**The kernel of a scenario.** `KernelImageBuilder.RELEASE_KERNEL_SCENARIOS` names the scenarios whose kernel is the
release kernel: `release` and the five layer-2 scenarios. Such a kernel has no self-test layer and no `WITOS_SELFTEST`
code, so a scenario builds no fixture and needs no MSVC. Its map is still checked to hold no self-test code. Every
other scenario keeps its self-test kernel.

**The verdict.** The five scenarios are judged by the release suite on both ISAs: in the x64 and ARM64 suites and in
their own commands (`libc`, `libc-test`, `cxx`, `spawn`, `process`, each with `--arch`). The release suite now also
requires a request's `RequiredLines`, the lines each root task prints when its checks passed (`[LIBC] …`,
`[LIBC-TEST] … all`, `[CXX] …`, the spawn scenario's five lines, `/bin/init`'s and the root task's report). It still
requires the release markers in order (the boot contract, the exception tables, kernel paging, the clock,
`Kernel initialized.`, `Hello`, `Boot.RootTask`). It still forbids panics, kernel exceptions, user faults and
self-test markers, which none of the layer-2 programs produces: the faults they cause on purpose are handled in
layer 2.

**CI.** The `linux-host` job runs the five scenarios on the release kernels of both ISAs after the release kernels
themselves. The Windows suites run them as before, now on the release kernel.

## Tests

On Linux (the container): `libc`, `libc-test`, `cxx`, `spawn` and `process` pass on x64 and on ARM64. On Windows, the
x64 suite (26 scenarios), the ARM64 suite (20), both release kernels and the host tests pass.

## Limits kept explicit

- Kernel self-tests still run only in self-test kernels, which need the frozen line's fixtures and so a Windows host,
  until K8 (T2.2).
- The `release` command and the layer-2 commands boot one memory size each; the suites keep theirs.
