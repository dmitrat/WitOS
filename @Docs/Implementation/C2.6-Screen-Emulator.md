# C2.6 — the screen's emulator for full-screen console applications

Plan step C2.6 (phase C, ADR 0027 decision 8): what the display's terminal emulator lacked for a TUI. Since C2.2 the
display service drew `TerminalScreen` white on black and ignored SGR and the private modes, so a full-screen console
application's selection, focus and alternate screen were invisible on the screen, and an Arlecchino application's
startup probe printed its kitty-graphics query as text. ADR 0027 puts this step before the first TUI application
(C4.2). Made on 2026-10-18.

## 1. What the emulator learned

`src/OutWit.OS/Display/TerminalScreen.cs` is shared by the display service, the runner's side of a scripted terminal
(C1.2) and the host's judge of the screen (C2.2), so each of them learned the same:

| What | How |
| --- | --- |
| SGR (C2.6) | each cell keeps a `TerminalStyle`: a foreground and a background among the 16 colours or the defaults, and bold, underline and inverse. 30–37/40–47 and their bright forms 90–97/100–107, 39 and 49, 1/22, 4/24, 7/27, 0 and an empty SGR; 38;5;n and 48;5;n (xterm's 256 colours) and 38;2;r;g;b and 48;2;r;g;b reduced to the nearest of the 16 by `TerminalPalette` (xterm's default palette); colons separate sub-parameters as semicolons do; faint, italic, blink, hidden and crossed out paint as plain text |
| Erase | an erased or scrolled-in cell keeps the current background, as xterm erases |
| Private modes | `?25` the cursor's visibility, `?7` autowrap (off: the last column takes every further character), `?47`, `?1047` and `?1049` the alternate screen (blank on entry; `?1049` saves the cursor and restores it with the main screen) |
| Strings | DCS (`ESC P`), APC (`ESC _`), PM (`ESC ^`) and SOS (`ESC X`) swallowed to ST or BEL, as OSC strings already were |
| Answers | DA1 (`CSI c`, `CSI 0c`) with `CSI ?62;22c`, a VT220 with ANSI colour; the size report (`CSI 18t`) with `CSI 8;rows;columns t`; OSC 10 and 11 queries with the default colours, ended as the query was. DA2, the kitty keyboard query and the pixel sizes (14t, 16t) stay unanswered, as a terminal without them answers, so their askers time out to their defaults |
| Editing | ICH, DCH and ECH (`@`, `P`, `X`), IL and DL (`L`, `M`) |
| Characters | a surrogate pair is one character; an East Asian wide or fullwidth character, or an emoji presented wide, takes two cells (the second marked `WIDE_TAIL`), a character beyond the BMP is shown as U+FFFD; combining marks, zero-width characters and variation selectors take no cell; writing over half of a wide character blanks its other half |
| DEL and C1 | paint nothing |

The renderer (`FrameRenderer`) draws a cell in its colours: the default foreground and background stay the white and
black of C2.2, so a screen without SGR is drawn as before; bold brightens a dark colour, since Spleen has one weight;
inverse trades the colours, and so does the cursor, which is drawn only while it is shown; underline lights the
cell's bottom row; a character the font lacks is a hollow box, since Spleen's default character is a space. A cell is
redrawn when its character, its look or the cursor's presence changed.

The keyboard (`UsKeyboardLayout`) sends xterm's modifier parameter with the cursor, editing and function keys —
`CSI 1;m A`, `CSI 1;m P` for F1–F4, `CSI n;m ~` for the others, `m` being 1 plus 1 for Shift, 2 for Alt and 4 for Ctrl —
so that Shift+F4 or Alt+F7, which an orthodox file manager lives on, reach the application; Alt adds no ESC before
them, while a character keeps Alt's ESC.

## 2. The judge

The judge of the screen is unchanged in kind: the host renders the frame it expects from the mirror's transcript with
the same emulator, renderer and font, and the screendump must equal it pixel for pixel — now in colour. `runtime-display`
also requires that the screen shows colours beside the default white and black: PSReadLine colours the commands the
runner types, and the profile's console mark asks for xterm's 256 colours, so a display that dropped SGR would fail
even where both frames agreed. The emulator's host tests check every sequence of section 1, the renderer's the colours,
attributes, the hidden cursor and the missing glyph, the keyboard's the modified keys.

## 3. What ran

In the Linux host's image, on riscv64, whose runtime tree that image holds whole since V2.4: the services published
again (the display service carries the emulator), then `runtime-display`:

```text
Display on witos-riscv64: PowerShell 7.6.7 ran on the screen through the keyboard, and the display service's screen
(800 by 600, 100 by 37 cells) at its last prompt equals the frame the host rendered from the terminal's transcript
(6010 bytes, 37 lines, 5 colours beside the default white and black).
```

The screendump shows PSReadLine's colours — the commands typed in yellow, the tables' headers in green, the directories
of `/data` on a blue background — and equals the host's frame pixel for pixel. The x64 and ARM64 runs are CI's
`linux-host` legs, which run `runtime-display` with the rest of `runtime-witos`. Host tests: the emulator's 15, the
renderer's and the keyboard's among OutWit.OS's 202, WitOS.Dev's 113; `format`.

## 4. Limits

- Sixteen colours: a 256-colour or 24-bit colour is drawn as the nearest of the palette.
- No scrolling region (DECSTBM, `CSI r`), no insert mode, no tab stops other than every eight columns, no double-width
  lines; applications that draw with absolute moves, as .NET's TUIs do, do not need them.
- One weight and no italic: Spleen 8×16 has one face.
- Wide characters follow a range table of Unicode's East Asian Wide and Fullwidth classes and the wide emoji; an
  application with another table may disagree on a character outside both, as two terminals may.
- Spleen has no CJK or emoji glyphs: such a character is a box in its first cell.
- No mouse: the board has no pointing device.
